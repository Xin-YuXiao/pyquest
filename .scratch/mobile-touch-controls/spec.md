# 移动端触控：虚拟摇杆与触控按钮

Status: needs-triage
Priority: P1
Source: upstream README 路线图「移动端虚拟摇杆」；接手评估补充（源码核实：除对话框与答题选项外，全部操作只认键盘）
Depends on: 无（设置项与 `accessibility` 共用设置存储，见实现决策）

## 问题陈述

学生常在手机、平板上打开课程链接。#12 已把 DOM UI 做成随画布等比缩放的设计坐标系，画面在手机上能正常显示，
但游戏**玩不了**：

- 移动只认方向键 / WASD，挥剑只认 J / 空格，交互（符文石、石碑 / 长老、封印门）只认 E，世界地图只认 Tab，静音只认 M；
- 世界地图只能用 Tab 关闭，没有可点的关闭按钮——触屏上即使能打开也关不掉（除非点地标传送走）；
- 交互提示、标题页操作说明、对话框「继续」提示都写着键帽（`E`、`Tab`），触屏用户看不懂该做什么；
- 横屏时答题面板外层不可滚动（竖屏已可滚动），题面最长的题在矮屏横放手机上可能把「确认 / 领取奖励」挤出可视区（需核实）。

结果：手机用户能看到标题页和第一章野外，但走不动、答不了符文石，学习主线完全中断。

## 解决方案

在触屏设备上叠加一层触控操作层：

- 左下角**虚拟摇杆**负责移动；右下角**攻击键**、**交互键**（按钮上的文字随可交互对象变化：「解读」「对话」「检查」「继续」）；
- HUD 附近两个小按钮：**地图**、**静音**；
- 只在自由探索时显示操作层；答题面板、世界地图、标题页、胜利页打开时自动让位，对话进行时交互键变为「继续」；
- 所有提示文字按当前输入方式显示（键盘显示键帽，触屏显示按钮名）；
- 答题面板在横竖屏都能滚动，触控目标足够大，确认按钮始终可达；
- 桌面端默认不显示操作层，行为与现在完全一致；设置里可以强制显示 / 隐藏。

## 用户故事

1. 作为用手机上课的学生，我想用拇指拖动虚拟摇杆移动勇者，以便在野外和巢穴里自由走动。
2. 作为手机用户，我想要一个随手可按的攻击键，以便击退靠近的小怪。
3. 作为手机用户，我想在靠近符文石时点一下交互键就打开答题面板，以便不依赖键盘完成碎片符文。
4. 作为手机用户，我想让交互键上的文字告诉我「解读 / 对话 / 检查 / 继续」，以便知道点下去会发生什么。
5. 作为手机用户，我想在附近没有可交互对象时看到交互键变暗，以便不会误以为按钮失灵。
6. 作为手机用户，我想一边按住摇杆移动一边点攻击键，以便边走边打（多点触控）。
7. 作为手机用户，我想按住攻击键时按冷却节奏连续挥剑，以便不用狂点屏幕。
8. 作为手机用户，我想点地图按钮打开世界地图、点关闭按钮或空白处关掉它，以便查看进度和快速传送。
9. 作为手机用户，我想点静音按钮开关声音、并看到当前是否静音，以便在教室里不打扰别人。
10. 作为手机用户，我想在对话进行时点交互键或点对话框推进台词，以便读完长老 / 石碑的引导。
11. 作为手机用户，我想在答题面板里直接点选项、点确认，以便和桌面端一样答题。
12. 作为横屏使用矮屏手机的学生，我想让最长的题也能滚动看到确认按钮，以便任何题都能作答。
13. 作为手机用户，我想让摇杆和按钮不会触发页面滚动、双击缩放或文本选中，以便操作时画面不乱跳。
14. 作为竖屏握持手机的学生，我想让操作层放在画布下方的空白区，以便手指不挡住游戏画面。
15. 作为刘海屏 / 手势条手机用户，我想让按钮避开安全区边缘，以便不会误触系统手势。
16. 作为桌面用户，我想完全看不到触控层、键盘操作和现在一模一样，以便已有体验不被打扰。
17. 作为二合一笔记本（触屏 + 键盘）用户，我想两种输入同时可用，以便随手切换。
18. 作为平板用户，我想按钮的物理尺寸足够大（不随画布缩小到难以点中），以便稳定命中。
19. 作为手机用户，我想在标题页看到触屏操作说明而不是键帽说明，以便第一次进游戏就知道怎么玩。
20. 作为手机用户，我想让交互提示条写「点【交互】解读符文石」而不是「按 E」，以便提示与我手上的操作一致。
21. 作为偏好特定方式的用户，我想在设置里把触控层设为「自动 / 总是显示 / 总是隐藏」，以便检测出错时自己纠正。
22. 作为手机用户，我想在切到后台再回来、或旋转屏幕后，摇杆不会卡在按住状态，以便勇者不会自己一直走。
23. 作为手机用户，我想在勇者死亡、场景转场、被传送门切换场景时摇杆自动复位，以便新场景里不会带着旧方向乱跑。
24. 作为维护者，我想让键盘和触屏都汇入同一套「移动意图 + 动作」输入抽象，以便以后加手柄等输入不再改玩家实体。
25. 作为维护者，我想有一条在 CI 里跑的触屏 E2E 主线，以便触控回归能被自动发现。

## 实现决策

- **输入抽象（prefactor）**：玩家实体不再直接读键盘对象，而是每帧读一个「移动意图」；交互、攻击、地图、静音改为场景订阅的「动作」。
  键盘与触控层都只是意图 / 动作的生产者。形状（极简）：
  ```
  MoveIntent = { x: -1 | 0 | 1, y: -1 | 0 | 1 }        // 8 方向数字量
  Action     = 'attack' | 'interact' | 'map' | 'mute'
  ```
  键盘路径改造后行为必须逐帧一致（速度、朝向判定顺序、斜向两轴满速的现有手感都不变——近期提交遵循「玩法冻结」）。
- **摇杆量化为 8 方向**：摇杆偏移超过死区（推荐半径的 25%）后按角度量化到 8 方向，输出与键盘同一种数字量，
  从而与现有手感、E2E 的确定性一致。模拟量（按推力调速）列入待决策。
- **触控层位置**：操作层是 stage 之外、覆盖整个视口的固定层（不放进 #ui-scale），按钮尺寸用 CSS 像素而非设计坐标，
  保证最小触控目标 ≥ 48 CSS px，不随画布缩小；横屏贴视口左右下角，竖屏放在画布下方的留白区；使用 safe-area 内边距。
  层本身 pointer-events 透传，只有摇杆和按钮接收事件；层与按钮设置 `touch-action: none`，不全局禁用页面缩放（无障碍考虑）。
- **事件模型**：Pointer Events（pointerdown / move / up / cancel），按 pointerId 分别跟踪摇杆与各按钮，天然支持多点；
  pointercancel、页面 visibilitychange 为 hidden、orientationchange、场景 shutdown / 玩家死亡 / 转场开始时全部复位为「无意图」。
- **显示策略**：「UI 模式」由既有开关量推导——答题面板 isOpen、世界地图 isOpen、对话 isOpen、标题页 / 胜利页可见。
  自由探索：显示全部；对话：只保留交互键（文案「继续」，触发对话推进）；答题 / 地图 / 标题 / 胜利：隐藏整层。
- **自动检测**：`matchMedia('(pointer: coarse)')` 命中或收到首个 touch 类指针事件即启用；设置项三态「自动 / 总是显示 / 总是隐藏」，
  存入与 `accessibility` 共用的设备级设置存储（不进存档，「新的冒险」不清除）。
- **交互键文案与可用态**：复用现有「交互提示」的判定结果（NPC / 符文石 / 封印门 / 门链接，阈值即 INTERACT_RUNE_RADIUS 等现有常量），
  不另写一套距离判定；无目标时按钮置灰但仍可点（点了无事发生）。
- **提示文案按输入方式切换**：引入一个「操作提示词」映射（交互 → `E` 键帽 / 【交互】按钮名，地图 → `Tab` / 【地图】等），
  交互提示条、对话框「继续」提示、标题页操作说明、世界地图页眉的「Tab 关闭」都从映射取词；最近一次使用的输入方式决定显示哪一套。
- **攻击键**：按住即按现有攻击冷却（340ms）连发，不绕过冷却。
- **世界地图**：新增可点的关闭按钮与点空白处关闭（键盘 Tab 行为不变），这对桌面鼠标用户也是改进。
- **静音**：音效模块补一个读取静音状态的接口，静音按钮显示当前状态；静音是否持久化归 `accessibility` 的设置面板。
- **答题面板触控适配**：答题背景层在横竖屏都可纵向滚动、面板设最大高度；选项与按钮触控目标 ≥ 44 CSS px（按缩放后尺寸核算）；
  打开面板时滚回顶部。数字键 1-4 / Enter 仍保留给键盘。
- **测试接缝**：不新增作弊型接缝；触屏 E2E 走真实指针事件。必要时给 __PYQUEST__ 只读查询补一个「当前移动意图 / UI 模式」快照，便于断言。

## 测试决策

- 好测试只验证外部行为：触摸摇杆后玩家坐标改变、点交互键后答题面板打开、点选项与确认后碎片数增加——不断言内部字段。
- **E2E 声明式 runner** 增加输入方式选项（键盘 / 触屏）：触屏模式下用「点交互键 / 点攻击键」替代按 E / J，答题仍走真实点击；
  移动断言用摇杆拖动后 __PYQUEST__ `state()` / 场景玩家坐标变化。先例：runner 现有 steps（collectShards、sealedGate、bossFight）。
- 触屏上下文用 Playwright 的移动视口 + `hasTouch`（Chromium）；点击用 touchscreen.tap；摇杆拖动需要触摸移动——
  Playwright 1.63 是否提供触摸移动 API **需核实**，否则走 Chromium CDP 的触摸事件派发或页面内派发 pointerType=touch 的 PointerEvent。
- 键盘回归：输入抽象 prefactor 之后全部 11 章 E2E 必须原样通过（这是 prefactor 的验收主体）。
- 选一章（推荐第三章样板章，流程最全）跑完整触屏主线，横屏手机视口；另加一条竖屏手机视口的冒烟（进野外、摇杆移动、打开 / 关闭地图）。
- 先例：设计审计脚本已用 375×667 视口截图（design-audit、shots-b13），可参照其视口设置。

## 待决策

1. **摇杆 8 方向数字量还是模拟量**——推荐 8 方向：与键盘手感和 E2E 确定性一致；模拟量手感更细腻但斜向速度与键盘不同，属玩法改动。
2. **竖屏是否提示「横屏体验更佳」**——推荐只在首次竖屏进入游戏时提示一次，可关闭，不强制旋转。
3. **触感反馈（navigator.vibrate）**——推荐暂不做：iOS Safari 不支持，收益小；如做，只在受击时短振并受设置开关控制。

## 不做的事

- 手柄 / 外接控制器支持（输入抽象为它留了口子，但不在本 effort 实现）。
- 自定义按钮布局、按键重映射。
- 原生 App 封装、PWA 安装体验（离线缓存见 `public-deploy` 的后续讨论）。
- 改动攻击判定、移动速度、交互半径等玩法数值。

## 备注

- 现状核实：对话框已支持点击推进；答题选项本就是按钮可点击；世界地图地标按钮可点击传送，但打开 / 关闭只认 Tab。
- 竖屏下设计画布已向上下扩展铺满视口（--cam-pad），HUD / 提示 / 对话锚定画布边缘——触控层放在下方留白区不会与它们冲突，但要避开对话框（对话框在画布底部上方）。
- 与 `accessibility` 协调：两者共用设备级设置存储与设置面板；触控层按钮需要可读的 aria-label。
