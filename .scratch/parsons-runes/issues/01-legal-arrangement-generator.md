# 01: 合法排列生成器（构建期 python 实跑 + 入库数据 + CI 同步检查）

Status: ready-for-agent
Type: task
Blocked by: None (can start immediately)

## 要做什么

先把「判分数据」这条链路做出来并能独立验证，UI 之后再接。

- 新增一个构建期脚本（与 verify-quiz 同一套 python 探测逻辑：anaconda → python3 → python，UTF-8 输出）：
  读取题库，按 spec「适合做拼图的题」规则自动筛选候选题；对每道候选题在**单个 python 进程内**
  枚举「行顺序 × 按语法规则剪枝的缩进」，compile 通过的候选在受限环境执行（步数上限防死循环），
  stdout 与来源题正确选项一致者记为合法排列。
- 输出两样东西：
  1. 入库的判分数据文件（每道题：参考排列、合法排列集合、行文本，紧凑编码）；
  2. 一份筛选报告（候选数、每题合法排列数、被排除的题与原因：行数超限 / 含随机数 / 输出与正确选项不符 / 编译失败等）。
- 新增 npm 脚本运行生成器；CI 在 `npm test` 里跑「重新生成 → 与入库数据比对，有差异即失败」。
- 本工单不新增任何题目条目、不改答题面板，只产出数据与报告。

## 验收标准

- [ ] 生成器在本机与 CI（Ubuntu + scripts/requirements-verify.txt 环境）下结果一致
- [ ] 报告列出 W1-W3 每道候选题的去留与原因；W2 至少有 5 道题可做拼图（若不足，在 Comments 里贴报告并说明）
- [ ] 人工构造一个「两行可交换」的题目夹具，生成器能找出两个合法排列（证明不只认参考顺序）
- [ ] 人工构造一个「错排会死循环」的夹具，生成器在步数上限内结束且不把死循环排列判为合法
- [ ] 每道入选题：参考排列 ∈ 合法集合；集合非空；生成耗时写进报告（整体 < 2 分钟）
- [ ] CI 新增「判分数据与题库同步」检查，临时改动一道来源题代码时该检查失败（在 Comments 里贴验证记录）
- [ ] `npm run check` 全绿
