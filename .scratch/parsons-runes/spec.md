# 代码拼图符文：把打乱的代码行排回能跑的程序

Status: needs-triage
Priority: P1
Source: 接手评估新增 · 借鉴教学研究（见 .scratch/INSPIRATION.md）——Parsons problems（Ericson 等）
Depends on: pyodide-sandbox（硬依赖其 01 号题型分派扩展点；不依赖 Pyodide 运行时本身）；协同 quiz-bank-lint（可执行题覆盖率回填）、learning-records（作答记录）

## 问题陈述

- 现在每块符文石都是「读代码 → 选输出」。这练的是**读**（预测），从来没让学生**组织**过一段代码：
  先算什么、后算什么、哪一行属于循环体、`return` 该缩进到哪一层。
  W2「函数 / 循环 / 条件」恰恰是缩进和顺序决定一切的章节。
- 从空白编辑器写代码对 W1-W3 的新手门槛太高（还需要浏览器里的 Python 运行时，见 pyodide-sandbox），
  而四选一又太低：认得出不等于写得出。中间缺一档。
- Parsons problems（把一段正确程序的行打乱，让学习者重新排序并给出缩进）正好是这一档：
  研究综述与多校研究显示，它比从零写代码更快完成、学习收益相当、学生觉得更有参与感，
  也能帮助掌握常见代码模式（见备注来源）。
- 题库里现成就有大量适合的载体：W1-W3 有 76 道「无填空、代码里有 print」的候选可执行题，
  其中 W2 有 28 道、21 道带缩进（函数 / 循环 / 条件）；这些题的代码已对齐讲义（ADR-0001），
  正确选项就是程序输出——**不需要编新题**就能做出拼图。

## 解决方案

新增题型「代码拼图」（`kind: 'parsons'`）：

1. 打开拼图符文：题干写「把代码行排好，让程序输出 ⟨原题的正确选项⟩」，下方是打乱顺序、去掉缩进的代码行卡片。
2. 玩家拖动卡片（鼠标 / 触屏）或用键盘（选中一行 → 上下移动 → 左右调缩进）把程序排好，点「确认咒语」提交。
3. 判定：玩家的「行顺序 + 缩进」只要属于**构建期预先算好的合法排列集合**就算对——
   不只认参考顺序，任何能跑出同样输出的等价排列（例如两行互不依赖的赋值交换顺序）都算对。
   运行时只做查表，**不需要浏览器里的 Python**。
4. 答对：与普通符文一样发奖励、显示原题解析。答错：按规则扣心，并高亮「第一处放错的行」作为提示。
5. 先在 W2 做一块样板拼图符文，再铺到 W1 与 W3。

## 用户故事

1. 作为 W2 学生，我想把打乱的函数定义、循环体和 `return` 排回正确位置，以便真正理解缩进决定代码归属。
2. 作为学生，我想拼图的目标输出写在题干里，以便知道「排对」的标准是什么。
3. 作为学生，我想用鼠标拖动代码行改变顺序，以便操作直观。
4. 作为用触屏的学生，我想用手指拖动代码行，以便在平板上也能玩。
5. 作为只用键盘的学生，我想用方向键选中行、上下移动、左右调缩进、Enter 提交，以便不用鼠标也能完成。
6. 作为学生，我想看到每行的缩进层级有清楚的视觉标尺，以便知道自己把这一行放进了哪个代码块。
7. 作为学生，我想我写出的等价顺序（例如先赋值 b 再赋值 a）也被判对，以便不因为「和标准答案不一样」被冤枉扣心。
8. 作为学生，我想排错时看到第一处放错的行被标出来，以便有方向地修改而不是乱试。
9. 作为学生，我想答对后看到原题的解析，以便把拼图和知识点对上。
10. 作为学生，我想关闭面板再打开时我已经排好的部分还在（同一块符文石、答对之前），以便不用从头再排。
11. 作为学生，我想拼图里的代码有和普通题一样的语法高亮，以便读起来不吃力。
12. 作为学生，我想拼图答对和普通符文一样给碎片 / 回心，以便它自然融入章节流程。
13. 作为色弱或开了「减少动态效果」的学生，我想拖动和提示不依赖颜色与动画，以便同样能完成。
14. 作为教师，我想拼图题全部来自已对齐讲义、已被实跑校验的现有题目，以便不引入未经审核的新内容（ADR-0001）。
15. 作为教师，我想在作答记录里看到学生拼图的尝试次数，以便判断谁在缩进 / 控制流上有困难。
16. 作为内容作者，我想只需在题库里标记「这道题可以做成拼图」，构建脚本就自动算出合法排列，以便不手写判分数据。
17. 作为内容作者，我想构建脚本告诉我某道题为什么不适合做拼图（太长、含随机数、排列过多），以便挑题有依据。
18. 作为维护者，我想合法排列在构建期用本机 python 实跑得出、结果文件入库、CI 校验「重新生成无差异」，以便判分数据永远和题目代码同步。
19. 作为维护者，我想可能死循环的排列（例如把 `n -= 1` 移出 while 循环）在生成时被步数上限截断而不是卡住构建，以便生成器稳定。
20. 作为维护者，我想拼图复用 pyodide-sandbox 01 号的题型分派扩展点，以便不改答题面板公共外壳。
21. 作为 E2E 维护者，我想测试接缝能读到「当前拼图的一个合法排列」并用真实拖动 / 键盘完成它，以便 E2E 覆盖真实交互。
22. 作为维护者，我想现有四选一题的行为完全不变，以便新题型零回归风险。

## 实现决策

- **题型**：`kind: 'parsons'`，经 pyodide-sandbox 01 号工单的题型分派注册渲染器；渲染器声明 `keyboardShortcuts: false`
  （1-4 数字键不再选选项，方向键 / Enter 由拼图自己处理）。
- **数据来源（ADR-0001 友好）**：拼图题是现有题目的**派生变体**，不是新题。题库里新增的拼图条目只引用来源题：
  ```
  { kind: 'parsons', from: 'f12', tier, chapter }   // 题干、代码、解析都从来源题取
  ```
  拼图题 id 约定为「来源题 id + p」（如 `f12p`），放进独立题池（如 `w2parsons`），tier 取所在章野外档。
- **适合做拼图的题（构建期自动筛选）**：无填空；正确选项文本 == 程序 stdout（与 quiz-bank-lint 的答案键核对一致）；
  去掉空行与注释后 3-7 行；不含随机数 / 时间 / 外部文件；W3 的 numpy 题需要构建机装 numpy（与 verify-quiz 同一环境）。
- **合法排列生成器（构建期）**：一个脚本调用本机 python，**在单个 python 进程内**对每道题：
  1. 枚举行的排列（行数 ≤ 7 时最多 5040 种）；
  2. 缩进不盲目枚举：首行 0 级，以 `:` 结尾的行下一行必须 +1，其余行只能保持或回退到某个外层——按 Python 语法规则剪枝；
  3. 每个候选先 `compile()`，通过的再在受限环境里执行（行数步数上限防死循环，捕获 stdout）；
  4. stdout 与来源题正确选项一致的候选即为合法排列。
  结果写入一个数据文件（编码为「行顺序 + 缩进」紧凑字符串列表），**入库**；CI 运行生成器并要求结果无差异。
  生成器同时输出筛选报告：可做拼图的题数、每题合法排列数、被排除的原因。
- **运行时判定**：把玩家当前排列编码后查表；不依赖 Pyodide、不依赖网络。
- **交互**：
  - 卡片列表：每行一张卡片，左侧有缩进刻度（0-3 级），当前选中卡片有粗边框（不只靠颜色）。
  - 鼠标 / 触屏：Pointer Events 拖动排序、横向拖动改缩进；拖动时其他卡片让位动画在「减少动态效果」下关闭。
  - 键盘：↑/↓ 移动焦点，Space 拿起 / 放下，拿起状态下 ↑/↓ 移动该行、←/→ 改缩进，Enter 提交。
    方向键是 Phaser 已登记捕获的按键（会在 window 层 preventDefault），但本题型不需要浏览器默认行为、
    监听器仍能收到事件；答题期间场景暂停，角色不会移动（需核实场景暂停时 Phaser 是否仍拦截）。
  - 打乱规则：按「符文槽 id + 题 id」做固定种子打乱，保证同一块符文石重开顺序不变，且打乱结果不能恰好是合法排列。
- **反馈**：答错时找出与玩家排列「最长公共前缀」最长的合法排列，标出第一处不一致的行（行级反馈）；
  不直接显示正确位置。扣心规则待 02 号 grilling（推荐与四选一一致：扣 1 心，最低 1 心）。
- **暂存**：答对前的排列在本次游戏会话内保留（关面板再开仍在）；是否进存档随 learning-records 的 v3 schema 决定。
- **槽位形态**（待 02 号 grilling，推荐）：W1-W3 野外各新增 1 块「拼图符文」，独立槽位、独立题池，
  v1 作为祝福符文形态（答对回心、不产碎片），不改变封印门所需碎片数，避免新题型影响主线节奏。
- **术语**：GLOSSARY 新增「代码拼图（Parsons）」「合法排列」。

## 测试决策

- 好测试只看玩家可见结果：能否拖 / 键盘排好、等价顺序是否判对、错排是否被标出、奖励是否到账。
- **E2E（首选）**：声明式 runner 新增步骤 `parsonsRune`：打开拼图符文 → 通过接缝只读查询拿到「一个合法排列」→
  用**真实键盘**（Space/方向键）把卡片排成该排列 → 提交 → 断言奖励到账；另一条路径故意排错一次 → 断言扣心 + 出现错位标记。
  先例：runner 的 `healRunes` / `bossRune` 与 `answerCorrect`（读接缝拿答案再点真实 DOM）。
- **接缝**：`__PYQUEST__` 新增只读查询 `parsons()`（当前卡片顺序 / 缩进 / 一个合法排列），不提供「直接判对」的作弊动作。
- **生成器自检（CI）**：每道拼图题的参考排列必须在合法集合里；打乱后的初始排列必须不在合法集合里；
  合法集合非空；重新生成与入库数据一致。
- **smoke**：拼图条目的 `from` 指向存在的题、来源题满足筛选条件、所属题池 tier 一致、kind 已注册。
- **单元测试**（若 core-unit-tests 已落地）：排列编码 / 解码、最长公共前缀反馈这类纯函数。

## 待决策

1. **槽位形态**：独立「拼图符文」（推荐，v1 祝福符文形态、不影响碎片数）vs 让现有符文石随机以拼图形式呈现同一道题
   （不加槽位，但难度会在同池内漂移，违背「池内同难度」）。
2. **扣心**：推荐与四选一一致（错一次扣 1 心、最低 1 心）；备选：前两次错不扣心（拼图试错成本高于选择题）。
3. **反馈粒度**：推荐行级反馈（标第一处错行）；备选：执行反馈（显示错排程序的输出）——需要浏览器 Python，v1 不做。
4. **干扰行**（paired distractors，例如 `return x` 与 `print(x)` 二选一）：会显著提高区分度，但干扰行是新内容，
   推荐 v1 不做，v2 走「提纲 → grilling」。
5. **首批范围**：推荐 W2 先行（缩进最有价值），W1 次之，W3（numpy）最后。

## 不做的事

- 不做自由写代码（那是 pyodide-sandbox 的代码符文）。
- v1 不做干扰行、不做执行型反馈、不做计时。
- 不改任何现有题目的题面、选项与答案。
- 不在浏览器里运行 Python。
