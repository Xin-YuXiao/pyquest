# 学习报告（学生自查 / 交给老师）

Status: needs-triage
Priority: P1
Source: 接手评估新增——游戏对齐一门 64 学时课程，但学生和老师都无法从游戏里看到学习情况；
胜利画面只有「用时 / 解开谜题数 / 章节进度」三个数字
Depends on: learning-records

## 问题陈述

- 学生通关一章后，只知道「过了」，不知道自己哪些知识点是蒙对的、哪些反复出错。
- 老师想把游戏当作课后练习，却拿不到任何结果：没有成绩、没有薄弱点统计，
  只能让学生截图胜利画面，而胜利画面的用时还会把关掉游戏的时间算进去。
- 课程没有后端服务器，也不打算为一个配套游戏搭账号体系；任何方案都必须纯前端、离线可用。

## 解决方案

- **学习报告页**：在胜利画面和世界地图里都有「学习报告」按钮，打开一个独立的报告页面（新标签页），
  读取本机存档实时生成：
  - 总览：有效游玩时长、通关章数、作答次数、首答正确率、总正确率、复习次数；
  - 分章表格：每章的作答题数、首答正确率、总正确率、平均用时、进入/通关日期；
  - 薄弱点：错误率最高的知识点与题池（作答次数太少的不参与排名），附「去错题本复习」提示；
  - 通关时间线：各章进入与通关的日期。
- **可打印**：报告页有打印样式，浏览器「打印 → 存为 PDF」即可得到一页整洁的报告。
  学生可在报告顶部填写姓名/学号（只写进导出文件，不存进游戏存档）。
- **导出**：一键下载 JSON（完整数据，供老师汇总）和 CSV（Excel 能直接打开的分章汇总与作答明细）。
- **班级汇总**（老师用）：报告页提供「汇总」视图，老师把收上来的多个 JSON 拖进去，
  得到一张全班分章正确率表和全班最常错的知识点，并可下载汇总 CSV。全程在老师自己的浏览器里完成，不上传。

## 用户故事

1. 作为学生，我想要通关后一键打开学习报告，以便知道自己这一章学得怎么样。
2. 作为学生，我想要看到首答正确率而不只是最终正确率，以便区分「真会」和「试出来的」。
3. 作为学生，我想要看到我最常错的知识点，以便知道该复习什么。
4. 作为学生，我想要薄弱点旁边有去错题本的提示，以便看完报告马上开始复习。
5. 作为学生，我想要报告里的用时只算我真正在玩的时间，以便如实反映投入。
6. 作为学生，我想要看到每章的进入与通关日期，以便回顾自己的学习节奏。
7. 作为学生，我想要把报告打印或存成 PDF，以便作为作业提交。
8. 作为学生，我想要在报告上填写姓名和学号，以便老师知道是谁的报告。
9. 作为学生，我想要姓名学号不被存进游戏存档，以便共用电脑时不泄露个人信息。
10. 作为学生，我想要报告页明确告诉我「数据只来自本机，没有上传」，以便放心使用。
11. 作为学生，我想要还没作答任何题时报告也能打开并给出提示，以便不会看到一堆 0 和报错。
12. 作为学生，我想要从老存档升级来的进度在报告中如实标为「升级前的记录不可用」，以便理解为什么某些章没有数据。
13. 作为学生，我想要报告区分主线作答与复习作答，以便看到复习的效果。
14. 作为学生，我想要下载 CSV 后用 Excel 打开中文不乱码，以便自己再做分析。
15. 作为老师，我想要收到一个结构固定、带版本号的 JSON 文件，以便批量处理。
16. 作为老师，我想要把全班的 JSON 拖进汇总页就得到班级表格，以便不用写任何代码。
17. 作为老师，我想要汇总页指出哪些文件无法读取或版本不符，以便追问对应学生。
18. 作为老师，我想要同一学生交了两份报告时被提示重复，以便不重复计数。
19. 作为老师，我想要看到全班最常错的知识点，以便下次课针对性讲解。
20. 作为老师，我想要导出班级汇总 CSV，以便放进成绩表。
21. 作为老师，我想要文件被手动改过或损坏时能看到「完整性校验未通过」提示，以便判断是否需要核实。
22. 作为课程负责人，我想要报告里的指标口径（首答正确率等）有书面定义，以便与课堂测验对比。
23. 作为维护者，我想要统计口径是一组不依赖页面的纯函数，以便用单元测试锁定每个数字的算法。
24. 作为维护者，我想要报告页不加载游戏引擎，以便打开快、打印干净。
25. 作为维护者，我想要题库重组后旧记录的统计仍按作答当时的题池/章归类，以便报告不随题库变更而漂移。

## 实现决策

- **统计口径模块（纯函数）**：输入 v3 存档对象 + 当前题库（只用于取题面摘要与知识点标签），输出报告数据对象。
  口径定义（写进报告页底部「指标说明」）：
  - 作答题数：至少提交过一次作答的不同题目数（放弃不算）；
  - 首答正确率：作答题数中，第一次提交即答对的比例；
  - 总正确率：所有提交中答对的比例；
  - 平均用时：所有提交用时的中位数（中位数比均值更不受「挂机」影响）；
  - 薄弱点：按知识点（题目章节标签）与题池分别统计错误率，作答次数 < 3 的不参与排名，取前 5；
  - 主线/复习分开统计：复习作答（符文类型 review）不计入首答正确率，单列「复习次数 / 复习正确率」；
  - 章归属用记录里的章快照，而不是当前题库反查。
- **报告页形态**：独立的页面入口（多页面构建的第二个入口），不加载游戏引擎，只读取本机存档。
  从游戏内打开时在新标签页打开。存档不存在或为空时显示引导文案。
- **升级前记录**：章节时间点为 null、且该章无作答记录但已通关的，标「升级前的记录不可用」。
- **姓名/学号**：报告页顶部两个输入框，只用于渲染与写入导出文件，不写入游戏存档；
  可记在报告页自己的本地存储里方便下次自动填充（与游戏存档分开的键）。
- **导出 JSON 契约**（版本化）：

  ```
  format: 'pyquest-report', reportVersion: 1, gameVersion, generatedAt,
  student: { name, id },            // 可为空
  summary: { … 总览指标 … },
  chapters: [ { id, title, answered, firstTryRate, overallRate, medianMs, enteredAt, doneAt } ],
  weakSpots: [ { label, kind: 'topic'|'pool', attempts, errorRate } ],
  attempts: [ …原始作答记录… ],
  integrity: '<payload 的摘要>'
  ```
- **防篡改的边界**：`integrity` 是对内容的摘要（浏览器内置摘要算法），只用于发现意外损坏与随手修改；
  任何纯前端方案都无法阻止有意伪造（算法与代码都在学生手里）。报告页和汇总页会把这一点写明：
  报告是「学习自查记录」，若用于评分，应配合课堂内验证。不做签名、不做混淆。
- **CSV**：两份——分章汇总、作答明细；UTF-8 带 BOM（否则 Excel 打开中文乱码），首行为中文表头。
- **班级汇总视图**：同一报告页的另一视图；拖入/选择多个 JSON → 逐个校验 format 与 reportVersion
  → 按「学号（无则姓名，再无则文件名）」去重并提示 → 输出全班分章表与全班薄弱点，并可下载汇总 CSV。
  完全在本地浏览器计算。
- **入口**：胜利画面按钮区新增「学习报告」；世界地图头部新增「学习报告」。

## 测试决策

- 好测试：给定一份存档，报告页上显示的数字是什么；给定若干 JSON，汇总表是什么。不测渲染细节。
- **单元测试**（主力）：统计口径模块——用构造的 v3 存档覆盖首答/总正确率、中位数、薄弱点阈值、
  主线/复习分离、升级前记录、空存档；JSON 契约与 integrity 校验；CSV 生成（含 BOM、逗号/引号转义）；
  汇总去重规则。
- **E2E**（声明式 runner + `__PYQUEST__`）：第一章通关（其中一题先答错）后点「学习报告」→
  新页面显示第一章行、首答正确率 < 100%、薄弱点出现该题知识点；下载 JSON/CSV（Playwright 下载事件）并校验内容；
  汇总页上传两份 JSON（一份重复）得到正确行数与重复提示。
- 先例：E2E runner 的 `victory` 步骤（胜利画面断言）；smoke 的数据层断言风格。

## 待决策

1. **报告做成独立页面还是游戏内覆盖层**——推荐独立页面：打印干净、不加载游戏引擎、老师汇总视图天然有处可放；
   代价是多一个构建入口。
2. **是否做班级汇总视图**——推荐做（本地拖拽，零部署）：老师不是开发者，「运行一个 Node 脚本」门槛太高；
   若课程方明确不需要，可整张工单 wontfix。
3. **姓名/学号是否必填**——推荐选填：自查场景不需要；交作业时由老师在布置时要求。
4. **指标口径**——推荐按「实现决策」的定义；课程方若有既定口径（如以最终正确率计分），以课程方为准。

## 不做的事

- 不做服务器、账号、自动提交、排行榜。
- 不做强防篡改或反作弊。
- 不做跨学期的长期趋势分析。
- 不在报告中展示题目答案（避免报告被当作答案册流传；薄弱点只给知识点与题面摘要）。
