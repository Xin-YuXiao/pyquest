# 03: 存档读写、迁移与容错的单元测试，以及共享存档夹具

Status: ready-for-agent
Type: task
Blocked by: 01

## 要做什么

存档模块的全部对外契约都有单元测试。同时提供可复用的存档测试夹具，用来构造 v1、v2 原始存档，供 `learning-records` 的 v2→v3 迁移测试直接使用。

覆盖的契约：

- **往返**：设置一组典型进度（多章碎片、封印门状态、BOSS 状态、已答符文、已答题目、抽题记录、心数、当前章），保存后重置状态再读取，全部字段还原
- **v1→v2 迁移**：旧版两章字段正确映射到第一、二章进度；当前章按旧档的通关情况推断；已答集合、抽题记录、心数和开始时间保留；旧键被删除，新档写入后可再读
- **容错**：无档返回 false；损坏的 JSON 返回 false 且不抛异常；版本号未知返回 false；localStorage 读写抛异常时保存静默失败、读取返回 false、游戏状态不受影响
- **补齐与夹紧**：存档缺少某章进度或某些字段时按初始值补齐；存档中的当前章超出章节总数时夹到合法范围；章节的碎片需求量以章节注册表为准，而不是存档里的旧值
- **清除与探测**：清除后探测「有无存档」为 false；「继续冒险」落点探测对 v1 存档与 v2 存档都给出正确章号

## 验收标准

- [ ] 上述五组契约各有用例，全部通过
- [ ] 存档夹具可单独导入，带文档注释说明用法；`learning-records/issues/01` 的描述中引用它（在该工单 Comments 留言告知即可）
- [ ] 人为让迁移漏掉一个字段（如第二章封印门状态），至少一个用例失败（验证后撤回，记在 Comments）
- [ ] 测试运行在 happy-dom 环境，不依赖真实浏览器
- [ ] 不修改存档模块的生产代码
- [ ] npm run check 全绿
