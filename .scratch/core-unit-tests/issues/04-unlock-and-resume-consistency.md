# 04: 解锁条件解析与「继续冒险」落点一致性测试

Status: ready-for-agent
Type: task
Blocked by: 03

## 要做什么

传送门、封印门的解锁条件解析和「继续冒险」的落点规则都有单元测试。另加一个性质测试，保证落点的两份实现永远一致：一份读原始存档（决定标题按钮显示「继续冒险 · 第 N 章」），一份读内存状态（决定实际落到哪一章）。

覆盖：

- 解锁条件：缺省（无条件）为真；对象形式 { 章, 标志 } 读取对应章进度的标志（如 done、gateOpen）；函数形式以全局状态为参数求值；引用尚未初始化的章节进度时按初始值处理
- 落点：第一章未通关时落在 1；第一章通关后落在「最后一个已通关章 + 1」；全部通关时以章节总数为上限；跳着通关（例如只通关第 1、3 章）时按现有规则计算，并把结果作为当前行为固定下来
- 一致性：随机生成至少 200 组各章完成状态，写档后分别用两份实现计算落点，结果必须相同

## 验收标准

- [ ] 解锁条件四种情况各有用例
- [ ] 落点规则的四种情况各有用例；其中跳着通关的期望值附注释，说明这是在固定当前行为
- [ ] 一致性性质测试使用固定随机种子，失败时打印出导致不一致的那组状态
- [ ] 人为让其中一份实现漏掉「以章节总数为上限」，一致性测试失败（验证后撤回，记在 Comments）
- [ ] npm run check 全绿
