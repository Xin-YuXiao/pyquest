## 问题陈述

- 打通全部 11 章后，游戏只剩「返回村庄 · 自由探索」，没有任何新目标；HUD 显示「全部通关！自由探索吧」后就结束了。
- 课程的落脚点是八个 Project（双爱因斯坦环模拟、透镜建模、cutout 测参、NFW 晕密度重建、形态分类、椭率测量、光谱分类、自选题），
  但游戏里它们只在第十一章的四选一题里被**概念性地**提到：学生知道「拟合类流程是建模 → 拟合 → 参数 → 不确定度」，
  却没在游戏里完整走过一个具体 Project 的链条。
- **命名冲突**：路线图写的是「毕业试炼」隐藏关卡，但第二部已经上线了「第十一章 · 毕业试炼」（野外「毕业试炼场」、BOSS「三途守门人」），
  再叫同名会让玩家和维护者都混淆。
- 维护者视角（已核实的结构约束）：章节注册表的长度被到处当作「总章数」使用——胜利页统计「N / 11」、世界地图标题与节点数
  （E2E 断言地图节点数等于章节数）、HUD 的「全部通关」判断、标题页「继续冒险」落点、符文槽位映射、场景批量注册与测试接缝的场景列表。
  隐藏关卡如果直接塞进章节注册表，会同时改变所有这些数字。

## 解决方案

1. 全部 11 章通关后，诺瓦村庄长老身边出现一道新的传送门「Project 秘境」（名称待拍板），长老台词提示它的存在。
2. 每个 Project 是一片独立的小地图，里面按顺序排着 6 块「课题符文」，对应标准链：选题 → 文献 → 数据 → 分析 → 验证 → 报告。
   第 N 块在第 N-1 块解开之前是封印状态（靠近会提示「先完成：<上一步>」），玩家必须按科研顺序推进。
3. 每一步的题目都扎根于该 Project 的真实素材（Project notebook 的目标、数据、代码与结论），
   以现有四选一为主；代码符文、对话符文上线后可用于「分析」「验证」两步。
4. 走完「报告」一步 = 该 Project 完成：弹出「课题封印页」（复用胜利页样式），获得该 Project 的课题徽章，传送回村庄。
5. 先做一个样板：Project-4「重建暗物质晕密度轮廓」（emcee NFW 拟合，与第八章直接相关），流程跑通后再按批次补齐其余 Project。

## 用户故事

12. 作为学生，我想在某个地方（标题页或世界地图标题）看到自己已完成几个 Project，以便追踪收集进度。
13. 作为学生，我想 Project-4 的步骤和第八章（NFW、emcee、密度 / 质量双轨拟合）呼应，以便把主线学的东西串起来用一遍。
14. 作为学生，我想将来在「分析」步骤里真的写代码（代码符文），以便秘境不只是选择题。
15. 作为学生，我想刷新页面后秘境进度仍在，以便不会丢失完成记录。
16. 作为学生，我想「新的冒险」清档时秘境进度一起清空，以便重新开始的语义一致。

19. 作为维护者，我想秘境用独立的注册表，不改变章节总数，以便胜利页、世界地图、HUD、E2E 里所有「11」都保持正确。
20. 作为维护者，我想秘境进度尽量从已有的存档数据推导，以便不必为它升级存档格式。
21. 作为维护者，我想按顺序解锁的「课题符文」是一个通用的道具能力（链 id + 步号），以便将来别的玩法也能复用。

## 实现决策

- **改名（待 01 号 grilling 确认）**：推荐对玩家统一叫「Project 秘境」（或「课题秘境」），effort slug 保持 graduation-trials 以便追溯路线图出处；
  GLOSSARY 新增「秘境」「课题符文」「课题链」「课题徽章」。
- **独立的秘境注册表**：与章节注册表平行，每个 Project 一条记录（id、标题、地图主题、6 个步骤的名称与槽位、完成文案）；
  场景注册与测试接缝的场景列表同时纳入秘境场景；**章节注册表与 `CHAPTERS.length` 不变**。
- **解锁条件**：全部章节通关（与 HUD「全部通关」同一判断）。入口为诺瓦村庄长老附近的一道传送门，未解锁时不显示；
  长老的跨章问候（第一章已有基于第十一章通关的台词分支）补一句秘境提示。
- **课题符文（按序解锁）**：符文道具新增可选字段「所属链 id + 步号」；交互时若上一步的槽位未破解，则不开题、浮字提示「先完成：<上一步名称>」，
  已解开的符文照旧置灰。奖励：答对回 1 心（不产碎片，秘境没有封印门）；答错扣 1 心（沿用「最多扣到 1」）。
- **进度推导（推荐，无需改存档格式）**：每个课题步骤有固定槽位 id，答对后槽位进入「已破解槽位」集合——它本来就随存档持久化；
  因此「第 N 步已完成」= 该步槽位已破解，「Project 完成」= 6 个槽位全部已破解，徽章数量也由此推导。
  清档时随已破解槽位一起清空，语义自然一致。若 learning-records 的 v3 存档先落地，不受影响。
- **题池**：每个步骤一个小题池（v1 每池 1-2 题，答错保持同一题的规则不变）；tier 从 35 起顺延（主线最高 34），每个 Project 一个 tier 或每步一个 tier 待 01 号决定。
  槽位映射的生成循环需要同时遍历秘境注册表（现在只遍历章节注册表）。
- **地图**：复用通用野外生成器（主题驱动），地图更小、无封印门、无巢穴、6 块课题符文沿一条小径排布；不放史莱姆或只放少量（待决策）。
- **完成页**：复用胜利页（章节封印页）样式与组件，统计印改为「课题步骤 6 / 6」「已完成课题 K / 8」；按钮「返回村庄」。
- **世界地图**：v1 不加节点（E2E 断言节点数 = 章节数，地图美术是固定的 11 个地标）；只在地图标题行追加「课题徽章 K / 8」（已核实：E2E 对地图标题用子串包含断言，追加文字不破坏现有用例）。
- **样板 Project-4 的六步（草案，待素材核对）**：选题（为什么要从模拟 halo 重建密度轮廓）→ 文献（NFW 轮廓的出处与形式）→ 数据（模拟粒子 → 球壳分箱）
  → 分析（emcee 拟合 ρ₀、Rₛ）→ 验证（密度拟合与质量拟合双轨对照）→ 报告（参数 + 不确定度 + 结论措辞）。
  与第十一章 boss（pj18 双轨设计）、第八章（dm 系列）不重复考同一角度。

## 测试决策

- 好测试的标准：只验证玩家可见结果——未通关看不到入口、通关后能进入、符文必须按序解开、完成后出现课题封印页与徽章、刷新后进度保留。
- **E2E（首选接缝）**：
  - 测试接缝新增语义动作 `completeAllChapters()`（把 11 章全部标记为通关并破解全部章节符文槽，复用跳章动作的逻辑）；
    只读查询 `trials()` 返回每个 Project 的已完成步数。
  - runner 新增步骤：`completeAll`、`enterTrial`、`trialChain`（按顺序答六块课题符文，并断言越级交互时被拒绝）、`trialVictory`、`resume`（刷新后进度保留）。
  - 新增一份秘境 E2E 脚本，E2E 总入口除了按章节编号，还要包含秘境脚本。
  先例：现有章节脚本的声明式 labels + steps、第十一章脚本的「全部通关 → 返回村庄」。
- **smoke（数据层）**：秘境注册表完整（每个 Project 6 个步骤、槽位 id 唯一且不与章节槽位冲突、每个槽位都映射到存在的题池、tier 从 35 起且不与主线重叠）；
  秘境地图构建成功（尺寸、越界、6 块课题符文都在可达位置）；章节总数仍为 11。
- **verify-quiz**：秘境题中标注「可执行」的题进校验表（Project notebook 里的确定输出）。

## 待决策

1. **名称**：推荐「Project 秘境」；备选「课题秘境」「毕业秘境」。不推荐沿用「毕业试炼」（与第十一章重名）。
2. **入口形态**：推荐 v1 只做 Project-4 时由村庄传送门直达；做到第 2 个 Project 时再加「秘境大厅」场景（8 个入口）。
3. **进度存储**：推荐从已破解槽位推导（不改存档格式）；备选在 v3 存档里加独立字段（若将来需要记录「完成时间」等额外信息）。
4. **tier 规划**：推荐每个 Project 一个 tier（35-42），步骤之间不分难度——课题链的挑战来自顺序与综合，而不是逐步加难。
5. **秘境里要不要小怪？** 推荐少量（1-2 只）保留动作手感，但远离课题符文，答题时不被打扰。
6. **Project-8（自选题）怎么做？** 推荐不做成固定答案的课题链，而是一条「如何把自己的研究问题落成 Project」的引导链（选题可检验性、数据可得性、方法匹配），放到最后一批。
