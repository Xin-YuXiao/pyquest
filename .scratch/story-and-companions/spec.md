# 主线剧情与随行伙伴：让十一章连成一段旅程

Status: needs-triage
Priority: P3
Source: 接手评估新增。现在每章只有引导石碑/长老按章内阶段播放的说明性台词与胜利结算文案，没有贯穿全程的故事与人物；第一部终章到第二部的转折只有一句「传说，深空之后还有『第二部』的大陆」。答错时只有冷冰冰的「生命 -1」与章节提示语，缺少情绪上的陪伴。
Depends on: learning-records（「已看过的过场」与伙伴开关按存档 v3 扩展约定持久化）；与 accessibility（伙伴开关/文字速度放进设置面板、过场可读屏）、observatory-minigames（伙伴可兼任观测站向导）、mistake-review（鼓励台词可引导去错题本）协调

## 问题陈述

- **玩家**：十一章之间没有因果，像在刷一份很长的练习册；第八章打完「NFW 幻龙」后突然进入「统计圣所」，不知道为什么要继续走。
- **学生**：连续答错时只看到「咒语失败了…… 生命 -1」，挫败感没有出口；遇到新知识点时没有任何铺垫。
- **教师**：第二部（统计 / vibe coding / project）和第一部（Python 工具）的学习目标不同——从「学会用工具」到「学会做判断」——游戏里没有把这个转变讲出来。
- **维护者**：已有的胜利文案用词其实暗含一条线索：第一部是「击败 / 封印 / 制服 / 消散」，第二部是「说服 / 看穿 / 通过」。但没有地方把这条线索串起来。

## 解决方案

### 一条轻量主线（每章不超过 3 句新增过场，可跳过、只播一次）

- **序章**：诺瓦村庄的魔法靠「Python 咒语」驱动（沿用长老现有设定）。一场「混沌」把古老的《星图》——记载全部咒语的学程——打碎成符文，散落在十一片土地上；各地的守护者被混沌侵蚀，成了把守符文的 BOSS。长老把勇者和一架会说话的小望远镜送上旅程。
- **第一部（第一至八章）·「学会用工具」**：每收复一片土地，《星图》就亮起一块；BOSS 被击败后从混沌中醒来（胜利文案已有「封印 / 制服 / 臣服 / 消散」）。第八章深空晕环里，星图拼完了第一部分——但小望远镜在暗物质晕的边缘看到了**星图背面**：还有三片从未被标注的大陆。
- **转折（第八章通关后）**：长老解释，第一部的守护者考的是「会不会用咒语」，星图背面的守护者考的是「能不能判断咒语对不对」——统计（证据够不够）、灵思（AI 说的能不能信）、试炼（独立完成一项研究）。
- **第二部（第九至十一章）·「学会做判断」**：守护者不再被混沌侵蚀，而是主动出题的考官（胜利文案已有「说服 / 看穿 / 通过」）。
- **终章尾声（第十一章通关后）**：《星图》完整；三途守门人把「试炼印记」交还给勇者；回到诺瓦村庄，长老把自己的法杖交给勇者——你成为下一位引路人。之后自由探索（沿用现有「返回村庄 · 自由探索」）。

### 随行伙伴：小望远镜「斯塔」（暂定）

- 一架会说话的小望远镜，以小像素精灵跟在勇者身边；说话时屏幕角落弹出带头像的**气泡**（不暂停游戏、自动消失）。
- **只鼓励，不剧透**：答错后给情绪上的陪伴和方法上的提醒（「再读一遍代码？」「石碑上也许有线索」），从不暗示选项。
- **触发时机**（每类都有冷却与次数上限）：同一块符文连续答错第 2 次后（答题面板关闭时）；本章第一次接近某类符文（碎片 / 祝福 / BOSS）时的一句知识点引子；第一次进入巢穴；集齐碎片可以开门时；爱心剩 1 颗时；在野外 60 秒没有任何进展时提示当前目标。
- 可在设置里关闭伙伴或调低频率。

## 实现决策

- **剧情数据表**：新增数据模块集中存放全部过场与伙伴台词，按 id 组织：`prologue`、`arrive:<章>`、`interlude:part2`、`epilogue`；伙伴台词按触发类别分组（`wrongAgain`、`poolIntro:<题池>`、`firstLair`、`gateReady`、`lowHp`、`idle`），每类一个候选数组，按轮换取用。文本中的数字与名字用与现有 `npcLines` 相同的函数式写法注入（例如本章 `shardLabel`）。
- **过场系统**：过场 = 一组台词 + 可选的镜头平移/淡入淡出，复用对话框模块渲染（打字机效果、【E】键帽标记），新增「跳过」按钮与 Esc 跳过；播放期间场景暂停（与对话框一致）。触发点：新游戏开场（序章）、首次以任意方式进入某章野外（到达过场）、第八章胜利结算后进入第九章前（转折）、第十一章胜利结算后（尾声）。
- **持久化**：新增存档字段 `story: { seen: string[], companion: 'on' | 'encourage-only' | 'off' }`，按存档 v3 扩展约定加入（依赖 learning-records 的 v3 schema 工单）；清档时清空；伙伴开关在 accessibility 的设置面板中暴露（面板未落地前，标题页提供一个临时开关）。
- **伙伴**：程序化像素精灵（小望远镜，与现有程序化贴图同风格：平涂 + 深紫描边），跟随勇者并带轻微漂浮；说话时在 HUD 角落弹出带头像的气泡（DOM，`aria-live="polite"`），默认停留 4 秒。
- **伙伴调度器**：订阅已有事件（HUD 更新事件、答题面板的答错回调、场景切换、交互提示变化）判断触发；每类触发有冷却（缺省 20 秒）与每章次数上限；答题面板或对话框打开时排队不播；只保留最新一条，过期丢弃。
- **答错鼓励**的判定：同一符文槽在本次打开答题面板期间第 2 次答错后，于面板关闭时触发；不读取题目内容，因此不可能剧透。
- **测试接缝**：新增语义动作 `markStorySeen('all' | id[])` 与只读 `storyInfo()`（已看过的过场、伙伴开关、最近一条气泡文本）。E2E 运行器的 `newGame` 步骤缺省调用 `markStorySeen('all')`，保证现有 11 章 E2E 不受影响。

## 测试决策

- **好测试的标准**：断言玩家可观察结果——过场是否出现、是否能跳过、读档后是否重播、气泡文本是否出现/消失；不断言调度器内部状态。
- **E2E（首选）**：新增独立脚本或步骤 `story`：新游戏 → 断言序章对话框出现 → 点击跳过 → 断言进入第一章且 `storyInfo().seen` 含 `prologue` → 刷新读档 → 断言序章不重播。伙伴：在第一章故意对同一符文连续答错两次 → 关闭面板 → 断言气泡出现且文本属于 `wrongAgain` 候选集；关闭伙伴后重复操作断言无气泡。先例：runner 的 newGame / resume 步骤与答题助手。
- **smoke**：剧情数据表完整性——每章都有 `arrive:<章>`；每个题池都有 `poolIntro`；每条台词长度不超过对话框单行上限（与现有台词同一约束）；全程总句数不超过预算。
- **回归**：现有 11 章 E2E 在 `newGame` 缺省跳过剧情后全部通过；`npm run check` 全绿。
