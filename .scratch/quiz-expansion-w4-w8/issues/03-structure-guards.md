# 03: 结构准备：按章题量下限、题面长度护栏、可执行题覆盖率报告

Status: ready-for-agent
Type: task
Blocked by: None (can start immediately)

## 要做什么

在加题之前先把护栏装好，让每一批扩充都被 CI 自动把关：

- **按章题量下限**：smoke 现有的全局下限（shard ≥ 10 / lair ≥ 7 / boss ≥ 3）改为一张按章配置的目标表，默认值等于现状；
  之后每批扩充只需要改表里对应章节。
- **老题保护**：smoke 校验 W4-W8 现有题目 id 全部仍在（防误删 / 误改 id，老存档的抽题记录依赖它们）。
- **题面长度护栏**：测出现有题库中最高的一题（已知 sp15 的答题面板连反馈高约 805px，E2E 视口 900 就是为它调的），
  据此定出代码行数、题干与解析字数的上限并写进数据层检查；现有题全部满足，超限的新题在 CI 中失败。
  若 quiz-bank-lint 已落地，规则放进它；否则先放在 smoke，并在 Comments 注明日后迁移。
- **verify-quiz 覆盖率报告**：按章按池输出「题量 / 可执行题进校验表的数量」，不改变通过 / 失败判定。

## 验收标准

- [ ] smoke 的题量下限来自按章目标表，现状数值下全部通过；人为把某章下限调高 1 时 smoke 失败（自测后恢复）
- [ ] smoke 能发现「W4-W8 老题 id 缺失」（自测：临时删一个 id 时失败）
- [ ] 题面长度护栏的阈值与依据写在 Comments；现有 251 题全部通过
- [ ] verify-quiz 在末尾输出按章按池的覆盖率表
- [ ] `npm run check` 全绿
