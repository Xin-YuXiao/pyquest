# W4-W8 题量扩充：每章从 20 题扩到 40-60 题

Status: needs-triage
Priority: P2
Source: upstream README 路线图「W4-W8 题量进一步充实（可选扩展至每章 40-60 题：FITS 实操、emcee 漫步、NFW 拟合数值题）」
Depends on: 无硬依赖（推荐先落地 quiz-bank-lint 的题库静态校验；作答记录与复习方向见 learning-records / mistake-review）

## 问题陈述

- W4-W8（天文包 / 加速 / 数值方法 / 信号 / 暗物质）是课程最硬核的五周，目前每章 20 题（shard 10 / lair 7 / boss 3），
  讲义里大量有确定输出的实操内容（FITS 读写、emcee 漫步、NFW 拟合数值）还没有进题库。
- **一个容易被忽视的事实（已核实）**：W3 起的生成器章节，一次通关只会抽到 **9 道题**——
  3 块碎片符文（shard 池）+ 野外 2 块与巢穴 3 块祝福符文（都抽 lair 池）+ 1 块 BOSS 符文；答错时同一块符文石保持同一道题，
  答对的题不再出现。所以把题池扩到 40-60 题，**不会**让单个学生在一次通关里见到更多题，
  它带来的是：同班同学之间题目重合更少（抄答案更难）、重玩有新鲜感、为将来的复习 / 练习模式储备题源。
  扩充前必须想清楚这一点，否则会投入大量出题精力却达不到「多练」的预期。
- ADR-0001 当年否决「超纲题标注拓展并存」的理由之一是「每章仅 20 题，拓展题挤占讲义核心知识点的空间」；
  题量扩到 40-60 后这个前提变了，需要显式复议（见待决策）。
- 新维护者很可能**没有**课程素材：素材源目录在原作者的 Mac 上（docs/course-materials.md），讲义剥离版缓存在临时目录、可能已失效。
  没有素材就无法按 ADR-0001 出题。

## 解决方案

1. 先拿到并登记课程素材（人工），让「以讲义为权威源」可执行。
2. 一次 grilling 定下扩充目标与规则：每章目标题量、三池比例、是否允许「拓展」题、是否同时增加符文数量、批次顺序。
3. 做好结构准备：smoke 的题量下限改为按章可配置、题面长度护栏（防止长题把答题按钮挤出视口）、verify-quiz 覆盖率报告。
4. 沿用 docs/quiz-outline-w4-w8.md 的格式写一份 W4-W8 扩充提纲（每题标注「素材」「可执行」），grilling 确认后分两批实现。
5. 每批实现都必须让 verify-quiz 覆盖所有可执行题、smoke 下限随之提高、全部 E2E 保持绿色。

## 用户故事

1. 作为学生，我想不同同学抽到的题尽量不同，以便大家各自独立思考，而不是互相对答案。
2. 作为学生，我想重玩 W4-W8 时遇到没见过的新题，以便重玩也有练习价值。
3. 作为学生，我想新题仍然来自讲义（FITS 实操、emcee、NFW 数值），以便游戏里练的就是考试和作业要用的。
4. 作为学生，我想同一个题池里的题难度一致，以便无论抽到哪道题，挑战程度都公平。
5. 作为学生，我想新题的解析和老题一样讲清「为什么」，以便答对答错都有收获。
6. 作为学生，我想长代码题也能完整显示、按钮能点到，以便不会因为题面过长卡住。
7. 作为教师，我想扩充后的题库按知识点覆盖讲义各节，以便没有「某节课一题都没有」的盲区。
8. 作为教师，我想每道可执行题的输出都被真实运行校验过，以便题库没有算错的答案。
9. 作为教师，我想能看到每章每池的题量、可执行题比例，以便评估题库质量。
10. 作为教师，我想超纲内容要么不进题库，要么被明确标注来源，以便学生不被讲义外的写法困扰（ADR-0001）。
11. 作为维护者，我想先拿到课程素材的本地副本并登记版本，以便出题有据可查。
12. 作为维护者，我想扩充目标（40 还是 60、三池比例）在动手前定下来，以便提纲和实现不返工。
13. 作为维护者，我想 smoke 的题量下限随每批扩充自动收紧，以便题被误删时 CI 立刻报警。
14. 作为维护者，我想有一条题面长度护栏，以便新题不会重演「最高的题把确认按钮挤出视口、E2E 偶发失败」的旧问题。
15. 作为维护者，我想扩充按批次走、每批独立可合并，以便评审负担可控、出问题容易回滚。
16. 作为维护者，我想新题的 id 延续各章现有前缀与编号（不重排老题 id），以便老存档里的已答记录和抽题记录继续有效。
17. 作为维护者，我想扩充不改变任何题池的 tier，以便 smoke 的 tier 对齐检查与难度曲线保持不变。
18. 作为维护者，我想清楚知道单次通关只抽 9 题这件事，以便决定是否同时增加符文数量或依赖复习模式消化题库。
19. 作为课程方，我想提纲先给我审，以便内容经过课程把关后再进游戏。
20. 作为将来做复习 / 练习模式的开发者，我想题库足够大、按池按知识点组织，以便练习模式有充足题源。

## 实现决策

- **扩充只加题、不改结构**：W4-W8 仍是三池式 `w{N}shard / w{N}lair / w{N}boss`，heal 与 lair 共用池，tier 不变
  （W4=11/12/13 … W8=23/24/25）。新题 id 沿用各章现有前缀（ap / sp / nm / sg / dm）往后编号，老题 id 一律不改——
  存档里的已答槽位、已答题目、抽题记录都按 id 存储，改 id 会让老存档的抽题记录失效。
- **不改符文数量（除非 grilling 决定）**：单次通关抽 9 题由章节主题配置决定（碎片 3、野外祝福 2、巢穴祝福 3、BOSS 1），
  槽位 id 已预留到碎片 12 / 野外祝福 6 / 巢穴祝福 6，增加符文数量在数据层是可行的，但属于玩法改动，需要 grilling 拍板。
- **smoke 下限按章可配置**：现在是全局的 shard ≥ 10 / lair ≥ 7 / boss ≥ 3；改为一张「每章目标题量」表，
  每批实现后把对应章节的下限收紧到实际题量。
- **题面长度护栏**：E2E 视口高度 900 是为最高的一道题（sp15）调出来的；新增一条数据层检查——代码行数、题干与解析字数的上限
  （具体阈值由结构准备工单在现有最高题基础上测定）。若 quiz-bank-lint 已落地，规则放进它，否则先放在 smoke。
- **verify-quiz 覆盖率报告**：每章每池列出「可执行题数 / 已进校验表数」，提纲里标了「可执行」的题必须进校验表。
- **出题提纲格式**：沿用 docs/quiz-outline-w4-w8.md——按章、按池列知识点分配，「素材」标注直接采用讲义确定输出的题，
  末尾列「已决策事项」与「待决策事项」。
- **批次**：批次 A = W4 + W5，批次 B = W6 + W7 + W8（两批互不依赖，都依赖提纲 grilling）。

## 测试决策

- 好测试的标准：验证题库的外部性质（题量、tier 一致、槽位映射、可执行题输出正确、题面可完整显示），而不是逐题内容。
- **smoke（首选）**：按章题量下限、池内 tier 一致（已有）、题面长度护栏、新题 id 不与老题冲突、老题 id 全部仍在（防误删 / 误改）。
- **verify-quiz**：所有标注「可执行」的新题进校验表并实跑通过；输出覆盖率报告。
- **E2E**：不新增章节流程，现有 W4-W8 E2E 随机抽题、按正确答案作答，本就会覆盖新题；
  每批实现后连续跑两遍 W4-W8 E2E，确认长题不再导致点击失败。
- 不新增单元测试层。

## 待决策

1. **每章目标题量：40 还是 60？** 推荐先到 **40**（每章 +20，与上次「每章 20 题」批次同等工作量），用学习记录的数据再决定是否到 60。
2. **三池比例**：
   - A. 保持现有 10 / 7 / 3 的比例（40 题 = 20 / 14 / 6），与现有提纲结构一致；
   - B. 按单次通关的抽取频率 3 : 5 : 1（40 题 ≈ 13 / 22 / 5），lair 池被抽得最多、应最大。
   推荐 **A**：出题结构与难度分层更清晰；lair 池的重复率问题留到有学习记录数据后再调。
3. **是否允许「拓展」题（讲义外但合理的天文知识，如 astropy units / SkyCoord、M₂₀₀）？**
   ADR-0001 否决「拓展题并存」的理由之一是 20 题空间不足；扩到 40 后该理由不再成立。
   推荐**仍不允许**（保持「游戏教的 = 课堂讲的」这一验收标准）；若要允许，需新增一条 ADR 取代 ADR-0001 的这一部分，并要求拓展题显式标注来源。
4. **是否同时增加符文数量？** 推荐**不增加**（玩法冻结、章节时长不变），题库扩充的「多练」价值交给复习 / 练习模式（mistake-review）兑现。
5. **批次顺序**：推荐批次 A（W4+W5）与批次 B（W6-W8）并行；若人力有限，先做批次 B（路线图点名的 NFW 拟合数值题在 W8）。

## 不做的事

- 不改 W1-W3、W9-W11 的题库。
- 不改任何题池的 tier、不改池名、不改老题 id 与题面（老题内容修订走单独工单）。
- 不做练习 / 复习模式（属于 mistake-review）。
- 不提交课程讲义原文或剥离版到仓库（版权 / 许可未明，见 01 号工单）。
