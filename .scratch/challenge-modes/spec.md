# 挑战模式：每日星图 · 限时试炼 · 硬核模式 · 二周目

Status: needs-triage
Priority: P2
Source: 接手评估新增——通关第十一章后唯一的选项是「返回村庄 · 自由探索」，而所有符文石已变灰，游戏实际上结束了；
同时一周目最多 106 块符文石、题库 251 题（核实），超过一半的题永远见不到。课程是按周推进的，
学生在两次上课之间也缺少一个「每天花五分钟复习」的理由。
Depends on: achievements-codex（共用元进度存档模块，挑战纪录/打卡/周目数存在那里）、learning-records（作答记录带模式标签）、
mistake-review（挑战中答错的题也进错题本）、difficulty-economy（硬核模式与爱心/金币规则需协调）、accessibility（限时类模式的可访问性替代）

## 问题陈述

- 学生通关后没有任何可重玩的内容：主线符文石答对后永久变灰，BOSS 不再出现。
- 一周目只能见到约四成题目，剩下的题（含大量与讲义直接对应的可执行题）对学生不可见，浪费了题库。
- 课程按周上课，学生缺少「每天碎片时间回顾一下」的轻量入口；也没有「和同学比一比」的话题点。
- 答错最多扣到 1 颗心，乱猜几乎没有代价（核实：答题失误不会致死），对追求挑战的玩家缺少「答错真的有后果」的玩法。
- 现有抽题完全随机（核实：抽题用的是普通随机数），无法做「同一天大家同一套题」。

## 解决方案

在标题画面和冒险手册里新增「挑战」入口，提供四种基于既有题池的玩法：

1. **每日星图**：每天一套 5 题，按「本地日期」做确定性种子，从「已通关章节」的题池中分层抽取——同一天、同进度的同学拿到同一套题；完成后记录本地连续打卡天数与当日成绩。
2. **限时试炼**：选择一个或多个已通关的章，开始倒计时（初始 90 秒）；首答正确加时、答错扣时，连对计数；结束后记录该组合的本地最佳纪录。
3. **硬核模式**：开始新冒险时可勾选的规则修饰：答错真的会扣到 0 心并触发既有的「死亡 → 回本章野外重生」流程；答错的符文石下次打开会换一道题（防止靠排除法试出答案）。
4. **二周目（New Game+）**：全部通关后开启：保留图鉴/成就/纪录，重开主线；小怪更强；抽题优先抽「历史上从未答对过的题」；BOSS 符文答错即换题。

每日星图与限时试炼在「答题会话」里进行（一个不需要地图的连续答题界面），不影响主线存档；硬核与二周目是主线周目的修饰。

4. 作为学生，我想要每日星图在离线时也能玩，以便在没有网络的地方也能打卡。

15. 作为通关的玩家，我想要开启二周目，以便用更强的敌人重新走一遍旅程。
16. 作为二周目玩家，我想要符文石优先给我从未答对过的题，以便二周目真的能学到新东西、补全知识卡图鉴。

18. 作为二周目玩家，我想要标题画面「继续冒险」显示当前周目数（如「二周目 · 第 3 章」），以便清楚自己在哪一轮。
19. 作为二周目玩家，我想要 BOSS 符文答错就换题，以便 BOSS 题也需要真正掌握。
20. 作为学生，我想要在挑战模式里答对的题同样解锁知识卡、答错的题同样进入错题本，以便所有练习都沉淀下来。
21. 作为课程教师，我想要学习报告能区分主线作答和挑战作答，以便评估时不被刷题数据干扰。
22. 作为使用读屏或需要更多阅读时间的学生，我想要限时试炼有一个「不限时练习」的变体，以便同样能用这套题练习。

## 实现决策

**答题会话（新模块，挑战模式与教师题包共用）**
- 一个不依赖地图场景的连续答题界面：给定题目列表与规则（是否限时、加减时、是否计入打卡），顺序呈现题目，结束时给出结果页（每题对错 + 可展开解析）。
- 复用现有答题面板的渲染与交互（选项、填空、键盘 1-4/Enter、解析展示）。前置 prefactor：答题面板目前在打开/关闭时直接暂停/恢复它所属的 Phaser 场景，需要改为接收「打开时 / 关闭时」钩子，由调用方决定暂停什么；主线行为不变。
- 会话期间不扣主线爱心、不发碎片；结果写入元进度（成绩、打卡）和学习记录（若已落地，作答带模式标签 daily / trial）。
- 入口：标题画面新增「挑战」按钮，冒险手册新增「挑战」分页（入口与纪录）。

**确定性抽题（纯函数）**
- 新增一个纯函数：给定种子与候选题池列表，按「分层」规则抽 N 道不重复题。随机源用种子化的伪随机数（地图生成已有一个种子化随机数函数可复用）。
- 每日星图的种子 = 本地日期字符串（YYYY-MM-DD）的稳定哈希；候选题池 = 已通关章节的全部题池；分层 = 优先覆盖不同章，同章内 shard/lair/boss 按 3:1:1 的权重。
- 「同进度同题」：同一天、已通关章节集合相同 → 结果相同。这是可测试的契约。

**每日星图规则（推荐默认，待 triage 确认）**
- 解锁：通关第一章。每天 5 题；当天第一次完整提交才计成绩与打卡；之后可重看结果、不可重刷。
- 打卡：以本地日期计，连续天数中断即归零；不做服务器校验，不防改系统时间（只存本机、没有排行榜，作弊没有收益）。
- 中途退出不计成绩不算打卡（有确认提示）。

**限时试炼规则（推荐默认，待 triage 确认）**
- 解锁：通关任意一章；可多选已通关章节作为题源。
- 初始 90 秒；首答正确 +8 秒、答错 −10 秒（答错后同一题不再给第二次机会，直接下一题）；题源耗尽则提前结束。
- 成绩 = 答对题数；同时记录最长连对。每个「章节组合」保存一条本地最佳纪录。
- 可访问性变体「不限时练习」：同样的题源与流程，不计时、不计纪录。

**硬核模式与二周目（玩法改动，待 grilling 定稿）**
- 都是主线周目的修饰，存在主线存档的周目字段里（如 `run: { cycle: 1, modifiers: { hardcore: false } }`），可选字段，老存档缺省为一周目、无修饰。
- 硬核：答错扣心不再有「最低留 1 颗心」的保护；扣到 0 走既有死亡流程；答错的符文石清除其抽题记录（下次打开重新抽题）。
- 二周目：全部通关后在胜利封印页与标题画面出现「开启二周目」；开启时清空主线进度（章节进度、符文槽破解、当前抽题记录），保留元进度；小怪生命 +1、移速提高（具体数值待 grilling）；抽题时优先排除「历史上答对过的题」（元进度里的知识卡集合即可充当这个集合），池里不够再回退到现有规则；BOSS 符文答错即换题。
- 与 difficulty-economy 协调：若爱心成长/金币商店先落地，硬核模式下这些系统的规则需在 grilling 中一起定。

**测试接缝**
- 只读快照新增当前周目与修饰、当前答题会话状态（模式、剩余时间、题号）。
- 语义动作新增：「以指定日期开启每日星图」（注入日期，避免依赖真实时钟）、「让限时会话计时器快进 N 秒」。不新增直接写成绩/打卡的作弊入口。

## 测试决策

- **smoke（数据层，首选覆盖抽题契约）**：给定固定日期与已通关章节集合，每日星图抽题结果稳定（锁定一组期望题号）；结果中无重复、全部来自已通关章节的题池；已通关集合不同则结果可以不同。
- **E2E**：新增非章节 E2E 套件：新游戏 → 测试接缝 gotoChapter(2)（使第一章通关）→ 标题/手册进入每日星图（注入日期）→ 走真实 DOM 答完 5 题 → 断言结果页与打卡天数 = 1 → 刷新后再次进入显示「今日已完成」。限时试炼：注入快进让计时归零，断言结束页与最佳纪录。挂进 npm run test:e2e 的「额外套件」列表。
- 主线章节 E2E 必须全部保持不变——答题面板 prefactor 的回归由它们兜底。
- 硬核/二周目：章节 runner 增加可选的「周目修饰」参数，复用第一章或第三章的 spec 跑一遍硬核与二周目，断言答错后爱心可降到 0 并回野外、二周目抽到的题不在历史答对集合里。
- **单元测试层（若已落地）**：限时计时规则（加减时、提前结束）、打卡天数的跨日计算（含跨月、跨年）。
- 先例：smoke 现有的「随机抽题：同池同难度、重开不变题、已答不重复、同池不撞题」检查；runner 的 newGame / gotoChapter / resume 步骤。

## 待决策

1. **硬核与二周目的具体规则**（小怪加强数值、BOSS 是否加强、硬核死亡惩罚是否只回野外、二周目是否允许叠加硬核）：推荐二周目小怪生命 +1、移速 +15%，BOSS 不加血只加「答错换题」；硬核可与二周目叠加。→ 工单 03。
2. **挑战作答是否计入学习统计**：推荐全部记录但带模式标签，学习报告默认只统计主线、可切换查看全部；错题本与知识卡收所有模式。
3. **每日星图题源**：推荐「已通关章节」而不是「全题库」——保证不出现没学过的内容，代价是「同一天所有人同题」只在同进度内成立。
4. **限时试炼的数值**（90 秒 / +8 / −10）：推荐先用这组，试玩后校准。
5. **二周目开启后旧主线存档怎么办**：推荐直接覆盖（同一存档槽），开启前二次确认；多存档槽不在本 effort 范围。

## 不做的事

- 不做在线排行榜、服务器校验或防作弊（纪录只存本机）。
- 不新增题目（ADR-0001）；所有模式只使用既有题池。
- 不做多存档槽。
- 不做「无伤挑战」的独立副本模式——「无伤通关」作为成就由 achievements-codex 判定。
- 不做实时多人对战。

## 备注

- 二周目的「优先抽从未答对过的题」与一周目最多 106 块符文石的结构正好互补：两到三个周目即可覆盖全部 251 题，配合知识卡图鉴形成清晰的长期目标。
- 现有存档在每次打开符文石时就会存档（抽题绑定到符文石）；硬核「答错换题」需要在答错时清掉该符文槽的抽题记录并存档，避免刷新页面绕过。
- 答题面板 prefactor 若被 custom-quiz-packs 先做了，本 effort 直接复用（以先落地者为准）。
