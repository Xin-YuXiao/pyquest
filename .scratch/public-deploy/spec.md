# 公开部署：让学生打开链接就能玩

Status: needs-triage
Priority: P2
Source: 接手评估新增（目前没有任何部署，学生只能克隆仓库、自行下载素材、本地 npm run dev）
Depends on: self-hosted-fonts（国内可访问）；与 `.scratch/part2-landing/issues/02` 第 1 条（dev server 暴露到局域网）合并处理

## 问题陈述

PyQuest 是课程配套游戏，但今天想玩它的学生必须：装 Node、克隆仓库、自己去 itch.io 下载 Tiny Swords 素材包放到正确目录、
再 `npm run dev`。这对非计算机专业的天文学生门槛过高，课程方也无法在课堂上「发一个链接」。

公开部署有几道真实障碍（源码核实）：

1. **素材许可证**：Tiny Swords（Pixel Frog）许可证禁止再分发素材本身，所以仓库不入库素材；但任何公开部署的网页游戏都会让浏览器下载这些 PNG——
   「把素材打进公开部署的游戏构建」是否属于允许的「在项目中使用」，需要人工核实许可证原文后判断。
2. **子路径部署会坏**：构建配置的 base 是相对路径，但 Tiny Swords 素材清单里的资源 URL 是以 `/TinySwordsFreePack/...` 开头的根绝对路径，
   部署到 `用户名.github.io/pyquest/` 这类子路径时会请求到域名根目录而 404（需核实：本地 `vite preview` 服务在根路径，发现不了这个问题）。
3. **构建夹带未用素材**：构建把整个素材目录（publicDir）原样拷进产物——本地若有 Tiny Swords 就会一起打包；`assets/cc0/`（约 970 KB，当前版本未加载）也会被带上。
4. **国内可达性**：字体走 Google Fonts 与 jsdelivr（见 `self-hosted-fonts`）；托管平台本身在国内的可达性也要选型。
5. **同源存储**：存档存在 localStorage。若用 GitHub Pages，同一用户的所有 Pages 站点同源，预览版与正式版会共享 / 覆盖存档。
6. **版本可追溯**：部署后学生反馈问题时，无法知道他们玩的是哪个版本。

## 解决方案

- 先由人核实许可证并选定素材方案、托管平台；
- 修好子路径部署与构建产物内容，让构建产物可以放在任意静态托管的任意路径下；
- 合并到主分支后由 CI 自动构建、部署，并对线上地址跑一次冒烟；
- 页面显示版本号与提交哈希；每次发布前用「上一版存档」回归读档，保证学生进度不丢。

## 用户故事

1. 作为天文专业的学生，我想打开老师发的链接就直接开始冒险，以便不用装任何开发工具。
2. 作为在国内上课的学生，我想链接在校园网和手机流量下都能稳定打开，以便课堂上不卡住。
3. 作为学生，我想新版本发布后我的存档仍然能继续，以便不会因为更新丢进度。
4. 作为学生，我想在页面角落看到版本号，以便向老师报告问题时说清楚版本。
5. 作为老师，我想有一个固定的正式地址，以便写进课程大纲与讲义。
6. 作为老师，我想在新版本上线前先在预览地址试玩，以便确认没有问题再通知学生。
7. 作为维护者，我想合并到主分支后自动部署，以便不用手动打包上传。
8. 作为维护者，我想部署失败或线上冒烟失败时 CI 变红，以便第一时间发现坏版本。
9. 作为维护者，我想构建产物里只有游戏真正加载的素材，以便包体小、也不意外发布未授权的文件。
10. 作为维护者，我想构建产物放在任意子路径下都能正常加载资源，以便自由选择托管方式。
11. 作为维护者，我想 Tiny Swords 素材（若许可证允许进构建）只存在于 CI 的私有存储里、永不进入仓库，以便遵守「禁止再分发素材本身」。
12. 作为维护者，我想在许可证不允许时有一条换素材的路，以便部署不被卡死。
13. 作为维护者，我想预览版与正式版的存档互不覆盖，以便试玩预览不会弄坏正式进度。
14. 作为维护者，我想本地 `npm run dev` 默认只在本机可访问，以便开发服务器不暴露到局域网（需要局域网真机调试时显式开启）。
15. 作为课程方，我想部署方案的许可证判断有书面记录（ADR），以便日后合规审查有据可查。
16. 作为维护者，我想在线上地址上跑一次最小冒烟（标题页出现、进入第一章、打开一块符文石），以便确认部署产物真的可玩。
17. 作为学生，我想更新后浏览器不会长时间卡在旧版本，以便及时拿到修复。
18. 作为维护者，我想回滚到上一个版本只需要重新部署某个提交，以便事故时快速恢复。

## 实现决策

- **许可证与素材方案（01 决定）**：
  - A：许可证允许在已发布的游戏构建中包含素材——素材包存放在 CI 的私有存储（加密 secret 中的下载地址 / 私有制品），只在部署构建时取用，仓库永不入库；
  - B：许可证不允许——改用可再分发素材（仓库已有 `assets/cc0` 的 0x72 DungeonTileset 与 Kenney Tiny Town / Tiny Dungeon，均为 16px 像素风，
    与 Tiny Swords 的 64px 单位 / 192px 角色帧规格和画风差异很大，需评估工作量；角色动画帧是否够用需核实）；
  - C：只部署占位色块版本——**不可接受**：占位图仅用于逻辑验证，学生无法辨认角色与地形，等于不可玩。
  - 结论写成一篇新的 ADR（编号顺延 ADR-0001），记录许可证原文要点、判断依据与日期。
- **托管平台（02 决定）**：候选 GitHub Pages、Cloudflare Pages、国内对象存储 + CDN（需备案）。评估维度：国内可达性与速度、是否需要备案、预览环境能力、同源存储隔离、费用、CI 集成。
- **资源路径**：素材清单的 URL 改为相对构建 base 解析（由 Phaser 加载器的 base / 路径机制或构建时注入的 base 统一前缀），使产物可放在任意子路径；CC0 素材路径同理。
- **构建产物内容**：构建不再原样拷贝整个素材目录；只发布游戏实际加载的文件（Tiny Swords 清单 + 程序化贴图无需文件）；未加载的 `assets/cc0` 不进产物。
  具体机制（缩小 publicDir 范围 / 构建插件按清单拷贝）在 03 实现时选择，验收以「产物文件清单 = 清单引用的文件」为准。
- **版本标识**：构建时注入版本号（package.json version）与短提交哈希，标题页角落显示；同时作为存档的 savedWith 元数据（与 `learning-records` 协调，非必需）。
- **存档跨版本兼容**：维护一组「历史存档样本」（v1、v2、各里程碑版本的 v3），每次构建跑读档回归：能读、章节进度一致、不抛错。
- **存档隔离**：若预览与正式同源，预览版的存档键加渠道前缀（如 `pyquest:preview:save:v2`）；推荐让预览使用不同源（平台的预览子域名），则无需改键。
- **缓存**：JS / CSS 已带内容哈希；index.html 与素材 PNG 依赖托管平台缓存头；素材若无哈希，发布新素材时在 URL 上附版本参数。
- **dev server**：默认只监听本机；提供显式的局域网调试脚本（如 `dev:lan`），README 说明用途与风险（05 拍板）。
- **部署流水线**：沿用现有 CI 的 lint → test → build → test:e2e；部署作业只在主分支、且前序作业全绿时运行；部署后对线上地址跑最小冒烟（Playwright，只读、不写存档或写到隔离键）。

## 测试决策

- 只测外部可观察结果：产物文件清单、子路径下资源请求是否 200、线上冒烟能否进入第一章并打开答题面板、历史存档样本读档后的章节进度。
- **子路径回归**：在 CI 里把构建产物挂到一个非根路径（如 `/pyquest/`）的本地静态服务上，跑一条最小 E2E（标题页 → 第一章 → 打开一块碎片符文），断言无 404、浏览器无报错。
  先例：run-e2e 的「复用 / 临时起服务」逻辑与 E2E runner 的 BASE_URL 机制。
- **产物清单**：构建后脚本比对产物里的素材文件与素材清单引用的文件，多一个或少一个都失败。
- **存档兼容**：用历史存档样本做读档回归（E2E 注入 localStorage 后刷新，或单元测试直接调存档模块——后者依赖 `core-unit-tests/issues/01`）。
- 线上冒烟不进 PR 的必经检查（避免外网抖动导致 PR 红），只在部署作业里运行。

## 待决策

1. **Tiny Swords 是否可进公开构建**（01）——无推荐，必须读许可证原文；若原文含糊，推荐写信询问作者（Pixel Frog）并保留回复。
2. **托管平台**（02）——推荐先评估 Cloudflare Pages 与 GitHub Pages 的国内实测可达性；若都不理想且课程方能提供备案域名，再考虑国内对象存储 + CDN。
3. **预览环境**——推荐有：PR 预览让老师试玩新内容；若平台不支持，退而求其次用一个固定的 staging 地址。
4. **dev server 监听范围**（05）——推荐默认本机，局域网调试显式开启。

## 不做的事

- 账号系统、云存档、多人功能（存档仍在浏览器本地；跨设备迁移见 `save-portability`）。
- PWA 离线安装（可在部署稳定后另开 effort）。
- 自定义域名与备案流程本身（只在 02 中评估是否需要）。
- 访问统计 / 埋点（涉及隐私，需另行讨论）。
