# 成就与知识图鉴（冒险手册）

Status: needs-triage
Priority: P2
Source: 接手评估新增——答对一道符文石后，它的「解析」只在答题面板里闪现一次就再也找不到；
全游戏 251 题分布在 34 个题池里，但一次主线最多只有 106 块符文石（核实：W1 10 块 / W2 13 / W3 11 / W4-W11 各 9），
也就是一周目最多见到约 42% 的题，玩家既没有「我学会了什么」的归档，也没有继续探索剩余 58% 的动机。
Depends on: learning-records（首答正确等判定）、challenge-modes（二周目/每日星图是补全图鉴的主要来源，同一个元进度存档）、
mistake-review（分工：图鉴收「学会的」、错题本收「错过的」）、accessibility（解锁提示的减少动态 / 读屏）、world-secrets（彩蛋类成就）

## 问题陈述

- 学生答对一道题，讲解只在面板里显示一次；想复习「第六章那道 quad 返回两件套的题」时，只能重新打一遍游戏——而且符文石答对后变灰，主线里再也打不开。
- 玩家没有任何「收集」与「完成度」反馈：通关后不知道自己见过多少知识点、还差什么，缺少重玩的理由。
- BOSS 战是每章的高潮，但击败后 BOSS 的名字、所在章与对应知识点不会留下任何记录。
- 现有的激励只有「碎片」和「通关」，没有对「答得准」「打得稳」「探索得全」这些好行为的认可；而答错只扣心且最低留 1 颗心（核实：答题失误不会致死），乱猜的成本很低——如果设计不当，成就系统反而会奖励乱猜和刷题。
- 维护者视角：目前所有进度都在一个存档键里，「新的冒险」和胜利页的「重新开始」会整个清掉（核实：清档会删除整个存档键），任何长期收集都会被一键抹掉。

## 解决方案

新增「冒险手册」：在世界地图同一个面板里加分页（地图 / 知识卡 / BOSS 图鉴 / 成就），Tab 呼出不变。

- **知识卡图鉴**：任意一道题答对后，这道题成为一张知识卡（题面摘要 + 代码块 + 解析），按「章 → 题池」归档；未解锁的卡显示为剪影和「还差 N 张」。手册里随时翻阅，作为复习材料。
- **BOSS 图鉴**：击败某章 BOSS 后解锁 BOSS 卡（名字、所属章、野外/巢穴名、本章知识点概述、击败日期）。
- **成就徽章**：约 20 个，分学习向 / 探索向 / 挑战向三类；全部基于「首答」「无伤」「完整探索」这类好行为，不设任何「累计答题数」「累计尝试次数」型成就。解锁时在屏幕角落弹一条不打断操作的轻提示；答题面板打开期间排队，面板关闭后再弹。
- **完成度**：手册首页和标题画面显示总完成度（知识卡 x/251、BOSS x/11、成就 x/N）。
- **元进度存档**：图鉴、成就、各类最佳纪录放进独立于主线存档的「元进度」存档，「新的冒险」「重新开始」不会清掉它们。

## 用户故事

1. 作为学生，我想要答对一道题后它自动变成一张知识卡，以便我不用记笔记也能留住这道题的讲解。
2. 作为学生，我想要在冒险手册里按章、按题池翻阅已收集的知识卡，以便考前复习某一周的内容。
3. 作为学生，我想要知识卡上同时看到题面、代码块和解析，以便复习时能还原当时的情境，而不是只看一句结论。
4. 作为学生，我想要未收集的卡以剪影显示并标出「本题池还差 N 张」，以便知道哪些知识点还没见过。
5. 作为学生，我想要知识卡不显示选项和正确答案的序号，以便翻卡时仍能先自己想一想（解析里本来就包含了答案推理）。
6. 作为学生，我想要知道一周目最多只能见到约四成的题，以及剩下的题从哪里补（二周目、每日星图、限时试炼），以便有明确的重玩目标。
7. 作为学生，我想要在知识卡上看到「首答正确 / 曾经答错」的小标记，以便知道哪些是真会、哪些是蒙过去后又学会的（数据来自学习记录）。
8. 作为学生，我想要击败 BOSS 后在 BOSS 图鉴里留下一张卡，以便回顾每章的高潮与它代表的知识点。
9. 作为学生，我想要 BOSS 卡写明所在章、野外与巢穴名、本章知识点概述，以便把「打过的怪」和「学过的周次」对上号。
10. 作为学生，我想要在一章所有符文首答全对时获得一个徽章，以便我的「真会」被认可，而不是只有「通关」。
11. 作为学生，我想要成就不会因为「答得多」「试得多」而解锁，以便我不会被诱导去乱猜或刷题。
12. 作为学生，我想要无伤通关一章（不被小怪打到、也不答错）时获得徽章，以便有一个兼顾操作与学习的挑战目标。
13. 作为学生，我想要「又快又准」类徽章只按我在该章的实际游玩时长计时、并且要求本章无答错，以便速通不会变成乱猜的借口。
14. 作为玩家，我想要发现彩蛋、到访所有场景、和每块引导石碑都对话过之后有探索向徽章，以便探索本身有回报。
15. 作为玩家，我想要徽章解锁时屏幕角落弹出一条轻提示且不打断我正在做的事，以便不影响答题和战斗。
16. 作为玩家，我想要答题面板或对话框打开期间解锁的徽章先排队、关掉面板后再提示，以便答题时不被打扰。
17. 作为开启了「减少动态效果」的玩家，我想要解锁提示改为静态出现、不做飞入动画，以便不引起不适。
18. 作为使用读屏软件的玩家，我想要解锁提示和手册分页能被读出来，以便同样享受收集反馈。
19. 作为玩家，我想要部分徽章是「隐藏成就」（解锁前只显示问号与一句谜语式提示），以便保留发现的乐趣。
20. 作为玩家，我想要在手册首页和标题画面看到总完成度，以便一眼知道离全收集还有多远。
21. 作为重新开始冒险的玩家，我想要图鉴、BOSS 图鉴和成就在「新的冒险」或「重新开始」之后仍然保留，以便长期收集不会被一键清空。
22. 作为老存档玩家，我想要第一次打开新版本时，已经答对过的题自动补成知识卡、已击败的 BOSS 自动补进 BOSS 图鉴，以便升级不丢收集进度。
23. 作为用「跳章」进入后续章节的测试/演示用户，我想要被跳过的章节不会凭空解锁知识卡，以便图鉴只记录真正答对过的题。
24. 作为课程教师，我想要学生能把「已收集知识卡清单」作为学习证据之一（由学习报告导出），以便了解学生的覆盖面。
25. 作为维护者，我想要成就定义是一份纯数据清单（id、名称、分类、说明、是否隐藏、判定条件），以便增删成就不碰引擎代码，并能被数据层冒烟测试校验。
26. 作为维护者，我想要新增题目时知识卡自动增加、总数自动更新，以便题库扩充不需要同步改图鉴。
27. 作为维护者，我想要测试接缝能读到元进度快照（已收集卡、已解锁成就），以便 E2E 能断言收集和解锁行为。

## 实现决策

**元进度存档（与 challenge-modes 共用同一个模块）**
- 新增「元进度存档」模块，使用独立的本地存储键（建议 `pyquest:meta:v1`），与主线存档键分离；主线的「新的冒险」与胜利页「重新开始」只清主线存档，不清元进度。
- 元进度存放长期、跨周目的数据：知识卡集合、成就解锁记录（id → 解锁时间）、已读知识卡集合（「讲义精读」类成就用）、各挑战模式最佳纪录与打卡（challenge-modes 写入）、周目计数（challenge-modes 写入）。
- 极简形状（以实现时为准）：
  `{ v: 1, cards: string[], cardMeta: { [qid]: { firstTryCorrect?: boolean, unlockedAt: number } }, badges: { [id]: number }, cardsViewed: string[], bossesSeen?: number[] }`
- 首次加载时做一次「回填」：主线存档里已答对的题目集合 → 知识卡；已击败 BOSS 的章 → BOSS 卡（BOSS 卡本身可直接由主线进度推导，不必存；但为了在「新的冒险」后保留，需要在元进度里记一份已见 BOSS 列表）。跳章（测试接缝的 gotoChapter）只标记符文槽破解、不写入已答题目集合（已核实），因此天然不会凭空解锁知识卡。
- 存档导出/导入（save-portability）需要同时包含主线存档和元进度存档——在该 effort 的规格里协调。

**知识卡**
- 一道题 = 一张卡，卡的 id 就是题目 id；卡的归档维度为「章（由题池反查章节注册表）→ 题池」。题池到章的映射由章节注册表的 pools 字段反查；第一、二章的手工题池（w1field / w2heal 等）同样能反查到。
- 解锁时机：任何模式下答对一道主线题库里的题（主线符文、二周目、每日星图、限时试炼、错题本重做）都解锁对应知识卡；教师自定义题包里的题不进图鉴（不在主线题库里）。
- 卡面内容：章标签、题面（完整）、代码块（沿用答题面板的语法高亮）、解析；**不显示选项和答案序号**。若学习记录已落地，显示「首答正确 / 曾答错」小标记。
- 总数与分池数量全部由题库数据动态计算，不写死。

**BOSS 图鉴**
- 数据来自章节注册表（BOSS 名、章标题、副标题、野外/巢穴名、胜利文案）；「本章知识点概述」取章节注册表现有字段拼接，不新增题面类内容（若需要新文案，走内容流程，见待决策）。
- 解锁条件：该章 BOSS 被击败（主线任一周目）。

**成就引擎**
- 成就定义是一份纯数据清单：`{ id, name, category: 'learn' | 'explore' | 'challenge', desc, hidden?: boolean, hintWhenHidden?: string, when: <事件名>, test: (ctx) => boolean }`。
- 引擎订阅现有的 HUD 刷新事件，并新增少量语义事件：答题结果、章节通关、场景进入、对话结束、彩蛋发现（world-secrets 发出）、挑战模式结束（challenge-modes 发出）。每个事件触发时只评估订阅了该事件的成就，已解锁的不再评估。
- 判定只读三类数据：元进度、主线进度、「章内战绩」（见下）以及学习记录（若已落地）。
- **章内战绩**（新增，存在主线存档每章进度下，可选字段、缺省为空，向后兼容）：本章活跃游玩时长（只在本章场景激活且页面可见时累计）、本章受到的伤害次数（小怪与答错分开计）、本章答错次数、本章死亡次数。用于无伤、又快又准等判定。
  - 核实发现：胜利页的「冒险用时」是从开始新冒险起的墙钟时间（读档后沿用存档里的开始时间），关掉游戏的时间也算进去，所以不能用来判定「N 分钟内通关」；章内活跃时长必须单独累计。
- **反乱猜原则**：所有学习向成就基于「首答」（每道题第一次作答的对错）；不设「累计答对 N 题」「累计作答 N 次」类成就；「又快又准」要求本章答错次数为 0；收集类成就按「不同的题」计数，同一题重复答对不累加。

**冒险手册界面**
- 复用世界地图面板：Tab 呼出后顶部出现分页（地图 / 知识卡 / BOSS / 成就），默认停在地图页，保证现有「Tab 呼出世界地图」的 E2E 行为不变。分页可用鼠标点击，也可用键盘左右方向切换（已核实：世界地图打开时会暂停当前场景，且答题/对话/转场/濒死期间不允许打开，所以方向键不会驱动角色）。
- 标题画面新增「冒险手册」按钮（无存档时也可进入，只显示元进度里的内容）。
- 解锁提示：独立于 HUD 底部交互提示条的角落提示元素；队列化；答题面板 / 对话框打开期间暂缓；尊重减少动态效果。

**测试接缝**
- 只读快照新增 `meta`（知识卡、成就、已见 BOSS），保持纯 JSON。
- 语义动作新增「清空元进度」（测试隔离用），不新增任何直接解锁成就的作弊入口——成就必须走真实判定链路。

## 测试决策

- 好测试只断言外部行为：「答对一题后手册里多一张卡」「击败 BOSS 后 BOSS 页出现该卡」「通关后在主线清档后元进度仍在」，不断言引擎内部的订阅表。
- **E2E（首选）**：新增一个非章节的 E2E 套件（像现有第一章独立脚本那样的独立脚本），流程：新游戏 → 答对第一章一块符文 → Tab 打开手册切到知识卡页 → 断言该卡可见、解析文本存在；`slayBoss` 后断言 BOSS 页出现；点「新的冒险」后断言知识卡仍在。run-e2e 目前只按章节号枚举脚本，需要加一个「额外套件」列表把它挂进 `npm run test:e2e`（若其他 effort 已加，复用）。
- 现有章节 E2E 的 victory/saveCheck 步骤不应受影响；无伤成就可借 godmode 在 E2E 里稳定触发（godmode 本身就让玩家不受伤，用来断言「无伤封印」解锁是合理的）。
- **smoke（数据层）**：成就清单完整性——id 唯一、分类合法、隐藏成就必须有提示语、依赖开关指向存在的功能名；知识卡总数 = 题库总数；每个题池都能反查到章。
- **单元测试层（若 core-unit-tests 已落地）**：回填逻辑（v2 存档 → 元进度）、章内活跃时长累计（可见性切换时暂停）。
- 先例：现有 `e2e.mjs`（独立 E2E 脚本）、runner 的 worldMap 步骤（世界地图节点断言）、smoke 的题池校验。

## 待决策

1. **成就清单定稿**（名称、阈值、哪些隐藏）：推荐以上表为基础，阈值「10 分钟」「30 张」「100 张」需要一位真实玩家试玩后校准。→ 工单 03。
2. **知识卡是否显示正确选项**：推荐不显示选项与答案序号，只显示题面、代码与解析——解析本身已包含推理，翻卡时保留「先想一想」的余地。
3. **BOSS 卡的知识点概述文案**：推荐只用章节注册表现有字段拼接，不新写文案；若要写专门的「BOSS 卡背面故事」，属于内容工作，交给 story-and-companions 统一处理。
4. **元进度是否随「新的冒险」一起清**：推荐不清（长期收集的意义所在），另在设置/手册里提供一个需二次确认的「清空收集」按钮。
5. **手册入口**：推荐并入世界地图面板做分页（不新增按键，学习成本最低）；备选是新增一个 C 键独立面板。

## 不做的事

- 不做在线排行榜、账号或任何服务器同步（元进度只存本机）。
- 不做成就奖励道具/数值（不与 difficulty-economy 的金币挂钩），成就只是认可。
- 不新增题目或改写题面与解析（ADR-0001）；知识卡完全复用现有题库内容。
- 不把教师自定义题包的题纳入图鉴。
- 不做成就分享图片/社交分享。
