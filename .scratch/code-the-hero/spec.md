# 写代码驱动勇者：代码训练场

Status: needs-triage
Priority: P2
Source: 接手评估新增 · 借鉴教学研究/教育产品（见 .scratch/INSPIRATION.md）——CodeCombat（写 Python 控制角色过关）、The Farmer Was Replaced（Python 风格语言自动化、即时反馈、按概念逐步引入）
Depends on: pyodide-sandbox（硬依赖其 01 号题型分派/按键隔离与沙盒运行时工单）；可选协同 learning-records（记录关卡完成）、mobile-touch-controls（触屏编辑体验）

## 问题陈述

- **学生视角**：W1–W2 是全课程的地基（变量、列表与索引、for/range、if/elif/else、while/break、def/return），
  但游戏里这两章全是「读代码选答案」。学生会读，不一定会写；而「写一小段代码让东西动起来」恰恰是初学者最容易获得成就感、也最能暴露误解的时刻。
- **借鉴**：CodeCombat 用「写 Python 控制英雄」让大量学生入门；The Farmer Was Replaced 用 Python 风格语言自动化无人机，
  玩家评价它「按概念一个一个引入」「按下执行看着无人机干活的即时反馈很爽」，也有人指出对完全零基础者引导不足——
  PyQuest 的优势是：前面的四选一章节已经讲过概念，训练场只需要让学生「用出来」。
- **安全与稳定**：玩家写的是任意 Python，可能死循环、可能试图访问页面；游戏不能因此卡死或被破坏。
- **助教视角**：希望有一组短小、可以在课上演示的「写代码过关」关卡，概念顺序与讲义 W1–W2 一致。

## 解决方案

「代码训练场」：一系列网格小房间，每关一个目标（走到符文石、收集碎片、避开陷阱、击败史莱姆）。玩家不用方向键，而是在编辑器里写真 Python：

```
for i in range(4):
    move('right')
if look() == 'trap':
    move('up')
```

点「运行」后：代码在沙盒（Pyodide，Web Worker）里执行，期间调用的 `move / attack / look` 等英雄 API 由一个**确定性的关卡模拟器**即时结算，
产出一份「动作记录」；执行结束（或达到步数上限）后，游戏按动作记录回放勇者的动作。到达目标即过关，显示「用了几行 / 几步」与个人最佳。

关卡按 W1–W2 概念逐级引入（顺序需助教对齐讲义，01 号工单）：顺序执行 → 列表与索引 → for + range → if/elif/else → while（直到…）→ break → def 复用 → 遍历列表收集碎片。
每关开头一句话提示本关新概念（只用课上的术语），并给出起始代码。

## 用户故事

1. 作为学生，我想要写几行 Python 就能让勇者走动，以便第一次感受到「代码控制世界」。
2. 作为学生，我想要点「运行」后看到勇者按我的代码一步步行动，以便直观对照代码与结果。
3. 作为学生，我想要代码出错时看到 Python 的报错信息和出错行，以便学会读错误。
4. 作为学生，我想要写出死循环时几秒后被中断并提示，以便不用刷新页面。
5. 作为学生，我想要每关只引入一个新概念，并附一句提示和起始代码，以便循序渐进。
6. 作为学生，我想要 `look()` 能告诉我前方是什么（墙 / 陷阱 / 水 / 史莱姆 / 符文石 / 空地），以便用 if 和 while 做判断。
7. 作为学生，我想要回放可以加速、暂停和逐步执行，以便找到我的代码在哪一步走错了。
8. 作为学生，我想要回放时编辑器高亮当前正在执行的那一行（对应动作的行号），以便把动作和代码对上号。
9. 作为学生，我想要过关后看到「行数 / 步数」和个人最佳，以便有动力写得更简洁。
10. 作为学生，我想要卡关时可以看一个分级提示（先概念提示，再关键语句提示，最后才看参考解），以便自己想出来而不是直接抄答案。
11. 作为学生，我想要我写的代码在离开关卡后仍被保存，以便下次接着改。
12. 作为学生，我想要训练场完全可选、不影响主线进度，以便按自己的节奏练习。
13. 作为学生，我想要在编辑器里正常输入 w/a/s/d/e/j/m、空格与方向键，以便写代码时不被游戏快捷键干扰。
14. 作为网络差的学生，我想要沙盒加载失败时看到清楚的说明（并可以只看关卡演示），以便知道不是我代码的问题。
15. 作为助教，我想要关卡的概念顺序与讲义一致，以便配合 W1–W2 的课堂进度布置练习。
16. 作为助教，我想要投屏演示一关：现场写代码、运行、讲解回放，以便课上带学生一起思考。
17. 作为助教，我想要知道学生是否完成了某关（通过学习记录或学习报告），以便布置为课后练习。
18. 作为维护者，我想要关卡模拟器是纯函数、关卡是数据，以便新增关卡不改代码、每关参考解在 CI 里自动验证可过。
19. 作为维护者，我想要玩家代码无法直接操作游戏对象，只能产出动作记录，以便任何代码都破坏不了游戏状态。
20. 作为维护者，我想要每次运行有动作数上限与时间上限，以便恶意或失误代码不会耗尽资源。
21. 作为维护者，我想要关卡在没有 Python 运行时的环境（smoke、CI 数据层）也能用「动作列表」直接验证，以便测试不依赖 Pyodide。

## 实现决策

- **安全模型：代码只产出动作记录。** 玩家代码在沙盒 Worker 中运行；英雄 API 是注入到 Python 全局的少量函数，
  调用时同步转给 Worker 内的关卡模拟器结算并追加到动作记录；Worker 没有 DOM，主线程只消费结构化的动作记录（逐条校验类型与参数），
  不执行任何来自 Worker 的代码。注意：Pyodide 在 Worker 内仍可 `import js` 访问 Worker 全局（可能发网络请求），
  这一点与 pyodide-sandbox 共享安全边界，在其规格中统一处理（本游戏是自学工具，不做防作弊）。
- **关卡模拟器（纯函数、JS、Worker 与主线程共用同一模块）**：
  - 关卡数据：网格（地面 / 墙 / 水 / 陷阱 / 符文石 / 碎片 / 史莱姆）、起点与朝向、目标（到达 / 收集全部碎片 / 击败全部史莱姆 / 组合）、
    本关可用 API 白名单、步数上限、起始代码、分级提示、参考解（Python 文本）与参考动作列表；
  - `simulate(level, actions)` → `{ frames, result: 'win' | 'fail', reason, steps }`；`apply(state, action)` 单步结算；
  - 英雄 API（v1）：`move(direction)`（'up'/'down'/'left'/'right'，撞墙原地不动并记一步）、`attack()`（攻击前方）、
    `look()`（返回前方格子类型字符串）、`hero_hp()` 或只读变量（形式由 01 号定）；所有 API 调用都消耗步数，超过上限终止并判「步数用尽」。
- **执行流程**：编辑器文本 → 沙盒运行（复用 pyodide-sandbox 的运行时、超时中断与按键隔离）→ Worker 内模拟器即时结算、记录每个动作对应的源代码行号 →
  主线程拿到 `{ actions, lineNumbers, stdout, error }` → 用 `simulate` 重算并回放（Phaser 场景按帧动画）→ 判定。
  主线程重算而不是信任 Worker 的结果，保证判定只取决于动作列表。
- **场景**：新增「代码训练场」场景（复用现有地面/道具贴图与勇者动画，网格小房间），左侧游戏画面、右侧编辑器与输出区；
  回放控制：播放/暂停/单步/倍速；回放中编辑器高亮当前行。入口与是否计入进度由 01 号定（推荐：第一章村庄通关后出现一扇「训练场之门」，完全可选）。
- **编辑器**：沿用 pyodide-sandbox 的 v1 编辑器方案（原生 textarea + 等宽字体 + Tab 缩进 + 行号），不引入重型编辑器库。
- **成绩**：「行数」= 非空非注释行；「步数」= 动作数；每关个人最佳本地保存（存档字段随 learning-records 的 v3 schema 扩展约定；在 v3 落地前用独立设置键）。
- **提示分级**：概念提示 → 关键语句提示 → 参考解（看参考解后本关成绩标记「已看解答」）。
- **测试接缝**：只读 `codeRoom()`：当前关卡、最近一次运行的动作列表与判定、回放进度；语义动作 `openCodeRoom(levelId)`（E2E 直达）。

## 测试决策

- **好测试的标准**：断言玩家可见的结果（勇者最终位置、过关/失败原因、行数步数、报错信息、高亮行），不断言 Worker 内部实现。
- **数据层（smoke，不依赖 Pyodide）**：每关的参考动作列表经 `simulate` 必须判定过关；起始代码对应的「空动作」必须不过关；
  模拟器边界：撞墙、踩陷阱、步数上限、目标组合；关卡数据完整性（API 白名单、提示、参考解齐全）。
- **verify-quiz 式实跑（CPython）**：用本机 Python + 一个与 JS 模拟器等价的极简 Python 桩（只记录调用序列）运行每关参考解，
  比对产生的动作序列与关卡数据里的参考动作列表一致——保证「参考解」和「参考动作」不脱节（具体做法 04 号工单定）。
- **E2E**：`openCodeRoom` 直达第一关 → 用**真实键盘**在编辑器输入参考解（顺带验证 w/a/s/d 不被吞）→ 运行 → 等待回放结束 → 断言过关与成绩；
  再输入死循环代码 → 断言超时提示且游戏可继续；沙盒不可用时（pyodide-sandbox 的 `sandboxOffline()` 语义动作）断言说明文案。
- **先例**：pyodide-sandbox 的 `codeRune` E2E 步骤与降级测试；runner 的「浏览器无报错」断言；smoke 对地图数据的合法性校验。

## 待决策

1. **概念顺序与关卡清单**：推荐 8 关——①顺序执行 ②列表与索引（`path[0]`）③for + range ④if/elif/else（look 判断陷阱）⑤while（走到墙前）⑥break ⑦def 复用一段走法 ⑧遍历列表收集全部碎片；需助教对照讲义 W1–W2 的讲授顺序确认（01 号）。
2. **入口与进度**：推荐第一章通关后村庄出现「训练场之门」，完全可选、不计入章节进度；备选做成第二章野外的可选支线。
3. **英雄状态的暴露方式**：推荐函数 `hero_hp()` 而不是对象属性 `hero.hp`（W1–W2 还没讲类与属性，避免引入未讲概念）。
4. **成绩维度**：推荐同时显示行数与步数，个人最佳分别记录；不做排行榜。
5. **沙盒不可用时的降级**：推荐只提供「观看参考解回放」，不提供四选一替代（训练场本身就是可选内容）。

## 不做的事

- 不做排行榜、不做代码分享社区。
- 不支持 W3 以后的库（numpy 等）——训练场只覆盖 W1–W2 的纯 Python 概念。
- 不做积木式（Blockly）编辑器：课程目标是写真 Python。
- 不新增四选一题目（ADR-0001）；关卡说明只用课上术语。
