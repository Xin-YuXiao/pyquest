# 代码沙盒：在浏览器里真实运行 Python 判分

Status: needs-triage
Priority: P1
Source: upstream README 路线图「Pyodide 沙盒：W6-8 真实代码执行判分（跑 numpy/scipy 拟合 NFW）」
Depends on: 无（可选协同：learning-records 记录代码题作答；core-unit-tests 为判分比较逻辑提供单元测试层）

## 问题陈述

- 现在所有符文石都是「四选一 / 代码填空」：学生只需要**认出**正确答案，不需要**写出**能跑的代码。
  W6-W8 的核心能力恰恰是动手——用 `quad` 积分、用 `curve_fit` 拟合、把 NFW 密度积成质量——
  选择题测不出「会不会写」。
- 课程讲义里大量代码块有确定输出（verify-quiz 已经用本机 python 实跑了 56 道这样的题），
  这些素材天然适合变成「写代码、跑出正确结果」的任务，但游戏里没有执行环境。
- 学生手边不一定有配好 numpy/scipy 的 Python（机房、iPad、临时借的电脑），
  一个打开网页就能跑 Python 的环境本身就有教学价值。
- 维护者视角：答题面板写死了「渲染选项 → 选中 → 确认」一条路，任何新题型都无处安放；
  键盘也有暗坑——Phaser 在 window 层对 W/A/S/D/E/J/M 和方向键调用 preventDefault
  （已核实：键盘管理器对已登记捕获的按键一律拦截，不看事件目标），
  一旦面板里出现文本输入框，这些字母根本打不进去。

## 解决方案

新增一种题型「代码符文」：

1. 玩家打开代码符文，答题面板显示任务说明和一段起始代码（带待补全的位置），下方是可编辑的代码区。
2. 「运行」：代码在浏览器内的 Python 运行时（Pyodide，跑在 Web Worker 里，不卡游戏）执行，
   面板显示 stdout / 报错；运行不扣心，可以反复调试。
3. 「提交」：用隐藏测试判分。通过 → 和现在答对一样发奖励（碎片 / 回心 / 破盾）并显示解析；
   不通过 → 显示哪条测试没过（不泄露期望值的具体实现），按规则扣心。
4. 首次遇到代码符文时按需加载运行时，显示加载进度；加载失败、离线或设备太弱时，
   自动**降级为该题配套的四选一版本**，保证进度永远不会被运行时卡住。
5. 死循环 / 超时：超过时限自动中断并提示「运行超时」，游戏不受影响。

## 用户故事

1. 作为学生，我想在符文石前直接写 Python 代码并运行，以便在游戏里练习 W6-W8 真正需要的动手能力。
2. 作为学生，我想「运行」时看到自己代码的 stdout 和报错信息，以便像在 Jupyter 里一样调试。
3. 作为学生，我想反复运行而不被扣心，以便放心试错，只在正式「提交」时才承担后果。
4. 作为学生，我想提交失败时知道是哪条测试没过（例如「quad 的积分上限不对：结果应在 2/3 附近」），以便有方向地修改，而不是盲猜。
5. 作为学生，我想代码题通过后拿到和选择题一样的奖励（碎片 / 回心 / 破盾），以便代码符文自然融入章节流程。
6. 作为学生，我想在代码区正常输入 w、a、s、d、e、j、m、空格和方向键，以便写代码时不会被游戏快捷键吞掉按键或让角色乱跑。
7. 作为学生，我想在代码区里按 Enter 换行、按 Tab 缩进、按数字键输入数字，而不是触发「确认 / 选第 N 项」，以便编辑器行为符合直觉。
8. 作为学生，我想第一次加载运行时有清楚的进度提示和预计等待，以便知道游戏没有卡死。
9. 作为网络差的学生，我想运行时加载失败时自动切换为该题的四选一版本，以便不会因为网络卡在一块符文石前。
10. 作为学生，我想写出死循环时几秒内就被中断并看到「运行超时」，以便不需要刷新页面、不丢进度。
11. 作为学生，我想代码区预填起始代码、待补全处醒目标出，以便知道要改哪里，而不是对着空白发呆。
12. 作为学生，我想一键「重置代码」恢复起始代码，以便改乱之后能重来。
13. 作为学生，我想关闭面板再打开时，代码区还保留我上次写的代码（同一块符文石、答对之前），以便不用重写。
14. 作为学生，我想答对后看到解析和参考写法，以便对照自己的实现。
15. 作为第二次来的学生，我想运行时从浏览器缓存秒开，以便不必每次都等。
16. 作为用平板 / 手机的学生，我想在设备性能不足时直接走四选一版本，以便体验不被拖垮。
17. 作为教师，我想代码题的判分结果在任何学生的浏览器里都一致，以便判分公平、可复现。
18. 作为教师，我想代码题的期望结果来自讲义的确定输出（ADR-0001），以便游戏练的和课上讲的完全一致。
19. 作为维护者，我想每道代码题的参考解在 CI 里被真实执行、必须通过判分，而起始代码必须**不**通过，以便题目不会出现「无解」或「白给」。
20. 作为维护者，我想新增题型时只需要实现一个题型渲染器，而不用改答题面板的公共部分（标题、反馈、扣心、碎片入袋动画），以便题型可以持续扩展（对话式编程 UI 复用同一扩展点）。
21. 作为维护者，我想现有 251 道四选一 / 填空题在 prefactor 之后行为完全不变、全部 E2E 原样通过，以便重构零风险。
22. 作为维护者，我想运行时文件自托管、版本锁死，以便国内网络可达、E2E 可离线跑、结果不随 CDN 漂移。
23. 作为维护者，我想 CI 缓存运行时文件，以便流水线不必每次下载几十 MB。
24. 作为维护者，我想一个测试接缝能模拟「运行时不可用」，以便 E2E 稳定覆盖降级路径。
25. 作为不碰代码符文的玩家，我想游戏启动和其他章节的加载速度完全不受沙盒影响，以便沙盒只为需要它的人付出成本。

## 实现决策

- **题型分派（prefactor，固定为本 effort 01 号工单）**：答题面板拆成「公共外壳 + 题型渲染器」。
  公共外壳负责：章节标签、题干、反馈区、确认 / 取消按钮、扣心、答对后的「碎片入袋」兑付与关闭；
  题型渲染器负责：题面主体渲染、作答交互、判定「是否答对」，并通过统一回调把结果交给外壳。
  - 题目新增可选字段 `kind`，缺省为 `choice`（现有四选一与 `fill` 填空都归入 `choice`）。
  - 渲染器契约（极简形状）：`{ mount(q, ctx), unmount(), keyboardShortcuts: boolean }`，
    `ctx` 提供 `reportResult({ correct, detail })`、`setConfirmEnabled(bool)`、`setBusy(bool)`。
  - 键盘：现有的 1-4 选项 / Enter 确认快捷键只在 `keyboardShortcuts: true` 的题型生效。
  - 未知 `kind` 在数据层（smoke）直接失败，运行时兜底显示「此题暂不可用」且不扣心。
- **按键隔离**：代码区获得焦点时暂停 Phaser 的全局按键捕获（键盘管理器提供暂停 / 恢复捕获的能力），
  失焦或面板关闭时恢复；答题期间场景本就处于暂停状态，角色不会移动，问题只在 preventDefault 吞字。
- **代码题数据契约**（类型形状，`kind: 'code'` 的题在 choice 字段之外新增）：

  ```
  {
    kind: 'code',
    starter,            // 起始代码；待补全处用约定标记（与填空题的 ___ 一致）
    packages,           // 需预装的包，如 ['numpy', 'scipy']
    judge: { mode: 'stdout', expected } | { mode: 'asserts', tests },
    timeoutMs,          // 缺省 8000
    solution,           // 参考解：CI 实跑校验 + 答对后展示
    fallback: { code, options, answer },   // 四选一降级形态（同一知识点）
  }
  ```
  `asserts` 模式下 `tests` 是一段在玩家代码之后执行的 Python 断言，数值比较一律带容差，
  避免不同 numpy 版本的打印格式差异（numpy 1.x / 2.x 的标量 repr 不同，verify-quiz 已因此锁 numpy<2）。
- **运行时与 Worker 协议**：Pyodide 跑在专用 Web Worker；消息只有三类——
  `init { packages } → progress / ready / error`、
  `run { code, timeoutMs } → { stdout, stderr, error, durationMs }`、
  `judge { code, judge, timeoutMs } → { pass, failures[], stdout }`。
- **超时中断**：主线程计时，超时即 terminate Worker 并重建（预装包需重新加载，提示「正在重启 Python」）。
  不采用 SharedArrayBuffer 中断方案：它要求页面跨源隔离（COOP/COEP 响应头），
  静态托管（如 GitHub Pages）无法设置，且会影响字体等外链资源。
- **自托管运行时**：锁定一个 Pyodide 版本，构建前由脚本按清单下载核心文件与所需 wheel（带校验和），
  放进站点静态目录，**不提交进 git**（体积大）；开发 / 构建 / CI 用同一份清单。理由：
  1. E2E 运行器会把所有非 localhost 请求直接回空 200（已核实，用来隔离外网），走 CDN 的运行时在 E2E / CI 里必然加载失败；
  2. 默认 CDN（jsdelivr）在国内的可达性不稳定（需核实，见 02 号 prototype）；
  3. 版本锁死后判分结果可复现。
- **按需加载**：游戏启动不加载运行时；首次打开代码符文时加载。可选：进入含代码符文的章节野外后，在空闲时预取（07 号工单）。
- **降级**：`init` 失败 / 超时（建议 60s）/ 检测到低内存设备时，本题切换为 `fallback` 四选一，
  外壳顶部提示「Python 运行环境不可用，已切换为选择题」；降级不扣心、不改变奖励。
- **扣心规则**（待 03 号 grilling 确认）：运行不扣心；提交未通过扣 1 心（沿用「答题失误最多扣到 1，不会答死」）。
- **槽位与题池**（待 03 号 grilling 确认，推荐方案）：W6-W8 巢穴各新增 1 块「代码符文」，
  使用独立槽位与独立题池（如 `w6code`），tier 取该章 BOSS 档；v1 作为可选的祝福符文（答对回心），
  不阻塞 BOSS，避免运行时问题影响主线。
- **编辑器**：v1 用原生 textarea + 等宽字体 + Tab 缩进 + 行号；不引入重型编辑器库（体积与移动端兼容），
  需要语法高亮时复用现有的极简高亮做只读回显。
- **代码暂存**：同一槽位答对前，玩家写过的代码随存档保存（字段待 learning-records 的 v3 schema 决定；
  在 v3 落地前只保存在内存，关面板再开仍在，刷新后回到起始代码）。
- **术语**：GLOSSARY 需新增「题型（kind）」「代码符文」「判分（judge）」「降级（fallback）」。

## 测试决策

- 好测试的标准：只验证玩家能观察到的行为——能否在代码区打字、运行能否看到输出、提交能否拿到奖励、
  超时能否恢复、降级能否继续推进；不测 Worker 内部实现。
- **E2E（首选接缝）**：声明式 runner 新增步骤类型 `codeRune`：
  打开代码符文 → 用**真实键盘**在代码区输入参考解（顺带验证 w/a/s/d/e/j/m 不被吞）→ 运行 → 断言输出区出现期望文本
  → 提交 → 断言奖励到账；再走一条「错误代码提交 → 扣 1 心 → 显示未通过的测试」路径。先例：`healRunes` / `bossRune` 步骤与 `answerCorrect`。
- **测试接缝**：`__PYQUEST__` 新增语义动作 `sandboxOffline()`（让下一次运行时初始化失败），
  E2E 用它稳定覆盖降级路径；另提供只读查询 `sandbox.status()`（idle / loading / ready / failed）。
- **smoke（数据层）**：代码题字段完整性（starter / judge / solution / fallback 齐全、fallback.answer 下标合法、
  所属题池 tier 一致、未知 kind 报错）。
- **verify-quiz（实跑）**：扩展为对 `kind: 'code'` 的题，用本机 CPython 执行「solution + 判分」必须通过、
  「starter + 判分」必须失败。可选（03 号决策）：再用 Node 版 Pyodide 跑一遍，保证与浏览器同一运行时。
- **单元测试**（若 core-unit-tests 已落地）：stdout 归一化（换行 / 尾随空白）与浮点容差比较这类纯函数。
- **CI**：缓存运行时文件（按锁定版本做缓存键）；E2E 必须在不访问外网的前提下通过。

## 待决策

1. **代码符文是必经还是可选？** 推荐 v1 可选（巢穴祝福符文形态），观察加载失败率和通过率后再考虑升格为 BOSS 符文。
2. **提交失败扣心吗？** 推荐扣 1 心（与四选一一致，且运行免费已足够宽容）；备选：只在连续 3 次失败后扣。
3. **判分模式**：推荐默认 `asserts` + 数值容差（跨 numpy 版本稳定）；`stdout` 只用于纯文本输出题。
4. **Pyodide 版本**：推荐选择内置 numpy 与课程环境同为 1.x 的版本，与 verify-quiz 的 numpy<2 一致；
   若该版本过旧，则改用 numpy 2.x 并完全依赖 `asserts` 判分（需 02 号实测后定）。
5. **自托管还是 CDN？** 推荐自托管（E2E 离线 + 国内可达 + 版本锁定），CDN 只作可选的备用源。
6. **verify-quiz 是否加跑 Node 版 Pyodide？** 推荐加跑（CI 成本可接受时），彻底消除「CPython 能过、浏览器不过」。

## 不做的事

- 不接任何远程代码执行服务或后端（纯前端，离线可用）。
- 不做防作弊：参考解与判分本就打包在前端（与现有四选一答案一样），本游戏是自学工具。
- 不做多文件项目、文件上传、matplotlib 图像输出（v1 只判文本 / 数值）。
- 不改变现有四选一 / 填空题的任何行为与题面。
