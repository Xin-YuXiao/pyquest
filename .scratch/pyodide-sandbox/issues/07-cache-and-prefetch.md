# 07: 运行时长期缓存与空闲预取

Status: needs-info
Type: task
Blocked by: 05

## 要做什么

降低第二次及以后遇到代码符文的等待：

- 运行时文件使用带内容哈希的文件名 + 长期缓存策略，第二次打开秒级就绪（以 02 号报告的热启动数据为基线）。
- 玩家进入含代码符文的章节野外后，在空闲时（无答题、无战斗）后台预取运行时；预取失败静默，不影响后续按需加载。
- 评估是否需要 Service Worker 做离线缓存：若 HTTP 缓存已满足「第二次秒开」，则不引入 Service Worker（在 Comments 记录结论）。
- 低内存 / 省流量模式（浏览器提供 Save-Data 提示时）不预取。

## 验收标准

- [ ] 第二次打开代码符文的就绪时间相比冷启动显著下降，数据记录在 Comments
- [ ] E2E：进入 W6 野外并空闲后，沙盒状态变为 ready（经测试接缝只读查询）
- [ ] 不进入含代码符文的章节时不发生预取（E2E 断言首屏无运行时请求）
- [ ] Service Worker 是否引入有明确结论
- [ ] `npm run check` 全绿
