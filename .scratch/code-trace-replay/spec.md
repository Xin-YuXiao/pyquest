# 代码执行回放：答完题后「看它怎么跑」

Status: needs-triage
Priority: P1
Source: 接手评估新增 · 借鉴教学研究（见 .scratch/INSPIRATION.md）——PRIMM（预测-运行-调查-修改-创作）与 Python Tutor 式程序可视化，以及「notional machine」批评
Depends on: 无硬依赖（协同：quiz-bank-lint 的 verify-quiz 覆盖率回填扩大可回放题范围；mistake-review 的复习模式；learning-records 记录查看行为；bundle-performance 的按需加载）

## 问题陈述

- 现有四选一题的本质是 PRIMM 的第一步「预测」：读代码、猜输出。但游戏在学生答完之后就结束了——
  答错的人只看到一句提示，答对的人可能是蒙对的，**没有人看到代码到底是怎么一步步跑出这个结果的**。
  PRIMM 的第二、三步（运行、调查）缺失。
- 课堂上助教常用 Python Tutor 逐步演示，但学生在游戏里遇到的是另一段代码，需要自己复制出去，没人这么做。
- 研究提示的坑：只「展示执行」而不解释，新手看不懂可视化里的变量表、帧、引用（notional machine 批评；
  think-aloud 研究发现部分可视化元素会让新手困惑、工具也不解释它显示的术语）。
  所以不能只做一个动画，每一步都要配一句人话。
- 题库里已有 56 道被 verify-quiz 用本机 python 实跑校验的确定性题，代码对齐讲义（ADR-0001），
  正是理想的回放素材——**不需要任何新内容**。

## 解决方案

1. 学生答对一道「可回放题」后，解析区出现按钮「▶ 看它怎么跑」。
2. 点开后，题面代码块进入步进模式：当前执行行有 ▶ 标记和底色，下方出现紧凑的三栏：
   - **这一步**：一句中文说明（例如「for 循环第 2 轮：i = 1」「x 从 3 变为 4」「调用 add(2, 3)」「输出：5」）；
   - **变量**：当前可见变量的名字 / 值 / 类型（函数内部时分组显示「add 的局部变量」）；
   - **已输出**：到这一步为止的 stdout。
3. 控件：上一步 / 下一步 / 跳到开头 / 跳到结尾 / 自动播放；键盘 ←/→ 步进。
4. 「领取奖励」随时可点，回放不阻塞领取。
5. 轨迹在**构建期**用本机 python 预先算好（`sys.settrace` + `ast` 识别语句类型），游戏运行时只读数据，零依赖、离线可用。

## 用户故事

1. 作为答对但不太确定的学生，我想逐行看程序怎么跑出这个结果，以便确认自己不是蒙对的。
2. 作为学生，我想每一步都有一句中文说明在讲发生了什么，以便不需要先学会读可视化工具。
3. 作为学生，我想看到循环每一轮的循环变量值，以便理解 `range` 和循环次数。
4. 作为学生，我想看到变量从旧值变成新值的瞬间，以便理解赋值和 `+=`。
5. 作为学生，我想看到 `if` 条件为假时哪些行被跳过了，以便理解分支。
6. 作为学生，我想看到函数被调用、参数传进去、返回值带出来，以便理解 `return` 和局部作用域。
7. 作为学生，我想看到 `print` 在哪一步输出了什么，以便把输出和代码行对应起来。
8. 作为学生，我想看到程序抛出异常的那一步（例如 `math.sin` 遇到数组报 TypeError），以便理解错误发生在哪里。
9. 作为学生，我想能前进也能后退，以便反复看我没想明白的那一步。
10. 作为学生，我想用键盘 ←/→ 步进，以便不离开键盘。
11. 作为开启「减少动态效果」的学生，我想自动播放默认关闭、步进没有过渡动画，以便舒适地使用。
12. 作为学生，我想变量表里的列表 / 数组显示得简短可读（太长时截断并说明），以便面板不被撑爆。
13. 作为学生，我想回放不影响领取奖励，以便想看就看、不想看就走。
14. 作为在错题本里复习的学生，我想复习时答完也能看回放，以便把错题彻底弄懂。
15. 作为助教，我想课上可以直接在游戏里演示某道题的执行过程，以便不必切到 Python Tutor。
16. 作为助教，我想知道哪些学生点开过回放，以便了解自主探究的情况（经作答记录）。
17. 作为教师，我想回放的每一步都由真实 Python 执行得出，以便演示的内容与课堂环境一致。
18. 作为内容作者，我想只要题目进了 verify-quiz 的确定性题清单，就自动获得回放，以便不手写任何轨迹。
19. 作为内容作者，我想生成器告诉我哪些题因为太长 / 依赖不支持的库而没有回放，以便取舍。
20. 作为维护者，我想轨迹数据按需加载、不进首屏包，以便不拖慢游戏启动。
21. 作为维护者，我想 CI 检查「重新生成的轨迹与入库数据一致」，以便题目代码改了轨迹不会过期。
22. 作为维护者，我想回放与 verify-quiz 共用同一份「确定性题目」清单，以便两边不会各自漂移。
23. 作为 E2E 维护者，我想接缝能读到回放的当前步号和总步数，以便测试真实的步进交互。
24. 作为维护者，我想所有回放数据的总体积有预算并在 CI 报告，以便题目增长时可控。

## 实现决策

- **素材范围**：回放只对「确定性题目清单」里的题启用——即 verify-quiz 实跑校验过的题（现 56 道，
  随 quiz-bank-lint 05 号回填增长）。prefactor：把 verify-quiz 里的「题 id → 期望输出」表移到一个独立的数据模块，
  verify-quiz 与轨迹生成器都从这里读（与 quiz-bank-lint 03/04 号对 verify-quiz 的改造协调，谁先落地谁做这个搬家）。
- **可回放条件**：只依赖标准库或 numpy（scipy / astropy / sklearn 题本身不追踪库内部，但变量里常是大对象，v1 排除）；
  步数 ≤ 上限（建议 80 步，超出则截断并在最后一步说明「后面还有 N 步，结构相同」）；无随机数。
- **轨迹生成器（构建期）**：一个脚本调用本机 python（与 verify-quiz 相同的探测与 UTF-8 设置），在单个进程内对每道题：
  `compile` → 用 `sys.settrace` 只追踪题目代码自身的帧（文件名为题目代码的帧，不进库内部）→
  记录每个 line / call / return / exception 事件：行号、各帧可见变量的短 repr（过滤模块、内置函数、以下划线开头的名字）、
  stdout 增量。用 `ast` 给每行打语句类型（赋值 / for / while / if / def / return / 表达式-print），据此生成中文说明。
  输出一个入库的数据文件 + 体积 / 截断报告。CI 运行生成器并要求无差异（与 parsons-runes 的生成器同一模式，可共用 python 调用工具）。
- **说明标签模板（由事件 + 语句类型 + 变量差分自动生成，无需人工撰写）**：
  新建变量「新建变量 x = 3」；变量变化「x：3 → 4」；可变对象原地变化「列表 nums 原地变化：[1, 2] → [1, 2, 3]」；
  for 新一轮「for 循环第 k 轮：i = 2」；循环结束「循环结束，继续执行第 N 行」；
  if 真 / 假「条件成立，进入 if 代码块」/「条件不成立，跳过 if 代码块」；
  调用「调用 add(a=2, b=3)」；返回「add 返回 5」；输出「输出：5」；异常「抛出 TypeError：……」。
  模板表放数据层，便于后续人工润色（润色属于界面文案，不是题面内容）。
- **数据形状**（极简）：
  ```
  { qid, steps: [{ line, label, frames: [{ name, vars: [[名字, 短repr, 类型]] }], out }], truncated }
  ```
  `out` 为累计输出；短 repr 超过 60 字符截断加「…」。
- **呈现**：复用题面代码块原地步进（需要 prefactor：代码块按行渲染，每行可单独加当前行标记；语法高亮逐行进行），
  不额外弹窗，避免答题面板变高（runner 注释已记录最高题面板接近 805px 的问题）。三栏信息区放在代码块下方、解析之上，
  默认折叠，点按钮展开。
- **触发时机**（推荐）：只在答对后（以及错题本复习中作答后）出现；答错时不出现，避免直接泄露答案。
- **按需加载**：轨迹数据作为独立模块动态加载，点「看它怎么跑」时才请求；首屏包体积不变。
- **键盘**：←/→ 步进、Home/End 首尾；方向键已被 Phaser 登记捕获（window 层 preventDefault），
  但回放不需要浏览器默认行为，答题面板的 document 监听器仍能收到；与答题面板现有 1-4 / Enter 快捷键不冲突。
- **可访问性**：当前步说明放入 aria-live 区域；当前行标记用 ▶ 符号 + 底色（不只靠颜色）；自动播放在「减少动态效果」下默认关闭。
- **接缝**：`__PYQUEST__` 只读查询 `trace()` 返回 { open, step, total, qid }。
- **术语**：GLOSSARY 新增「执行回放」「确定性题目清单」。

## 测试决策

- 好测试只看学生可见结果：按钮是否只在该出现时出现、步进时行标记 / 说明 / 变量表 / 输出是否对应、领取奖励不受影响。
- **E2E（首选）**：新增独立脚本或 runner 步骤：在第二章答对一道可回放题（用 gotoChapter + 接缝读答案的现有模式，
  或用接缝语义动作把指定题绑定到符文槽——若需要，新增语义动作 `rollRune(slot, qid)`）→ 点「看它怎么跑」→
  按 → 若干次 → 断言接缝 `trace().step` 递增、页面当前行标记位于期望行、说明文字包含期望关键词（如「for 循环第 2 轮」）→
  ← 回退一步断言回到上一状态 → 领取奖励正常。答错路径断言按钮不出现。
- **生成器自检（CI）**：每条轨迹的最终累计输出 == verify-quiz 期望输出（交叉校验，轨迹与判分同源）；
  步数 ≤ 上限或标记 truncated；重新生成无差异；总体积报告并设预算（建议入库数据 ≤ 300 KB）。
- **smoke**：数据文件里每个 qid 都在确定性清单中、每步行号落在代码行范围内。
- **单元测试**（若 core-unit-tests 已落地）：「按行渲染 + 当前行标记」的纯函数。

## 待决策

1. **答错后能否回放？** 推荐只在答对后（及复习作答后），避免泄题；备选：答错 2 次后开放回放作为「强提示」。
2. **numpy 题是否纳入 v1？** 推荐纳入（W3 是 numpy 章，数组变化最需要看），数组 repr 截断显示。
3. **自动播放默认值**：推荐默认关闭（手动步进更符合「调查」）。
4. **PRIMM 的「修改」环节**（学生改一处代码再预测）：需要浏览器 Python，推荐留给 pyodide-sandbox 落地后再立项。

## 不做的事

- 不在浏览器里运行 Python；不支持学生改代码后重新追踪。
- 不追踪库内部（numpy / scipy 内部帧一律不显示）。
- 不做图形化的对象引用箭头图（Python Tutor 式堆栈图）——v1 用表格 + 文字说明，降低新手认知负担。
- 不改任何题目题面。
