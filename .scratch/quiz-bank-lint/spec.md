# 题库静态校验与覆盖率

Status: needs-triage
Priority: P0
Source: 接手评估新增。第二部落地时人工复核发现 4 处讲解不一致（见 `.scratch/part2-landing/issues/01`）；本 effort 起草时又实测出答案位置严重偏置、一个章节标签缺提示语、70 道可执行题未进 verify-quiz 校验表
Depends on: 无

## 问题陈述

题库现有 251 题、34 个题池，全部由对话式协作生成，今后还会继续扩充（W4-W8 计划扩到每章 40-60 题）。现有防线：

- **smoke** 检查结构完整、answer 下标不越界、有讲解、有 tier、填空题有占位、池内 tier 一致、符文槽映射有效、抽题行为。
- **verify-quiz** 用 python 实跑 56 道题，把输出和手写的期望值比对。

这两道防线之外，有几类问题目前没人能自动发现。以下数字都是本次起草时实测的：

1. **答案位置严重偏置**：251 题里正确答案在第 1 个选项的有 175 题（70%），第 2 个 43 题、第 3 个 23 题、第 4 个只有 10 题。答题面板按原顺序显示选项、不打乱，学生「无脑选 1」就能拿到七成碎片，测验失去区分度。另外有 133 题（53%）的正确选项恰好是唯一最长的那个，也是可利用的线索。
2. **跨章引用写错**：讲解里常写「W8 考过 percentile 怎么调用」「W9 的 pcov/percentile 正是这一环的工具」，但被引用的那一章根本没有这样的题（人工复核已发现 st17、pj4 两处）。
3. **数值口径前后矛盾**：同一门课里，st9 写「3σ 对应 p = 0.001」，st21 写「3σ（p≈0.0013）」；st19 用 Neff ≈ N/(2τ)，与 W8 dm20 及 emcee 的 τ 定义（Neff ≈ N/τ）矛盾。
4. **界面配套缺失**：章节标签「第一章 · 运算符」在答题面板的提示语表里没有对应条目，学生答错时只能看到通用的「仔细读题，逐行理解代码」。
5. **自动校验覆盖率不透明**：有 126 道「无填空且代码里有 print」的候选可执行题，只有 56 道进了 verify-quiz 校验表，其余 70 道（主要在 W1-W3）没有验证，也没人知道还差多少。
6. **答案键没有交叉核对**：verify-quiz 只比对「python 实际输出 = 手写的期望值」，从不检查这个期望值是不是正确选项。如果期望值和答案下标同时写错，或者只是答案下标指错了选项，它照样通过。

ADR-0001 规定题面内容以讲义为准、不得擅改，所以发现问题之后不能让 agent 顺手改题面，必须登记下来交给人确认。这就要求工具既能把问题暴露出来，又不会让 CI 永远红着。

## 解决方案

新增一道「题库 lint」防线，接入 `npm test` 与 CI：

- **结构类规则**（与 smoke 互补、不重复）：选项恰好 4 个且互不相同、章节标签都有提示语、题目所在题池与章节标签的章号一致、每题恰好属于一个题池、BOSS 标记与 BOSS 池一致、题干不重复等。
- **内容一致性规则**：跨章引用核对（被引用章节真的考过该考点）、σ↔p 值换算核对、口径对照表（已知易错公式的规范写法）。
- **已知问题清单**：已登记、等待人工确认的内容问题，按「规则 + 题号 + 指向 .scratch 工单的链接」列入豁免，CI 保持绿色。新出现的问题会让 CI 失败；题面修好之后，豁免条目必须删除，否则也报「过期豁免」失败。
- **verify-quiz 增强**：期望输出必须能在正确选项里找到、且不能在错误选项里找到（答案键核对）；输出覆盖率报告，覆盖率只能升不能降。
- **答案位置偏置**：lint 报告每个题池的答案位置分布。处置方案（推荐：答题面板按符文槽固定种子打乱选项显示顺序，不改题面）由维护者拍板后实施。

## 用户故事

1. 作为学生，我想要正确答案不总在第一个，以便碎片真正反映我是否懂了。
2. 作为学生，我想要同一块符文石重开时选项顺序不变，以便我刚才看过的选项不会换位置把我搞糊涂。
3. 作为学生，我想要讲解里说「第 N 章考过」时那一章真的考过，以便我回去复习能找到对应的题。
4. 作为学生，我想要同一个统计量（如 3σ 的 p 值）在全课程里只有一种说法，以便不被前后矛盾的数字困扰。
5. 作为在「运算符」类题目答错的学生，我想要看到针对运算符的提示，以便知道错在哪里。
6. 作为内容作者，我想要提交新题后马上知道结构问题（选项重复、答案越界、标签无提示语），以便在评审前就改掉低级错误。
7. 作为内容作者，我想要写错跨章引用时被自动指出，并告诉我被引用章节实际考了什么，以便快速改对。
8. 作为内容作者，我想要知道我写的可执行题有没有进自动校验表，以便不漏掉验证。
9. 作为内容作者，我想要 verify-quiz 告诉我「python 输出和正确选项对不上」，以便发现答案下标指错这类隐蔽错误。
10. 作为课程负责人，我想要所有被发现但未处理的内容问题都有登记、有链接，以便按 ADR-0001 逐条确认，而不是被 agent 擅自改掉。
11. 作为课程负责人，我想要题面修好之后对应豁免必须删除，以便豁免清单不会越积越多、变成摆设。
12. 作为维护者，我想要 lint 在 `npm test` 里运行、在 CI 里把关，以便不用记得手动跑。
13. 作为维护者，我想要 lint 的输出按规则分组、给出题号和原文片段，以便一眼定位问题。
14. 作为维护者，我想要区分「错误」（阻断 CI）和「提示」（只报告），以便答案位置分布这类统计信息不会误伤 CI。
15. 作为维护者，我想要 lint 和 smoke 分工清楚、不重复检查，以便某类问题只在一个地方报错。
16. 作为维护者，我想要 verify-quiz 覆盖率有下限且只升不降，以便新增可执行题时不会忘记加校验。
17. 作为维护者，我想要每道「不可执行」的题都写明原因（概念题、依赖随机数、依赖外部文件等），以便覆盖率报告可信。
18. 作为评审 PR 的维护者，我想要 lint 失败信息直接指向违反的规则说明，以便不用读 lint 源码就能理解。
19. 作为扩充 W4-W8 题量的内容作者，我想要新题自动受同一套规则约束，以便规模扩大时质量不下滑。
20. 作为维护者，我想要口径对照表是数据驱动的，以便人工复核每发现一类易错公式，就加一条规则防止复发。
21. 作为 E2E 维护者，我想要选项打乱后测试仍能找到正确选项，以便打乱显示顺序不让测试变脆。
22. 作为维护者，我想要答案位置分布按题池报告，以便以后扩题时有意识地平衡。

## 实现决策

- **形态**：一个独立的「题库 lint」脚本，与 smoke 同级，只依赖数据层（题库、章节注册表）和答题面板的提示语表，不依赖浏览器。`npm test` 依次运行 smoke → 题库 lint → verify-quiz。
- **提示语表要可被导入**：答题面板目前把「章节标签 → 提示语」映射写在私有方法里。先做 prefactor：把这张表提升为数据层导出的常量，答题面板改为读取它，行为不变。这样 lint 才能核对标签是否齐全。
- **与 smoke 的分工**：smoke 已有的结构完整、answer 越界、讲解存在、tier 存在、填空占位、池内 tier 一致、符文槽映射、抽题行为检查保持原样，不搬家。lint 只做 smoke 没有的规则。
- **结构类规则**（全部为错误级）：
  - 选项恰好 4 个（答题面板键盘只支持 1-4）且两两不同（比较前去掉首尾空白）
  - 每个章节标签在提示语表里有条目
  - 题目的章节标签章号与它所在题池的章号一致（池名前缀 w{N} 对应第 N 章；W1-W3 的旧池名按注册表映射）
  - 每题恰好属于一个题池（无孤儿题、无一题多池）
  - BOSS 池里的题都有 BOSS 标记，非 BOSS 池的题都没有
  - 题干（prompt）在全库内不重复
  - 选项文本不含「以上都对 / 以上皆非」等依赖位置的表述（为选项打乱做前提保证）
- **内容一致性规则**（错误级，可被已知问题清单豁免）：
  - **跨章引用**：在讲解与题干里匹配「W{N} 考过 X」「W{N} 的 X」「第 N 章考过 X」以及「(W{N} <题号> 考 …)」这类句式。抽出被引用的章号和考点词 X（API 名、符号或术语），检查该章题池里至少有一道题在题干、代码或选项中出现 X（只出现在讲解里不算考过）。显式写了题号的，检查题号存在且属于该章。
  - **σ↔p 值换算**：匹配「kσ ... p = x」或「kσ（p≈x）」，与正态分布单侧尾概率、双侧尾概率对照（k=1..6 的值内置为常量表）。与两者的相对偏差都超过 15% 时报错。
  - **口径对照表**：数据驱动的规则表，每条包含「规范写法、禁用变体（正则）、依据、首次发现的工单」。首条：有效样本量 Neff≈N/τ（emcee τ 定义），禁用「N/(2τ)」。
- **已知问题清单**：一份数据文件，每条为 { 规则, 题号, 工单链接, 说明 }。lint 命中清单内条目时降级为提示，并在报告里单列；清单里的条目如果不再命中，就报「过期豁免，请删除」（错误级）。首批条目对应 part2-landing/issues/01 的 st17、pj4、st9、st19。
- **提示级报告**（不阻断）：每个题池的答案位置分布；「正确选项是唯一最长选项」的比例；每章题量与 tier 一览。
- **verify-quiz 增强**：
  - **答案键核对**：期望输出规范化（合并空白、统一换行）后，必须作为完整词元出现在正确选项文本里，且不能出现在任何错误选项里。无法满足的题（例如正确选项是解释性文字、不含输出）进入一张「答案键核对豁免」表，并写明原因。
  - **覆盖率报告**：把每道题归为三类之一：已校验（在校验表中）、可执行未校验、不可执行（附原因：概念题 / 填空题 / 依赖随机数 / 依赖外部文件或网络 / 依赖未安装的包）。按章打印统计。设一个覆盖率下限（等于当前值），CI 低于下限即失败；补题后由人手动上调。
- **选项打乱（等拍板后实施）**：答题面板按「符文槽 id + 题目 id」生成固定种子的排列来显示选项，同一块符文石答对前每次打开顺序相同，不需要改存档。正确与否按原始下标判断。键盘 1-4 对应显示顺序。测试接缝暴露「当前题目正确答案所在的显示位置」，E2E runner 改为读取它，而不是直接读题目的 answer 下标。

## 测试决策

- 好测试：给 lint 喂真实题库，断言它报出（或不报出）特定问题；不测规则的内部实现。
- **lint 规则的正确性**：每条规则配一个「它确实能抓到」的证据。现成的证据就是已知问题清单：清单条目必须被命中（否则报过期豁免），这本身就是对规则的回归测试。新增规则时，在 Comments 里贴一次「临时注入错误 → lint 失败」的验证记录。
- **若单元测试层已落地**（见 `../core-unit-tests/issues/01`），规则函数可以用小型手写题目夹具做单元测试；不强制依赖，lint 脚本本身先作为 npm test 的一步上线。
- **选项打乱**：E2E 全部 11 章照常通过（runner 改读接缝），并新增断言「同一符文石关闭后重开，选项顺序不变」；在 smoke 层统计：全部符文槽的正确答案显示位置分布接近均匀（每个位置占比都在 15%-35% 之间）。
- **先例**：smoke 的 fail/ok 输出风格与退出码约定；verify-quiz 的 CASES 表结构。

## 待决策

1. **答案位置偏置怎么处置**：推荐运行时按固定种子打乱显示顺序。题面一字不改，符合 ADR-0001，而且一次性解决全部 251 题。备选方案是人工逐题调整选项顺序：这算改题面数据，工作量大，以后新题还会再次偏置。
2. **「正确选项最长」线索怎么处理**：推荐只报告、不自动处理。根治需要改写选项文字，属于内容修改，应在 W4-W8 扩题和内容评审时由作者逐步平衡。
3. **σ↔p 规则的容差**：推荐 15%。讲解里常见「≈0.001」这类一位有效数字的写法，容差太小会误报。但 st9 的 0.001 与单侧 0.00135 相差 26%，仍应报出（需由维护者确认这确实算错误，而不是可接受的近似）。
4. **覆盖率下限是全库统一一个数字，还是按章设定**：推荐全库统一，按章只报告。按章设下限会在扩题过程中频繁卡住。

## 不做的事

- 不修改任何题面、选项、答案或讲解（只登记）；唯一的例外是补上「第一章 · 运算符」的提示语，这是界面文案，不是题面。
- 不做语义正确性判断（例如物理公式本身对不对），只做可机检的一致性检查。
- 不引入外部 JSON Schema 库；规则用普通代码表达即可。
- 不改动 smoke 已有的检查。
