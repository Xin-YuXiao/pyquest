# 第十章对话式编程 UI：在模拟的 AI 对话里练「验证」

Status: needs-triage
Priority: P2
Source: docs/part2-plan.md（第十章「对话式编程 UI（模拟 prompt-迭代-验证）列入路线图后续升级」）+ docs/quiz-outline-w10.md 待决策第 2 条；README 路线图「第十章对话式编程 UI」
Depends on: pyodide-sandbox（硬依赖其 01 号题型分派扩展点；可选复用其沙盒真跑测试）

## 问题陈述

- 第十章「灵思之塔」要教的是一套**流程**：需求描述 → prompt 分解 → 迭代生成 → 集成验证，
  成体系考点是正确性验证（小步迭代 / 测试先行 / 边缘情况 / 回归检查）。
- 现在 20 道题都是四选一：学生能**认出**「先写测试再让 AI 实现」是对的，但从没**做过**一轮：
  自己挑 prompt、读 AI 给的代码、发现里面的幻觉、选测试去戳它、决定接受 / 打回 / 回退。
  识别正确流程 ≠ 能在真实对话里执行流程。
- vibe coding 最危险的时刻是「AI 给了一段看起来很对的代码」——四选一题面把错误直接摆出来让你挑，
  而真实场景里错误是藏着的，需要学生主动去验证。

## 解决方案

新增一种题型「对话符文」：

1. 打开后是一个仿聊天的面板：上方写明任务目标（例如「写一个归一化的高斯函数」），下方是与「AI 助手」的对话记录。
2. 每一轮玩家从几个选项里做选择：改写 prompt、选一个测试用例去跑、或对 AI 的代码下结论（接受 / 打回 / 回退到上一版）。
3. 「AI」的回复是**预先写好的脚本**：有的回复藏着题目要教的幻觉（漏归一化系数、角度当弧度、bin 边界 off-by-one……）；
   玩家选的测试会给出脚本化的运行结果（沙盒可用时可以真跑）。
4. 面板顶部有四步流程进度条（需求 / 分解 / 生成 / 验证），玩家始终知道自己在流程的哪一步。
5. 走到「验证通过」终点 = 答对，发奖励并显示解析；走到「接受了有 bug 的代码」等失败终点 = 答错，
   显示这条路错在哪、扣 1 心，可以从头再来。

为什么不接真实大模型：判分要确定（同一选择必须得到同一结果，E2E 才能测）；要保证题目想教的那个幻觉一定出现；
纯前端、离线可用、没有 API key / 费用 / 隐私问题；本章要训练的是**验证流程**，不是和某个模型聊天。

## 用户故事

1. 作为学生，我想在一个像真实 AI 助手的对话界面里完成一个小任务，以便把第十章的流程放到接近真实的场景里练习。
2. 作为学生，我想每轮从几个 prompt 改写里挑一个，以便体会「具体的 prompt」和「模糊的 prompt」带来的不同结果。
3. 作为学生，我想 AI 有时给出「看起来对但其实错」的代码，以便练习不轻信。
4. 作为学生，我想选择一个测试用例去跑 AI 的代码并看到结果，以便亲手用测试戳破幻觉。
5. 作为学生，我想在拿到 AI 的代码后决定接受、打回还是回退，以便练习「对结果负责」的判断。
6. 作为学生，我想顶部的四步进度条告诉我现在处在需求 / 分解 / 生成 / 验证哪一步，以便把具体操作和流程对应起来。
7. 作为学生，我想选错路时看到「这条路错在哪」的解释，以便从失败中学到东西，而不只是扣心。
8. 作为学生，我想失败后能从头再走一遍，以便尝试其他路径。
9. 作为学生，我想走到验证通过的终点时看到完整的回顾（我走过的每一步 + 解析），以便复盘整个流程。
10. 作为学生，我想用数字键选择对话选项，以便和四选一题一样快捷操作。
11. 作为学生，我想对话里的代码有等宽字体和语法高亮，以便读得清楚。
12. 作为学生，我想对话推进时有适度的「打字中」节奏但可以一键跳过，以便既有临场感又不拖沓。
13. 作为开启了「减少动态效果」的学生，我想对话直接整段出现，以便不被动画打扰。
14. 作为使用读屏的学生，我想新消息被播报，以便能跟上对话。
15. 作为学生，我想中途关掉对话再打开时从头开始（且没有惩罚），以便规则简单清楚。
16. 作为学生，我想原有的第十章四选一题保留，以便对话符文只是新增的练习方式，不是替换。
17. 作为教师，我想每条对话都对应 W10 提纲里的一个成体系考点（小步迭代 / 测试先行 / 边缘情况 / 回归检查），以便知道它在教什么。
18. 作为教师，我想对话里「AI 的错误代码」的错误输出是真实可复现的（例如漏系数的高斯在峰值给 1.0 而不是 0.1995），以便内容经得起学生自己去验证。
19. 作为维护者，我想对话脚本是纯数据（节点 + 选项 + 终点），以便不改代码就能新增对话。
20. 作为维护者，我想 smoke 自动检查每条对话：所有跳转都指向存在的节点、从起点一定能走到「通过」终点、没有走不出去的死循环、没有孤立节点，以便脚本写错能在 CI 里被抓住。
21. 作为维护者，我想对话里声称的代码输出被 verify-quiz 用真 Python 跑一遍，以便「AI 的 bug」不是我们自己编错的。
22. 作为维护者，我想 E2E 能声明一条「通过路径」和一条「失败路径」去自动走对话，以便回归测试覆盖新题型。
23. 作为维护者，我想沙盒可用时「跑测试」可以真跑、不可用时回落到脚本结果，以便两套能力解耦。

## 实现决策

- **题型**：在 pyodide-sandbox 01 号工单的题型扩展点上注册 `kind: 'dialogue'` 渲染器；
  公共外壳（章节标签、反馈、扣心、答对兑付）完全复用。渲染器声明启用数字键选择（Enter 不用于确认）。
- **对话脚本数据契约**（状态机形状）：

  ```
  {
    kind: 'dialogue', chapter, tier, title, goal,
    start: 'n1',
    nodes: {
      n1: { step: '需求'|'分解'|'生成'|'验证',
            ai?: { text, code? },              // 本节点「AI」说的话 / 给的代码
            ask, choices: [{ label, to, run? }] }, // run: 选「跑测试」时展示的结果
      pass: { terminal: 'pass', explain },
      failX: { terminal: 'fail', explain },     // 每个失败终点都要讲清错在哪
    },
  }
  ```
  `run` 为 `{ code, output }`：`output` 是脚本化结果；若沙盒可用且 03 号 grilling 选择真跑，则实际执行 `code` 并展示真实输出。
- **判定**：只看到达的终点类型；`pass` = 答对（走外壳答对兑付），`fail` = 答错（外壳扣 1 心、显示该终点的 explain，提供「重新开始」）。
  中途关闭不扣心、不记进度。
- **流程进度条**：根据当前节点的 `step` 高亮四步之一。
- **呈现节奏**：AI 消息逐条出现，可点击 / 按键跳过；`prefers-reduced-motion` 时整段直接出现。
  对话记录区使用礼貌级别的读屏播报（aria-live）。
- **槽位与题池**（待 01 号 grilling 确认，推荐方案）：W10 巢穴新增 1 块「对话符文」，独立槽位与独立题池（如 `w10dialog`），
  tier 取 W10 BOSS 档（31）；v1 作为可选的祝福符文，原有 20 道四选一不动。
- **为什么不接 LLM**：确定性（可判分、可 E2E）、内容可控（幻觉必然出现）、离线 / 无费用 / 无隐私风险；记录在备注供后续复议。
- **术语**：GLOSSARY 需新增「对话符文」「对话脚本（节点 / 选项 / 终点）」。

## 测试决策

- 好测试的标准：只验证玩家可见结果——走通过路径能拿到奖励、走失败路径会扣心并显示原因、重新开始后状态复位；不测渲染细节。
- **E2E（首选接缝）**：runner 新增步骤类型 `dialogueRune`，参数是一条路径（每轮选第几个选项）和期望终点（pass / fail）；
  W10 章节脚本声明一条通过路径和一条失败路径。先例：`bossRune` / `healRunes` 步骤与 `answerCorrect`。
  测试接缝 `__PYQUEST__` 增加只读查询「当前对话节点 id」，避免 E2E 依赖 DOM 文本。
- **smoke（数据层图校验）**：每条对话——所有 `to` 指向存在的节点；从 `start` 可达至少一个 `pass`；
  每个非终点节点都能到达某个终点（无死循环陷阱）；没有从 `start` 不可达的孤立节点；每个终点都有 explain；选项数 2-4。
  附反例自测（临时注入坏脚本时 smoke 失败）。
- **verify-quiz**：对话中所有声明了 `run.output` 的代码，用本机 python 实跑比对（与现有 CASES 同一机制），
  保证「AI 的错误输出」真实可复现。
- 不新增单元测试层：图校验放在 smoke，渲染与交互由 E2E 覆盖。

## 待决策

1. **对话符文放哪？** 推荐 v1：W10 巢穴新增可选的祝福符文；备选：作为 W10 BOSS 符文（主题最贴「幻言魔像」，但会让主线依赖新题型，等 v1 稳定后再议）。
2. **失败扣心？** 推荐只在到达失败终点时扣 1 心，中途选择不扣（每轮都扣会把探索变成惩罚）。
3. **「跑测试」要不要真跑？** 推荐 v1 全部脚本化（不依赖沙盒），沙盒稳定后再开真跑（05 号工单）。
4. **首批几条对话？** 推荐 3 条，各覆盖一个成体系考点：测试先行（mag2flux 零点锚点）、边缘情况（linspace bin off-by-one 或除零 inf）、回归检查（v2 让旧测试变红后的处置）；再加 1 条入门的「高斯漏归一化」作为样板。
5. **内容审核**：W10 是零素材起草（docs/quiz-outline-w10.md 待决策第 3 条），对话脚本同样需要课程方过目——推荐沿用 W10 提纲的审核流程。

## 不做的事

- 不接入任何真实大模型 / 远程 API。
- 不做玩家自由输入 prompt（无法确定性判分）。
- 不替换或删除第十章现有 20 道四选一题。
- 不做对话进度的存档（中途关闭即从头开始）。
