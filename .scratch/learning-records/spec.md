# 作答记录与存档 v3

Status: needs-triage
Priority: P1
Source: 接手评估新增——答题面板只在答对时留下痕迹（槽位破解、题目记为已用），
答错只扣 1 心、不留任何记录；错题本、学习报告、存档迁移都缺这块地基
Depends on: core-unit-tests（迁移逻辑需要单元测试层）

## 问题陈述

PyQuest 是一门 64 学时课程的配套教学游戏，但游戏本身不知道学生「学得怎么样」：

- 学生在符文石上答错一道题，只会扣 1 颗心；换一个选项答对后，这道题就和一次答对的题没有区别。
  哪些题曾经卡住过、卡了几次、想了多久，全部丢失。
- 存档（v2）只记录「结果」：各章碎片数、封印门/BOSS 状态、已破解的符文槽、已答对的题目、
  符文石抽到的题。没有任何「过程」数据，也没有章节的时间点（何时进入、何时通关）。
- 胜利画面的「冒险用时」是「当前时间 − 首次开始时间」。读档续玩时首次开始时间原样恢复，
  所以隔了几天再通关，用时会把关掉游戏的几天也算进去，数字失真。
- 想做错题本、学习报告、存档导出时，都会发现没有可用的数据，只能各自另起炉灶，
  存档结构会被改得支离破碎。

## 解决方案

在存档里加一层「学习记录」，并把存档升级到 v3：

- 每次在答题面板上作答（选定选项并确认）都记一条记录：哪道题、哪个符文槽、什么类型的符文、
  选了第几项、对还是错、想了多久、这是这道题的第几次尝试、什么时候答的。
  打开答题面板后没作答就关掉，也记一条「放弃」。
- 每道题维护一份永不裁剪的汇总（作答几次、错几次、首答对错、最近一次时间），
  原始记录用固定上限的环形日志保存，超限只丢最老的原始记录，不丢汇总、绝不丢游戏进度。
- 每章记下进入野外、打开封印门、通关的时间点，并单独累计「有效游玩时长」
  （页面在前台时才计时），胜利画面的用时改用它。
- v2 存档（以及 v1 → v2 的老存档）读档时自动迁移到 v3，进度一点不丢；
  迁移前的进度原样保留，学习记录从空开始，章节时间点标为未知。
- 记录只保存在本机浏览器，不上传任何地方。

玩家在游戏里看不到这一层的直接变化（除了用时更准确）；它是错题本、学习报告、存档导出的地基。

## 用户故事

1. 作为学生，我想要游戏记住我每一道题的作答过程，以便之后回头复习曾经答错的题。
2. 作为学生，我想要老存档升级后进度完全不变，以便更新游戏后不用重玩。
3. 作为学生，我想要还在用 v1 老存档时也能一路迁移到最新版本，以便很久没玩也能接着玩。
4. 作为学生，我想要胜利画面的「冒险用时」只计算我真正在玩的时间，以便这个数字有意义。
5. 作为学生，我想要切到别的窗口查资料时答题计时暂停，以便用时不被离开的时间污染。
6. 作为学生，我想要打开题目后点「取消」也被记成「放弃」而不是答错，以便记录如实反映我的行为。
7. 作为学生，我想要同一道题在同一次打开面板内连错两次时，记录里能看出这是第 1、2 次尝试，以便知道自己卡了多久。
8. 作为学生，我想要换了符文石再遇到同一道题时，尝试次数继续累计，以便看到这道题对我的真实难度。
9. 作为学生，我想要我的学习记录只存在本机，以便不用担心隐私。
10. 作为学生，我想要选择「新的冒险」或「放弃冒险，重头再来」时，学习记录和进度一起清空，并在确认框里被告知，以便不会误删。
11. 作为长期游玩的学生，我想要记录变多以后游戏不会因为本机存储满了而存档失败，以便进度永远安全。
12. 作为在隐私模式下游玩的学生，我想要存储不可用时游戏照常运行，以便不被存档问题打断。
13. 作为维护者，我想要每条记录都带上当时的题池、章、tier 快照，以便日后题库重组（比如 W4-W8 扩题）后，旧记录的统计口径仍然正确。
14. 作为维护者，我想要题目被删除或改名后，旧记录仍能被安全读取（标为「题目已下线」），以便题库演进不破坏存档。
15. 作为维护者，我想要存档的序列化、迁移、校验是不依赖浏览器的纯函数，以便用单元测试覆盖所有版本组合。
16. 作为维护者，我想要一份真实 v1、v2 存档的固定样本，以便迁移测试对照的是真实数据而不是想象中的结构。
17. 作为维护者，我想要测试接缝 `__PYQUEST__` 的状态快照包含学习记录，以便 E2E 能断言「答错一次就多一条错误记录」。
18. 作为维护者，我想要 E2E 能真实点击一个错误选项，以便答错路径（扣心 + 记录）也有端到端覆盖。
19. 作为错题本的实现者，我想要按题查询「是否曾错、错几次、最近对错」的汇总，以便不用每次扫描整个日志。
20. 作为学习报告的实现者，我想要每章的进入/开门/通关时间点和有效游玩时长，以便画出通关时间线。
21. 作为存档导出的实现者，我想要一个单一的「当前版本存档对象」及其校验函数，以便导出/导入复用同一套结构。
22. 作为维护者，我想要存档版本号单调递增且迁移链只在一个地方实现，以便以后的 v4 只需追加一步。
23. 作为维护者，我想要迁移失败（存档损坏）时游戏不会崩溃，而是当作无存档并保留原始数据不覆盖，以便有机会人工抢救。
24. 作为老师，我想要学生的作答过程数据可被报告读出，以便了解班级在哪些知识点上普遍卡住。

## 实现决策

- **新模块「学习记录」**：唯一负责追加记录、维护每题汇总、维护每章时间点与有效游玩时长。
  对外接口（意图层面）：
  - `recordAttempt({ qid, slot, kind, pick, ok, ms })`：答题面板确认时调用，模块内部补上
    章/题池/tier 快照、尝试序号、时间戳，并更新汇总；
  - `recordSkip({ qid, slot, kind, ms })`：打开面板后未作答即关闭时调用；
  - `statsOf(qid)` / `allStats()`：只读汇总查询（错题本、报告使用）；
  - `markChapter(chId, event)`：event ∈ entered / gateOpened / done，只记第一次发生的时间；
  - 有效游玩时长：页面可见时累计，切后台、答题面板之外的暂停不扣（游戏内暂停仍算在玩）。
- **答题面板只发事件、不懂存储**：答题面板在「确认」与「取消」时把作答事实交给学习记录模块，
  并负责计时（从面板打开到确认；页面隐藏期间暂停计时；单次上限 30 分钟，超出按 30 分钟记）。
  第一个接入点是符文石答题；复习模式等后续调用方用 `kind` 区分。
- **符文槽类型**：按符文石的实际行为分三类 `shard`（碎片符文）/ `heal`（祝福符文）/ `boss`（BOSS 符文），
  另保留原始槽位 id。（GLOSSARY 里的 lair 槽位在现有地图上都以祝福符文出现。）
  非符文石来源（复习等）用 `review` 等新值，槽位 id 为空。
- **存档 v3 形状**（顶层沿用 v2 全部字段，新增 `records` 与章节时间点；键名短以省空间）：

  ```
  v: 3
  …v2 全部字段（startTime/hearts/maxHearts/current/answered/qAnswered/runeRolls/progress）
  playMs: number                         // 有效游玩时长（毫秒）
  progress[chId] += { enteredAt, gateOpenedAt, doneAt }   // 时间戳或 null（迁移来的为 null）
  records: {
    stats: { [qid]: { n, w, first: 'c'|'w', firstAt, lastAt, lastOk, solvedAt|null } },
    log:   [ { t, q, s, k, ch, pool, tier, pick, ok, ms, a } ],   // ok: 1 对 / 0 错 / -1 放弃
    dropped: number                      // 因上限被裁掉的原始记录条数
  }
  ```
- **存储键与迁移链**：沿用现有「版本进键名」惯例，v3 写入 `pyquest:save:v3`；读档按 v3 → v2 → v1 顺序找，
  迁移链 v1→v2→v3 写成纯函数逐级升级；迁移后首次成功写入 v3 才删除旧键（与现有 v1→v2 行为一致）。
  「有存档」「存档落点章节」「清档」三处都要认识全部三个键。
- **纯函数分层**：存档模块拆为「序列化（G → 存档对象）」「水合（存档对象 → G）」「迁移（任意旧版本 → v3）」
  「校验（结构/类型/范围检查，返回问题列表）」四个纯函数 + 一层薄的 localStorage 读写。
  校验函数供存档导出/导入（save-portability）复用。
- **容量与裁剪**：日志上限 3000 条（单条约 120 字节，约 360 KB，远低于 localStorage 常见的 5 MB 配额）；
  超限丢最老的，`dropped` 累加。写入时若抛配额异常，先把日志砍半重试，再失败则只写不含日志的存档；
  任何情况下游戏进度字段必须写成功。汇总 `stats` 永不裁剪（251 题量级，体积可忽略）。
- **快照字段**：记录里存当时的章、题池、tier，而不是读取时从当前题库反查。代价是每条多约 30 字节，
  换来题库重组后历史统计仍然正确。选项只存下标（题目选项若日后重排，历史下标会失义，接受此局限）。
- **测试接缝**：`state()` 快照新增 `records`（深拷贝）、`playMs` 与章节时间点；
  不新增写入类语义动作（答错走真实 DOM 点击）。
- **清档**：「新的冒险」与胜利页「重头再来」清空进度的同时清空学习记录，两处确认文案补一句
  「学习记录也会一起清除」。
- **隐私**：记录只写本机 localStorage，不发任何网络请求；标题画面不弹额外提示（不打扰），
  隐私说明放在后续学习报告/导出界面里。

## 测试决策

- 好测试只看外部行为：读档后的进度、`state()` 快照里的记录内容、localStorage 里的存档对象，
  不断言内部函数调用。
- **单元测试层**（依赖 core-unit-tests 引入的测试框架）：迁移链与校验是纯函数，最适合在这里覆盖——
  v1 样本 → v3、v2 样本 → v3、v3 原样往返、损坏 JSON、未知版本号、缺字段补默认值、
  日志裁剪与配额异常降级（用假的存储对象模拟抛异常）。
- **固定样本**：在改动存档代码之前，先用当前版本真实玩出一份 v2 存档（以及构造一份 v1 存档），
  作为测试样本入库；迁移测试对照它们。
- **E2E**（声明式 runner + `__PYQUEST__`）：
  - runner 新增一种步骤：在符文石上先真实点击一个错误选项再答对，断言心数 −1、记录多一条错误、
    同题第二条记录尝试序号为 2、汇总 `first` 为错；
  - 现有「进度已自动存档（v2）」断言改为检查 v3 键与 `records` 存在；
  - 胜利后断言该章 `doneAt` 已写入、`playMs` > 0。
- **smoke**：不涉及（存档不在数据层冒烟范围内）。
- 先例：E2E runner 的 `saveCheck` / `resume` 步骤；smoke 的抽题行为校验风格（构造状态 → 断言结果）。
