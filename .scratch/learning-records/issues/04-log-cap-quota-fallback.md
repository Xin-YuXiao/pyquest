# 04: 记录容量上限与存储配额降级

Status: ready-for-agent
Type: task
Blocked by: 02

## 要做什么

长期游玩时学习记录不能拖垮存档：原始日志超过 3000 条时丢最老的并累加 `dropped`，
每题汇总永不裁剪。浏览器存储配额用尽时，游戏进度必须照样存下来，记录按「日志砍半 → 不含日志」逐级降级。

## 验收标准

- [ ] 日志超过上限后保留最新 3000 条，`dropped` 等于被丢弃条数；汇总不受影响
- [ ] 写入抛配额异常时：先日志砍半重试；再失败则写不含日志的存档；进度字段在所有路径下都写成功
- [ ] 存储完全不可用（隐私模式等）时游戏照常运行、不抛异常
- [ ] 单元测试用假存储对象模拟配额异常与不可用，逐条覆盖上面三条路径
- [ ] 单元测试：构造 3500 条记录的存档，序列化后体积 < 600 KB
- [ ] `npm run check` 全绿
