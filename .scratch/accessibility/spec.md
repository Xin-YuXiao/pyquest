# 无障碍与设置面板

Status: needs-triage
Priority: P1
Source: 接手评估新增（源码核实：index.html 只有 1 处 aria- 属性；src 内没有任何焦点管理代码；Tab 键在游戏场景里被世界地图无条件拦截）
Depends on: 无（`mobile-touch-controls` 的触控层设置项复用本 effort 的设置存储）

## 问题陈述

PyQuest 是课程配套的教学游戏，学习内容全部在 DOM 浮层里（答题面板、对话框、HUD、世界地图、胜利页），
但这些浮层几乎没有可访问性语义：

- 答题面板不是对话框：没有 dialog 角色、打开时焦点不移进来、关闭后焦点不归还；读屏软件不知道「弹出了一道题」；
- 答对 / 答错的反馈（「咒语生效了」「生命 -1」+ 解析 / 提示）只是改了一段文字，没有 live region，读屏用户听不到结果；
- 游戏场景里按 Tab 一律被世界地图拦截（阻止默认行为后开关地图），键盘用户无法用 Tab 在按钮间移动焦点（答题面板里的「先不回答 / 确认」只能靠数字键和 Enter，没有 Esc 关闭）；
- HUD 的爱心、碎片计数是 SVG 拼出来的图形，没有文字替代；目标提示更新时也不播报；
- 对话框逐字打出台词，读屏会读到半句话；
- 减少动态效果只覆盖了一部分（CSS 里代码块金光、碎片金光脉冲、对话框弹出、地图图钉、胜利页；JS 里只有「碎片入袋」飞行会降级），
  圆形转场、受击镜头震动 / 缩放、答错面板抖动、开门镜头震动、HUD 跳变动画都还在动；
- 静音只有 M 键，界面上看不到开关，刷新后也不记得；没有音量调节；
- 没有字号调节：讲解文字字号固定，弱视或在投影上演示时偏小。

## 解决方案

- 答题面板、对话框、世界地图、标题页、胜利页都具备正确的对话框语义、焦点管理与可读名称；
- 答题结果、HUD 变化用合适礼貌级别的 live region 播报；
- 键盘可完成全部 DOM 浮层操作：Tab / Shift+Tab 在浮层内循环、Esc 关闭可关闭的浮层；世界地图的 Tab 快捷键只在自由探索时生效；
- 新增**设置面板**（标题页与游戏内都能打开）：音效开关与音量、字号（100% / 115% / 130%）、减少动态效果（跟随系统 / 开 / 关）；
  设置存在设备级存储里，与存档无关；
- 「减少动态效果」开启时，所有装饰性动画（含镜头震动、转场）都降级为瞬时或淡入淡出；
- 用自动化无障碍审计把关，防止回退。

## 用户故事

3. 作为读屏用户，我想听到每个选项的编号与内容、以及哪个被选中，以便确认我的选择。
4. 作为读屏用户，我想在确认后立刻听到「咒语生效了」或「咒语失败了，生命 -1」以及解析 / 提示，以便知道对错和原因。
5. 作为键盘用户，我想用 Tab / Shift+Tab 在答题面板的选项和按钮之间移动，而焦点不会跑到面板外面，以便不迷失。
6. 作为键盘用户，我想按 Esc 等同于「先不回答」关闭面板，以便快速退出。
7. 作为键盘用户，我想在面板关闭后焦点回到游戏画面，以便继续用方向键移动。
8. 作为键盘用户，我想在游戏里打开世界地图后，用 Tab 在已解锁地标之间移动、Enter 传送、Esc 关闭，以便不依赖鼠标。
9. 作为读屏用户，我想听到 HUD 的「生命 5 / 6」「证据碎片 2 / 3」与当前目标，以便了解状态。
10. 作为读屏用户，我想在目标变化（如「收集碎片」→「进入巢穴」）时听到一次礼貌播报，以便不错过推进。
11. 作为读屏用户，我想在对话框里一次听到整句台词，而不是逐字打字的半句话，以便理解引导。
12. 作为前庭障碍或易晕的玩家，我想开启「减少动态效果」后不再有镜头震动、圆形转场和面板抖动，以便舒适地游玩。
13. 作为已在系统里设置「减少动态效果」的用户，我想游戏默认跟随系统设置，以便不用重复配置。
14. 作为弱视学生，我想把界面字号调到 130%，以便看清代码块和讲解。
15. 作为在投影上演示的老师，我想放大字号，以便后排学生看清题目。
16. 作为在图书馆的学生，我想在界面上看到并点击静音开关，以便不用记住 M 键。
17. 作为玩家，我想调节音量，并且刷新后静音 / 音量设置仍然保留，以便每次不用重新调。
18. 作为玩家，我想点「新的冒险」清档时不会清掉我的设置，以便设置与进度互不干扰。

20. 作为读屏用户，我想在胜利页打开时听到通关标题与统计，焦点落在「进入下一章」按钮上，以便继续。
21. 作为读屏用户，我想让纯装饰的图标、星空、金印对读屏隐藏，以便不被噪音打扰。
22. 作为键盘用户，我想在标题页用 Tab 在「继续冒险 / 新的冒险 / 设置」之间移动，以便不用鼠标开局。
23. 作为维护者，我想在 CI 里对五种关键界面状态跑自动无障碍审计，以便新改动不会引入严重问题。
24. 作为维护者，我想让「减少动态效果」有一个全局的单一判定，以便新加的动画都能遵守。

## 实现决策

- **答题面板对话框化**：面板容器 `role="dialog"` + `aria-modal="true"`，`aria-labelledby` 指向章节徽标、`aria-describedby` 指向题干；
  选项组用 radiogroup / radio 语义（或按钮 + `aria-pressed`，二选一，推荐 radiogroup：与「单选」语义一致）；
  打开时记录先前焦点，焦点移到第一个选项；Tab 在面板内循环（焦点陷阱）；Esc 等同「先不回答」（答对后的「领取奖励」阶段 Esc 不关闭，避免误丢奖励——或等同领取，推荐不响应）；
  关闭后焦点归还画布容器。数字键 1-4 / Enter 保持不变。
- **反馈播报**：答题反馈区设 `aria-live="assertive"`（结果需要立刻知道），内容在一次 DOM 更新里整体写入；
  HUD 目标提示设 `aria-live="polite"`；爱心与碎片计数以可读文本暴露（视觉隐藏文本，如「生命 5 / 6」），数值变化不逐次播报，只在目标变化时播报。
- **Tab 冲突**：世界地图的 Tab 快捷键只在「自由探索」时响应（与它现有的 open 守卫一致：答题、对话、转场、濒死期间不打开），
  其余时候不阻止默认行为，让 Tab 回归焦点导航；世界地图打开后 Tab 在地标间移动、Esc / Tab 关闭。
- **对话框**：对话框 `role="dialog"`（非模态，`aria-modal` 不设），台词以整句写入一个 live region，打字机效果只作用于视觉层。
- **其他浮层**：标题页、胜利页作为模态对话框处理焦点（打开即聚焦主按钮）；装饰元素（星空、金印、像素图标）`aria-hidden`。
- **设置存储**：独立的设备级键（推荐 `pyquest:settings:v1`），不进存档；存档模块的清档只清存档键。形状（极简）：
  ```
  Settings = {
    v: 1,
    muted: boolean, volume: number /* 0..1 */,
    fontScale: 1 | 1.15 | 1.3,
    reduceMotion: 'system' | 'on' | 'off',
    touchControls: 'auto' | 'on' | 'off',   // 由 mobile-touch-controls 使用
  }
  ```
  读取失败（隐私模式）时使用默认值，不影响游戏——与存档模块的容错策略一致。
- **设置面板**：标题页加「设置」按钮；游戏内入口推荐 Esc（自由探索时）+ HUD 上的齿轮按钮（触屏也能点）；面板本身是模态对话框，遵守上面的焦点规则；打开时暂停场景（同世界地图）。
- **音量**：音效模块加一个主增益节点，`volume` 映射到增益；静音状态从设置读取并持久化，M 键与界面开关写同一份状态。
- **字号**：字号设计令牌（:root 上的 --fs-* 一组）统一乘以 fontScale；代码块、选项代码等目前写死像素的字号改为引用令牌；
  #ui-scale 的整体缩放保持不变（两者相乘）。放大后面板变高，依赖答题面板可滚动（`mobile-touch-controls/issues/02` 也会做，二者谁先落地谁做，另一个核对）。
- **减少动态效果的单一判定**：一个全局判定函数 =（设置为 on）或（设置为 system 且系统偏好 reduce）；body 上挂一个类供 CSS 使用，
  CSS 里现有的 `@media (prefers-reduced-motion)` 规则同时匹配该类；JS 侧的圆形转场、镜头震动 / 缩放、面板抖动、开门震动、碎片飞行都查这个判定。
  符文石 ±0.7% 呼吸与心形掉落浮动属低幅装饰，开启时一并停止。
- **颜色之外的区分**：世界地图三态已有图例与 ✓ / 🔒 徽章（需核实读屏文本完整）；答对 / 答错选项除颜色外加图标或文字前缀。

## 测试决策

- 只测外部可观察行为：焦点在哪个元素、可访问名称与角色是什么、live region 的文本、设置刷新后是否保留、动画是否被跳过（通过元素是否仍有运行中的 animation / 转场时长判定）。
- **E2E 声明式 runner**：在第一章流程里加入键盘无障碍断言（打开面板后 `document.activeElement` 是第一个选项；Tab 循环不出面板；Esc 关闭后焦点归还）。先例：runner 现有的答题步骤与 quizClick 护栏。
- **自动审计**：推荐引入 `@axe-core/playwright` 作为开发依赖（MPL-2.0，常用、可在 CI 跑），在标题页、答题面板、对话框、世界地图、胜利页五种状态各审计一次，serious / critical 违规为零才算通过；引入依赖前先在工单里记录体积与许可证。
- **设置持久化**：E2E 改设置 → 刷新 → 断言保留；点「新的冒险」→ 断言设置仍在、存档已清。
- **减少动态效果**：E2E 用 Playwright 的 `reducedMotion: 'reduce'` 上下文跑一遍第一章主线，断言流程不变、关键动画被跳过。
- 不为纯 CSS 外观写快照测试。

## 待决策

1. **答对后「领取奖励」阶段的 Esc**——推荐不响应（避免误操作丢失奖励兑付动画以外的语义混乱）；若希望 Esc 也能领取，需要同步改提示文案。
2. **游戏内设置入口**——推荐 Esc + HUD 齿轮按钮；如果担心 Esc 与答题面板「先不回答」冲突，可只用齿轮按钮（答题面板打开时 Esc 只作用于面板，不会冲突）。
3. **是否做高对比主题**——推荐本 effort 先不做，审计后若对比度问题集中再单开工单；当前羊皮纸配色多为深字浅底，需审计核实。

## 不做的事

- 让动作玩法本身（移动、战斗）对读屏用户可玩——这需要完全不同的交互设计；可在 `mistake-review` 等纯答题模式里提供无动作的学习路径（另议）。
- 多语言 / 界面翻译。
- 按键重映射。
- 系统级字体替换（字体本地化见 `self-hosted-fonts`）。

## 备注

- 现状核实：世界地图地标按钮已有 aria-label（「第N章…，已通关 / 可传送 / 未解锁」），像素图标 SVG 已 aria-hidden，胜利页金印已 aria-hidden；除此之外没有 role / aria-live / 焦点代码。
- 世界地图 open 已有守卫（答题 / 对话 / 转场 / 濒死期间不打开），但其 Tab 监听器先无条件阻止默认行为再调用 toggle——这正是 Tab 无法导航焦点的原因。
- 与 `mobile-touch-controls` 协调：触控层按钮需要 aria-label；触控层设置项 `touchControls` 落在本 effort 的设置形状里。
