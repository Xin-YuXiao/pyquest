# 章节 BOSS 专属机制：让每场 BOSS 战都打出本章知识点的手感

Status: needs-triage
Priority: P2
Source: 接手评估新增。11 个 BOSS 只有两种原型轮流复用：史莱姆型（紫勇士巨型化，hp 10，hp ≤6 / ≤3 各召唤 2 只小怪）与巨蟒型（黑勇士蛇头 + 6 节体节，hp 12，偶数 hp 断尾提速，蓄力突咬）。章节注册表的 boss 字段只是 `'slime' | 'snake'` 字符串；原型里的浮字写死第一/二章名字（「循环之王召唤了帮手！」「巨蟒的尾巴断了一节！」），第九章贝叶斯祭司、第十章幻言魔像战斗时会飘出错误的名字（已核实，属 bug）。
Depends on: 无（若 BOSS 阶段需要跨场景持久化，按 learning-records 的存档 v3 扩展约定；本方案首选「不持久化」，见实现决策）

## 问题陈述

- **玩家**：第三章以后的 BOSS 战与前两章完全一样——同一套追击、同一套召唤、同一套断尾。打到第八章「NFW 幻龙」时，它和第二章的「巨蟒毕森」在手感上没有任何区别，BOSS 战成了答完 BOSS 符文后的例行公事。
- **玩家**：第九章的贝叶斯祭司召唤帮手时头顶飘出「循环之王召唤了帮手！」，第四章单位术士断尾时飘「巨蟒的尾巴断了一节！」——名字对不上，出戏。
- **教师**：BOSS 战是每章的高潮，却完全没在强化本章知识点。「频率」「密度轮廓」「后验更新」「幻觉」这些概念本可以变成可感知的战斗规则，让学生用身体记住。
- **维护者**：BOSS 行为写死在两个类里，想给某一章加机制只能复制整个类；E2E 的 BOSS 战断言按原型硬编码（史莱姆一击 hp=9，巨蟒两击 hp=11/10、体节 6→5），一改机制就要动共享运行器。

## 解决方案

- 保留两种原型作为 BOSS 的「身体」（素材、动画、移动、接触伤害不变），在其上叠加**数据驱动的招牌机制（signature）**：每章在章节注册表里声明「原型 + 机制 id + 参数 + 浮字文案」，同一套机制可被多个 BOSS 复用、参数化。
- 先做一次**零玩法变化的 prefactor**：BOSS 配置对象化、浮字改用本章 BOSS 名（顺带修掉错名 bug）、E2E 的 BOSS 战期望值从运行器挪到各章声明里。
- 为全部 11 个 BOSS 设计与本章知识点呼应的招牌机制（下表），经 grilling 确认数值与取舍后，**先做一个样板 BOSS（傅里叶魅影）跑通全链路**，再按原型分批铺开。
- 可选的**二阶段：护盾再生**——BOSS 血量降到阈值时护盾重新张开，需答第二块 BOSS 符文才能继续造成伤害；先在样板上启用，是否推广由 grilling 决定。

### 11 个 BOSS 的招牌机制方案

| 章 | BOSS（原型） | 呼应知识点 | 招牌机制（玩家视角） | 可读提示 / 反馈 |
| --- | --- | --- | --- | --- |
| 一 | 数据史莱姆王（史莱姆） | 列表索引 / 负索引 / append | **索引帮手**：召唤的帮手排成一列，头顶标 `[0] [1] [2]`；史莱姆王喊出「击败 `list[-1]`！」，打中被点名的帮手 → 王的护甲掉一层（下一击伤害 ×2）；打错 → 王再 `append` 一只帮手 | 被点名的帮手脚下亮圈；打错时浮字「索引错了：那是 list[0]」 |
| 二 | 巨蟒毕森（巨蟒） | for / range / break | **循环突咬**：每次突咬前头顶显示 `for i in range(n)`，连续突咬 n 次后进入 `break` 硬直 2 秒（输出窗口）；每断一节尾巴 n+1 | 头顶计数逐次点亮；硬直时浮字「break！」 |
| 三 | 混沌曲线魔君（史莱姆） | 广播 / 布尔掩膜 | **广播弹幕**：魔君同时射出一行和一列弹幕，地面预警成 N×N 网格；网格中被「掩膜」点亮的格子是安全格 | 预警 0.8 秒；安全格金色描边 |
| 四 | 单位术士（巨蟒） | HDUList 索引 / append / insert | **HDU 体节**：体节标 `Primary / BinTable / Image…`；术士念出 `hdul[2]` 时只有该索引的体节可被打断，打断后其余体节索引前移（与 w4boss 的 append/insert 索引推理一致） | 被点名体节发光；索引变化时体节标签刷新 |
| 五 | 迟缓巨魔（史莱姆） | 向量化 / @jit / 并行 | **迟缓光环**：光环内玩家移速 ×0.5（「for 循环般迟缓」）；破盾瞬间获得 15 秒「@jit 加速」（移速 ×1.4、光环无效） | 光环半透明红圈；buff 期间勇者身后残影 + HUD 小图标倒计时 |
| 六 | 优化牛头怪（巨蟒） | 优化 / 阻尼收敛 | **过冲冲锋**：冲锋穿过玩家位置后在墙间来回振荡，振幅逐次衰减（学习率过大 → 收敛），停稳后硬直 2 秒 | 振荡轨迹残影；停稳时浮字「收敛了！」 |
| 七 | 傅里叶魅影（史莱姆） | FFT / 频率 / ifft 还原 | **频率分身**（样板）：hp 降到 7 时分裂成三个分身，按不同频率闪烁、头顶标 1 / 4 / 7 Hz（与 w7boss 的三纯音 FFT 题一致）；须按频率从低到高击破；顺序错 → 分身重组、本体回 1 hp；三身全破 → 本体「ifft 还原」现形并硬直 | 闪烁节奏即频率；击破顺序在头顶依次打勾 |
| 八 | NFW 幻龙（巨蟒） | 密度轮廓 ρ ∝ r⁻¹ / r⁻³ | **密度护甲**：外层体节一击即断（稀薄外区 r⁻³），越靠近头部的体节需要越多击（致密内区 r⁻¹），头部只有体节剩 ≤2 时可伤（「核心暴露」） | 体节颜色由浅到深表示密度；被打时浮字显示剩余「质量」 |
| 九 | 贝叶斯祭司（史莱姆） | 先验 → 似然 → 后验更新 | **后验预判**：祭司记录玩家最近若干次的走位方向，每被击中一次就「更新后验」，下一轮弹幕向玩家最常走的方向偏移；玩家必须改变走位习惯「打破先验」 | 祭司头顶一条 4 方向小直方图实时变化 |
| 十 | 幻言魔像（巨蟒） | 幻觉 / 先验证再信任 | **幻觉符文**：破盾后大厅里浮现 2-3 块与真符文几乎一样的「幻觉符文石」（无影子、光晕偏色、铭文拼错如 `np.smooth`）；只有带「测试用例」徽记的验证符文是真的——交互真符文 → 魔像断一节；交互幻觉符文 → 扣 1 心并浮字揭穿 | 幻觉符文不弹答题面板、不占题池；揭穿浮字「np.smooth 不存在——这是幻觉！」 |
| 十一 | 三途守门人（史莱姆） | 三类 project workflow | **三途姿态**：守门人轮换「拟合 / 模拟 / ML」三种姿态。拟合姿态只在指定「残差环」距离内可伤；模拟姿态需先打掉环绕的「PSF 光晕」；ML 姿态对同一方向的连续攻击免疫（「过拟合」），必须换方向（「泛化」） | 姿态切换时头顶图标 + 一句姿态口诀 |

> 上表是起草方案，数值（hp 阈值、时长、倍率）与文案全部待 grilling 确认；玩法机制不属于题面内容，不受 ADR-0001 约束，但所有出现的 Python/天文概念（`list[-1]`、`hdul[2]`、1/4/7 Hz、r⁻¹/r⁻³）都取自已上线题目，保证与讲义一致。

## 实现决策

- **BOSS 配置对象化**：章节注册表的 `boss` 字段从字符串扩展为对象，字符串写法自动归一化为 `{ base }`，保证逐章迁移。极简形状：

  ```
  boss: {
    base: 'slime' | 'snake',          // 身体原型（素材/移动/接触伤害）
    hp?: number,                      // 缺省沿用原型：slime 10 / snake 12
    signature?: { id: string, params: object },   // 招牌机制
    phase2?: { atHp: number },        // 可选：护盾再生阈值（需第二块 BOSS 符文）
    lines?: { summon?, segment?, shield?, phase2?, intro? },  // 浮字文案，缺省按 bossName 生成
  }
  ```
- **机制 = 挂在原型上的策略对象**（组合而非继承）：机制注册表按 id 提供 `attach / update / beforeHurt / afterHurt / onPin / describe` 钩子；两个原型在固定位置调用钩子（每帧更新、受击前后、被冻结）。`beforeHurt` 可返回「吸收」（例如顺序错误、姿态免疫），由原型统一处理浮字与击退。机制只通过场景已有能力（召唤小怪、浮字、震屏、音效）与世界交互。
- **浮字修正（prefactor 中完成）**：原型里写死的「循环之王」「巨蟒」浮字改为读 `lines`，缺省模板用本章 `bossName` 生成（例如「贝叶斯祭司召唤了帮手！」）。第一、二章的现有文案作为它们的显式 `lines` 保留，玩家看到的内容不变。
- **纯逻辑抽离**：顺序判定（频率分身）、阻尼振荡轨迹（牛头怪）、走位直方图与偏移（祭司）、索引重排（HDU 体节）写成不依赖 Phaser 的纯函数，便于 smoke / 单元测试直接调用。
- **确定性**：机制中的随机（点名哪个索引、幻觉符文位置）使用按章节 seed 派生的伪随机，与地图生成器同一思路；`pinBoss` 时机制进入冻结态（暂停计时器、分身停在原位、弹幕清空）。
- **二阶段：护盾再生**：巢穴地图在启用 `phase2` 的章节额外放一块隐藏的第二 BOSS 符文槽 `c{N}boss2`（映射到本章 boss 题池；boss 池 3 题，与第一块符文「同池不撞题」规则自然兼容）。hp 降到 `atHp` 时：若 `c{N}boss2` 已在已答槽位中（之前的尝试答对过）→ 不再上盾；否则护盾重生、第二块符文显形。**不新增存档字段**：二阶段是否已解完全由「已答槽位」推导，死亡重生后 BOSS 满血重来，阶段随之重置（与现有 hp 不存档的规则一致）。
- **幻觉符文**（第十章）是新的道具类型（非 `rune`），不进题池映射、不被跳章接缝标记为已答，交互只触发机制判定。
- **测试接缝扩展**（语义化，保持只读优先）：
  - 新增只读 `bossInfo(sceneKey)`：`{ hp, base, signature, phase, shielded, targets: [...] }`，`targets` 给出当前可交互的分身/体节/帮手及其标签与坐标。
  - `pinBoss` 增加对机制冻结钩子的调用。
  - `slayBoss` 保持「hp=1 后真实 hurt」；对启用二阶段的 BOSS，E2E 需先用真实答题解第二块符文（与第一块符文同一套答题助手），不提供绕过护盾的作弊。
- **E2E 声明化**：运行器的 bossFight 步骤从「按原型硬编码 hp 9 / 11 / 10、体节 6→5」改为读取本章声明的 `hits: [{ hp, segs? }]` 期望序列，缺省值等于现状。新增步骤类型 `bossSignature`（按 `bossInfo.targets` 规则逐个击破）与 `bossPhase2`（等待护盾重生 → 答第二块符文 → 断言破盾）。

## 测试决策

- **好测试的标准**：只断言玩家可观察的结果（BOSS hp、护盾状态、分身数量、通关标记、浮字出现与否），不断言机制内部字段名。
- **E2E（首选接缝）**：每章现有 BOSS 战断言保留；做了招牌机制的章节在本章 E2E 声明里追加 `bossSignature` 步骤；启用二阶段的章节追加 `bossPhase2`。先例：现有 bossShielded / bossRune / bossFight / victory 步骤与 `pinBoss` / `slayBoss` 接缝。
- **smoke（数据层）**：校验所有章节 BOSS 配置可归一化、机制 id 已注册、参数齐全、`lines` 无旧名残留（第三章及以后不得出现「循环之王」「巨蟒」字样）、二阶段符文槽在题池映射里。先例：smoke 现有的「各章符文槽均指向本章题池」。
- **纯逻辑**：顺序判定、阻尼振荡、直方图偏移、索引重排在 smoke 中用固定输入断言输出；单元测试层（vitest）落地后可迁过去。
- **回归**：`npm run check` 全绿，11 章 E2E 全过，BOSS 战平均时长不明显变长（E2E 单章耗时作为粗略观测）。

## 待决策

1. **样板选哪个 BOSS？** 推荐**傅里叶魅影（第七章）**：机制最直观（频率=闪烁节奏）、覆盖分身/顺序/重组/现形四种能力，做完后其他机制大多是子集；备选幻言魔像（第十章，概念最贴「验证」但新增道具类型，样板风险更大）。
