# 教师自定义题包（练习场）

Status: needs-triage
Priority: P2
Source: 接手评估新增——游戏服务于 P4A@UCAS 课程，但题库只能由开发者改代码维护（题面在数据层源码里），
老师/助教想给某次课、某个作业补一组练习题，必须提 PR、等发布；按 ADR-0001 主线题库又必须严格对齐讲义，
课堂上的临时练习、习题课补充题、往届作业改编题没有合适的落脚点。
Depends on: challenge-modes（共用「答题会话」界面与答题面板 prefactor）、quiz-bank-lint（题目 schema 的同一份定义）、
learning-records / mistake-review（题包作答是否入册，见待决策）、save-portability（导出存档时是否附带题包）

## 问题陈述

- 老师想让学生在游戏里练一组「本周习题课」的题，现在唯一的办法是改源码，老师不会也不该这么做。
- 主线题库受 ADR-0001 约束（以讲义为权威源），老师自编、改编、往届真题这类材料不能也不应该进主线十一章。
- 老师/助教没有本地校验工具：写好的题目格式对不对、答案下标有没有越界、填空占位符写没写，只能等学生报错。
- 学生拿到一份题包后需要一个简单的导入方式，不需要安装任何东西、不联网也能用。
- 安全：题包来自外部文件，一旦答题面板把题包内容当 HTML 渲染，就是 XSS 入口。核实现状：题面与章标签走纯文本；选项与解析经过转义后拼进 HTML；代码块走语法高亮函数（先转义 & < > 再加高亮标签）——转义本身成立，但高亮函数有一个结构性缺陷：字符串字面量被包进 `class="str"` 的标签后，后续的函数名高亮规则会再匹配到属性里的 `str`，产出嵌套损坏的标签（核实：`print("hi")` 的高亮结果里出现了 `class="<span class="fn">str</span>"`）。主线题目同样受影响（显示上可能看不出来），而题包会让任意代码走这条路径，必须先加固。

## 解决方案

- **题包格式**：一个 JSON 文件，包含题包元信息（id、标题、作者、说明、版本）和题目列表；题目字段与主线题库一致（题面、代码块、选项、正确项、解析、可选的填空标记与提示语），不使用 tier 体系。
- **导入**：标题画面新增「题包练习场」：选择文件（或拖放、或粘贴 JSON 文本）→ 校验 → 预览（标题、作者、题数）→ 确认导入。校验失败给出逐条中文报错（第几题、哪个字段、怎么改）。
- **练习**：导入后的题包出现在练习场列表里，点开即在「答题会话」里顺序练习（与每日星图同一套界面），结束有结果页与解析；记录每个题包的进度（答对过哪些题、最佳成绩）。
- **隔离**：题包与其进度存在独立的存储里，不进入主线十一章、不影响主线存档、不进入知识卡图鉴；可删除题包。
- **教师工具**：仓库提供题包模板、本地校验命令（与游戏内校验用同一份 schema）、以及从既有题池导出示例题包的命令（例如把第一章碎片题池导出成一个示例题包，内容原样，不改题面）。

## 用户故事

1. 作为课程教师，我想要用一个 JSON 文件写一组练习题发给学生，以便不改游戏代码就能布置练习。
2. 作为课程教师，我想要题包的题目字段和游戏主线题目一致（题面、代码、选项、答案、解析），以便直接参考现有题目的写法。
3. 作为课程教师，我想要一个可以直接复制修改的题包模板，以便十分钟内写出第一份题包。
4. 作为课程教师，我想要在自己电脑上运行一条命令就能校验题包，并得到逐条中文报错，以便发给学生前就把问题修掉。
5. 作为课程教师，我想要校验命令和游戏内导入用同一套规则，以便「本地校验通过」就等于「学生导入不会失败」。
6. 作为课程教师，我想要从现有题池导出一份示例题包，以便看到真实、完整的格式样例。
7. 作为课程教师，我想要题包支持代码填空题和代码块语法高亮，以便和主线题目有同样的表现力。
8. 作为课程教师，我想要给每道题写一句答错时的提示语，以便学生答错时得到针对性的引导（主线的提示语按章硬编码，题包的题需要自带）。
9. 作为课程教师，我想要给题包标注版本号，以便更新题包后学生重新导入时能看到「新版本」并选择覆盖。
10. 作为学生，我想要在标题画面一键导入老师发的题包文件，以便不用安装任何东西。
11. 作为学生，我想要导入前先看到题包标题、作者、题数的预览，以便确认导入的是对的文件。
12. 作为学生，我想要导入失败时看到能看懂的原因（例如「第 3 题的正确项超出选项范围」），以便转告老师。
13. 作为学生，我想要在练习场里看到已导入题包的列表、各自的完成情况，以便管理多份练习。
14. 作为学生，我想要用和每日星图一样的答题界面练题包，以便不用重新学操作。
15. 作为学生，我想要练习结束后看到每题对错与解析，以便当场学会。
16. 作为学生，我想要题包练习不扣主线爱心、不影响主线进度，以便放心练习。
17. 作为学生，我想要删除不再需要的题包，以便列表保持整洁。
18. 作为学生，我想要重复导入同一份题包（同 id 同版本）时被提示「已存在」，而导入新版本时被询问是否覆盖并保留进度，以便老师更新题目后不丢记录。
19. 作为学生，我想要题包离线也能使用，以便在没有网络的地方练习。
20. 作为学生，我想要题包里的内容不会在我的浏览器里执行任何脚本，以便来路不明的文件也不会伤害我。
21. 作为维护者，我想要题包的题目 schema 与主线题库校验共用一份定义，以便规则只维护一处。
22. 作为维护者，我想要对题包大小、题数、单字段长度设上限，以便异常文件不会撑爆本地存储或卡死界面。
23. 作为维护者，我想要题包存储与主线存档、元进度分离，以便清档、二周目都不会误删题包。
24. 作为维护者，我想要题包功能完全不影响主线题库与十一章的行为，以便 ADR-0001 的约束保持不变。
25. 作为维护者，我想要测试接缝能读到已导入题包列表与练习进度，以便 E2E 能断言导入、练习、删除全流程。

## 实现决策

**题包格式（schema v1）**
- 极简形状：
  `{ format: "pyquest-pack", schema: 1, id, title, author?, description?, version, questions: [ { id, label?, prompt, code, options: [3..4 个], answer, explain, fill?, hint? } ] }`
- 约束：
  - id 为小写字母、数字、连字符。
  - 选项 3–4 个：答题面板的键盘只支持 1–4；主线 251 题全部是 4 个选项，主线校验要求至少 3 个。
  - answer 是合法下标；选项互不相同。
  - fill 为真时，代码里必须有 `___` 占位符。
  - 单题字段长度上限（例如题面 ≤ 600 字、代码 ≤ 40 行）；每个题包最多 200 题；序列化体积上限 512KB（参考：主线题库 251 题序列化约 98KB）。
- 题包不使用 tier、题池、符文槽概念；label 只用于显示（相当于主线的章标签），hint 为答错提示语（缺省时用通用提示）。
- **单一 schema 定义**：题目字段规则与 quiz-bank-lint 的主线题目 schema 共用同一个模块；题包 schema 在其基础上去掉 tier、加上 hint 与包元信息。若 quiz-bank-lint 尚未落地，本 effort 先建立该 schema 模块，quiz-bank-lint 复用（以先落地者为准）。

**导入与存储**
- 标题画面新增「题包练习场」入口：文件选择、拖放、粘贴文本三种方式，统一走「解析 → schema 校验 → 预览 → 确认」。
- 存储在独立的本地存储键（建议 `pyquest:packs:v1`）：已导入题包本体 + 每个题包的进度（答对过的题 id、最佳成绩、最后练习时间）。与主线存档、元进度都分离；「新的冒险」「二周目」不影响它。
- 同 id 同版本 → 提示已存在；同 id 新版本 → 询问覆盖，进度按题 id 保留（被删掉的题对应的进度丢弃）；不同 id → 新增。
- 写入失败（本地存储配额不足）时给出明确提示，不留下半写入状态。

**练习**
- 复用 challenge-modes 的「答题会话」：顺序或打乱（题包可声明，缺省顺序），答错不给第二次机会、直接显示提示语与正确答案解析（与限时试炼一致），结束显示结果页。
- 不扣主线爱心、不发碎片、不进知识卡图鉴；是否进入学习记录与错题本见待决策。

**渲染安全边界**
- 题包所有字段一律当纯文本：题面、标签、提示语用纯文本节点；选项与解析继续走转义；代码块走语法高亮，但先修复高亮函数的嵌套标签缺陷（建议改为「先切分词元再统一转义输出」，而不是在已生成的 HTML 上多轮正则替换），并为它补上结构良好性测试。
- 不支持题包内任何 HTML/Markdown 富文本、图片、外链（v1）。

**教师工具（命令行，仓库内）**
- 校验命令：读取一个或多个题包文件，用同一份 schema 校验，输出逐条中文报错与「通过 / 不通过」，退出码可用于老师自己的 CI。
- 导出命令：把指定主线题池原样导出为题包（题面/代码/选项/答案/解析不改动，label 取题目的章标签，hint 取该章的提示语），用作示例。
- 题包模板与一页使用说明（放在 docs 下）。

**测试接缝**
- 只读快照新增 packs：已导入题包的 id/版本/题数/进度。
- 语义动作：「清空题包存储」（测试隔离）。导入本身必须走真实 DOM（文件选择或粘贴），不提供跳过校验的作弊入口。

## 测试决策

- **E2E（首选）**：新增非章节套件：标题画面 → 题包练习场 → 用 Playwright 的文件选择注入一个合法题包 → 预览显示标题与题数 → 导入 → 练完 3 题（真实 DOM 点击）→ 结果页 → 刷新后进度保留 → 删除题包。另一条注入非法题包（answer 越界）→ 断言出现定位到「第 N 题 answer」的中文报错且没有导入。挂进 npm run test:e2e 的额外套件列表。
- **恶意内容 E2E**：题包题面/选项/解析/代码里放 `<img src=x onerror=...>` 与 `<script>`，导入并打开该题，断言页面没有执行（用一个全局标志变量检测）且文本按字面显示。
- **校验规则**：schema 的规则用表驱动测试覆盖（合法 / 每条规则各一个非法样例）。放在 smoke（纯数据，Node 可直接跑）或单元测试层（若已落地）。
- **教师命令**：smoke 中调用导出命令导出第一章碎片题池，再用校验命令校验导出结果必须通过——保证「导出 ↔ 校验」闭环。
- **高亮函数**：结构良好性测试——对含字符串字面量、数字、关键字、`___` 占位符的代码，输出的 HTML 解析后标签正确嵌套、文本内容与原代码一致。
- 先例：smoke 现有的题库格式校验（题目结构完整、answer 越界、填空占位、高亮无 script）；`e2e.mjs` 独立脚本。

## 待决策

1. **题包作答是否进入学习记录 / 错题本**：推荐进入学习记录（带 `pack:<id>` 模式标签，学习报告可筛选），错题本里单独一个「题包」分组；不进知识卡图鉴。→ 工单 05。
2. **是否支持从 URL 导入**（老师把题包放在课程网站上）：推荐 v1 不做（涉及跨域与内容来源信任），只支持文件/粘贴；v2 再评估。
3. **题包能否包含可执行判分题**（pyodide-sandbox 落地后）：推荐 v1 只支持四选一与填空，schema 预留题型字段但不开放。
4. **练习顺序**：推荐题包可声明顺序或打乱，缺省顺序（老师通常按讲解顺序组织）。
5. **题包是否随存档导出**：推荐 save-portability 的导出提供「附带题包」勾选项，缺省不附带。

## 不做的事

- 不做服务器、账号、题包市场或在线分享。
- 不让题包进入主线十一章、题池、符文槽或 tier 体系（ADR-0001 只约束主线题库，题包内容由老师自行负责）。
- 不支持富文本、图片、外链、脚本。
- 不做游戏内的题包编辑器（老师用文本编辑器 + 校验命令）。
- 不做老师端的成绩回收（学生可通过 learning-report 的导出把成绩交给老师）。

## 备注

- 主线题库序列化约 98KB / 251 题，按此估算 200 题的题包约 80KB，512KB 的上限对本地存储足够宽松。
- 主线答错提示语目前是答题面板里按章标签硬编码的一张表（共 21 个标签），题包题目必须自带 hint，否则只能显示通用提示。
- 高亮函数的缺陷影响主线所有含字符串字面量的题目，修复后应顺手跑一遍全部章节 E2E 与 verify-quiz，确认显示无回归。
