# 课堂投屏模式：Peer Instruction 两轮投票与全班 BOSS 战

Status: needs-triage
Priority: P1
Source: 接手评估新增 · 借鉴教学研究/教育产品（见 .scratch/INSPIRATION.md）——Peer Instruction（Mazur）、Kahoot 文献综述、Classcraft 的 BOSS 战形成性评价
Depends on: 无硬依赖（可选协同：custom-quiz-packs 提供题包题源；boss-signature-mechanics / 现有 BOSS 贴图提供全班 BOSS 战的形象；quiz-bank-lint 的高亮修复影响投屏代码显示）

## 问题陈述

- **助教视角**：这门课有现成的 251 道对齐讲义的题（34 个题池，带代码块与解析），但它们只能在学生各自的游戏里一题一题地答。
  课上想拿几道题做一次全班即时检测，只能手抄到 PPT 里，代码块排版、解析都要重做。
- **课堂互动视角**：Peer Instruction（先独立作答 → 同伴讨论 → 再作答）是物理与理工科课堂里被广泛使用、
  有研究支撑的互动方法；它需要的只是「一道好题 + 两轮票数 + 揭晓对比」，游戏的题库天然合适，但游戏里没有这种界面。
- **设备与网络现实**：教室里学生的手机、校园网都不可控；Kahoot 一类工具依赖每个学生联网登录。
  一个「只需要助教一台电脑 + 投影」的方案门槛最低：学生举手或举 ABCD 卡片即可。
- **氛围视角**：Kahoot 文献综述提到竞争性可能增加部分学生的焦虑；Classcraft 的设计刻意不做排行榜。
  课堂检测应该是全班一起「打 BOSS」，而不是个人排名。
- **维护者视角**：现有答题面板绑定游戏场景（暂停/恢复场景、扣心、发碎片），且住在 960×640 的设计坐标系里，
  投屏需要的是全视口、超大字号、无游戏副作用的独立显示层。

## 解决方案

标题画面新增「课堂模式」入口（只在标题画面，不进入野外/巢穴，不读写玩家存档）：

1. **选题**：按章节 → 题池浏览全部题目（题面摘要、是否带代码、是否可执行），勾选组成本节课的题单；
   也可「从某题池随机抽 N 题」。题单可保存为「课堂题单」下次复用。后续可从教师题包选题。
2. **一题一屏**：全视口投屏，题面与代码块超大字号、代码高亮；选项同时标 A/B/C/D 与 1/2/3/4（方便举卡片）；
   F 全屏、B 黑屏（翻页器常用键）、←/→/PageUp/PageDown/空格翻页。
3. **Peer Instruction 两轮流程**（每题可选开/关）：
   - 第一轮：倒计时（可选）→ 学生独立举手/举卡 → 助教用大按钮或键盘快速录入每个选项的人数 →
     显示票数分布直方图（**不揭晓正确答案**）；
   - 界面按第一轮正确率给出流程建议（例如很低时建议先讲解、中等时建议同伴讨论、很高时建议简短讲解后跳过，阈值可配置）；
   - 同伴讨论：讨论计时器 + 「和邻座说服对方」提示；
   - 第二轮：再次录入 → 揭晓正确答案（高亮）+ 解析 + 两轮分布对比（正确率从 x% → y%）。
4. **全班 BOSS 战**（可选包装）：开场投屏一个章节 BOSS 和血条；每道题以全班最终正确率换算成对 BOSS 的伤害，
   答完题单时结算「BOSS 被击败 / 剩余血量」。只有全班的数字，没有任何个人分数或排行榜。
5. **课后**：本节课每题的两轮票数、正确率、提升幅度汇总成一张表，可导出 CSV，供助教写课堂记录或调整下次讲解。

## 实现决策

- **入口与生命周期**：标题画面新增「课堂模式」按钮。课堂模式是独立的全视口 DOM 层，**不放进 960×640 设计坐标系的
  `#stage` 内部**，而是覆盖整个视口，用视口单位与 clamp 字号自适应 16:9/4:3；退出后回到标题画面。
  不启动任何野外/巢穴场景，因此不涉及 Phaser 全局按键捕获与世界地图的 Tab 监听（二者只在世界场景创建后才挂载，已核实）。
- **零游戏副作用**：不调用扣心、发碎片、标记已答题、抽题记录等任何状态函数；不读写玩家存档键。
- **题源**：只读题库模块的 QUESTIONS/POOLS（章节标签取题目的 chapter 字段，题池名取 POOLS 键）；
  题面、代码、选项、解析原样显示（ADR-0001：课堂模式不改写题面）。代码块复用答题行为层的语法高亮
  （注意：高亮函数存在字符串字面量嵌套标签缺陷，custom-quiz-packs 的 01 号工单负责加固；投屏前必须确认已修复或在本 effort 内修复）。
  教师题包题源通过 custom-quiz-packs 的题包存储只读接入（07 号工单）。
- **课堂数据存储**：独立本地存储键 `pyquest:classroom:v1`：保存的题单（题 id 列表 + 名称）、默认参数（计时、阈值、是否两轮）、
  最近若干节课的统计（只有每题每轮每选项的人数，不含任何学生身份信息）。
- **会话状态机**（极简形状）：
  ```
  题单 → 每题：show → [timer] → vote1 → histogram1 → (advice) → [discuss] → vote2 → reveal → next
                                                     └─ 跳过第二轮 ──────────────→ reveal
  ```
  翻页器的「下一步」在状态机里前进一步；「上一步」只允许回退到上一个展示态，不清除已录入的票数（防误触）。
- **录票交互**：每个选项一个大按钮（点击 +1，右键或长按 −1）；键盘 1-4 / A-D 为对应选项 +1，Shift+键 −1，
  也可点击人数直接输入；「清零」需确认。录入阶段显示合计人数（可选填写「应到人数」，用于显示参与率）。
- **统计纯函数**：`distribution(counts)`（各选项人数与百分比）、`correctRate(counts, answer)`、
  `advice(rate, thresholds)`（返回 explain/discuss/move-on 三档）、`gain(round1, round2, answer)`、
  `bossDamage(rate, config)`；全部在数据层测试覆盖边界（0 票、单选项全票、只有一轮）。
- **建议阈值**：默认值取 Peer Instruction 文献中常见的经验区间（具体数值以核实 Crouch & Mazur 2001 原文后为准，01 号工单定），
  界面文字写「建议」，不强制流程。
- **全班 BOSS 战**：开场选 BOSS（11 章 BOSS 名与形象；形象优先复用游戏已加载的贴图——课堂模式在 BootScene 完成后才可进入，
  可从纹理管理器取帧绘制到 canvas，需核实；不行则用程序化像素图标）；血条总量 = 题单题数 × 单题满伤；
  每题伤害 = 满伤 × 最终正确率（取第二轮，若跳过第二轮取第一轮）；正确率低于护盾阈值时伤害打折并提示「需要讲解」；
  结算页只显示全班数字。不做个人得分、不做排行榜（Classcraft 的设计取舍，见备注）。
- **课后汇总与导出**：每节课生成汇总表（题 id、章节标签、正确选项、第一轮各选项人数与正确率、第二轮同上、提升幅度）；
  导出 CSV 带 UTF-8 BOM（Excel 中文不乱码），与 learning-report 的 CSV 约定一致。
- **可访问性**：直方图每根柱子标字母与人数、柱内纹理区分正确项（揭晓后）；投屏配色高对比；尊重 prefers-reduced-motion（BOSS 受击动画降级）。
- **测试接缝**：新增只读查询 `classroom()`：当前状态机阶段、题单、当前题 id、两轮票数、BOSS 血量；
  语义动作 `clearClassroomStore()`（测试隔离）。录票必须走真实 DOM/键盘，不提供直接写票数的作弊入口。

## 测试决策

- **好测试的标准**：只断言助教和学生在屏幕上能看到的东西——题面、票数、百分比、建议文案、揭晓的正确项、BOSS 血量、导出文件内容；
  不断言内部状态机的实现细节（阶段名只通过只读接缝读取，用于等待）。
- **E2E（首选）**：新增非章节套件 `e2e-classroom`（仿照 runner：外网请求拦截、浏览器无报错断言），登记进 `npm run test:e2e` 的额外套件列表：
  标题画面 → 课堂模式 → 选 `w1field` 两题 → 第一题：键盘录入第一轮票数 → 断言直方图百分比 → 前进到讨论 → 第二轮录入 → 揭晓 →
  断言正确项高亮与「x% → y%」→ 第二题跳过第二轮 → 课后汇总表数值正确 → 导出 CSV（Playwright 下载事件）内容核对 →
  退出后玩家存档键未出现；BOSS 战另一条：血量按正确率下降、低正确率出现护盾提示。
- **数据层（smoke）**：统计纯函数表驱动测试（0 票、全票、单轮、阈值边界）；题单引用的题 id 必须存在。
- **先例**：runner 的声明式步骤与「浏览器无报错」断言；QuizOverlay 的高亮显示；learning-report 的 CSV 约定。

## 待决策

1. **建议阈值**：推荐默认「第一轮正确率 < 30% 建议先讲解、30%–70% 建议同伴讨论、> 70% 建议简短讲解后继续」，
   并允许助教修改；具体数值需核实 Peer Instruction 原始文献后再写入界面说明（01 号工单）。
2. **默认是否开启两轮流程**：推荐默认开启，单题可跳过第二轮（概念题适合讨论，纯记忆题不适合）。
3. **BOSS 伤害换算**：推荐线性（伤害 = 满伤 × 正确率），护盾阈值 30% 时伤害减半；题单答完 BOSS 未倒下就显示「下节课再战」而不是「失败」。
4. **录票方式**：推荐「数字键 +1 / Shift −1 / 点击直接输入」三种并存；是否支持「只录正确/错误两类」的简化模式（举手式）——推荐支持，作为题单级开关。
5. **是否允许课堂模式里展示「可执行」标记与运行代码**：推荐 v1 只展示；待 pyodide-sandbox 落地后再考虑现场运行代码演示。
6. **课堂统计保留多少节**：推荐保留最近 20 节课，超出时提示导出后清理。

## 不做的事

- **不做学生手机实时投票**：需要后端、账号或局域网服务，与「零学生设备、零网络」的前提冲突；列入未来方向（可评估局域网 WebRTC 或第三方投票工具导入 CSV）。
- 不做个人得分、排行榜、点名。
- 不改写、不新增题目（ADR-0001）；课堂模式只是题库的另一种呈现。
- 不把课堂统计写进任何学生的学习记录或玩家存档。
- 不做 PPT/PDF 导出（浏览器打印足够，见备注）。

## 备注

- Peer Instruction：Mazur 的课堂流程「概念测验 → 独立作答 → 同伴讨论 → 再作答」，报道中的课堂例子从 29% 正确提升到讨论后 62%；
  JHU 的案例报告了概念量表增益约为讲授学期的两倍（单一课程案例，需谨慎外推）。
  来源：https://ii.library.jhu.edu/2013/09/27/leveraging-peer-instruction 、https://columbia.edu/cu/gsapp/BT/RESEARCH/mazur.html ；
  主文献 Crouch & Mazur (2001), *Peer Instruction: Ten years of experience and results*, American Journal of Physics——**引用前需核实原文与数值**。
- Kahoot 文献综述（Wang & Tahir 2020，Computers & Education，93 项研究）：总体对学习表现、课堂氛围有正面作用，
  但部分研究报告竞争性带来的焦虑。来源：https://research.gold.ac.uk/id/eprint/39435
- Classcraft：以「BOSS 战」做形成性评价、团队共担后果，创始人刻意不做排行榜。来源：https://www.gettingsmart.com/2014/03/classcraft-gamifies-classroom-culture/
- 投屏打印：汇总表页面提供打印样式即可「打印 → 存为 PDF」，与 learning-report 一致。
- 与 challenge-modes 的「答题会话」不同：答题会话面向个人练习（有作答、有对错反馈），课堂模式面向投屏与计票（无个人作答），两者只共享题源与高亮，不共享流程。
