# 02: 画布飘字等待显示字体就绪

Status: ready-for-agent
Type: task
Blocked by: 01

## 要做什么

野外和巢穴里的画布文字（如「+1 碎片」「咒语已领悟 ✓」「轰隆—— 石门打开了！」）要始终用 ZCOOL KuaiLe 显示，不能因为字体晚到而永久回退成系统字体。

做法：启动场景在开放标题按钮之前，先主动加载显示字体（ZCOOL KuaiLe，以及文楷常规体）的首屏切片，和素材预加载并行进行。等待设上限（建议 3 秒，实测后调整），超时就照常继续；字体加载失败也不阻断开始游戏。

## 验收标准

- [ ] 进入第一个场景时，浏览器字体就绪 API 报告 "ZCOOL KuaiLe" 已加载（网络正常时）
- [ ] 用浏览器网络节流（Slow 3G）冷启动，第一次飘字仍是快乐体，或者等待已经超时、游戏照常可玩（两种结果都记录在 Comments）
- [ ] 把字体请求全部改成失败时，标题按钮在等待上限后仍可点击，游戏可正常开始
- [ ] 网络正常时，启动到标题按钮可用的耗时相比改动前没有可感知的增加（记录前后数值）
- [ ] E2E 第一章脚本新增断言「进入野外时显示字体已就绪」
- [ ] npm run check 全绿
