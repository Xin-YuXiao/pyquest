# 05: 评估自定义字形子集化是否值得做

Status: ready-for-agent
Type: research
Blocked by: 04

## 要做什么

根据 04 测得的字体体积，评估「只打包游戏文本里实际出现的字形」能省多少、代价多大，给维护者一份带推荐结论的报告。报告由维护者拍板，这张工单不改生产代码。

评估要回答：

- 游戏全部文本（题库、章节对话、界面文案）一共用到多少个不同字符？子集化后三套字体分别多大？与 04 的基线相比省多少？
- 每次改题面后都要重新生成子集：能否在构建时自动完成？漏字（新题生僻字显示成方框）的风险怎么兜底？
- 会给构建时间和依赖带来哪些变化（需要的工具链、是否需要 Python 等）？
- 如果不做全量子集化，只对 ZCOOL KuaiLe（用字极少）做子集化，收益如何？

## 验收标准

- [ ] 报告追加在本工单 Comments 中，包含实测数字（字符数、各方案体积、构建耗时变化）
- [ ] 给出明确推荐：做 / 不做 / 只对快乐体做，并附理由
- [ ] 如推荐要做，列出后续实现工单的草案（标题、验收标准），由维护者确认后再建
- [ ] 不修改任何生产代码；如有原型代码，放在临时分支，不合入
