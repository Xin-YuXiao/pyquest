# 字体本地化：国内网络与离线可用

Status: needs-triage
Priority: P0
Source: 接手评估新增：页面头部从 fonts.googleapis.com 引入 ZCOOL KuaiLe、JetBrains Mono，从 cdn.jsdelivr.net 引入霞鹜文楷（LXGW WenKai）；目标用户是 UCAS 学生，人在中国大陆，Google Fonts 经常连不上
Depends on: 无

## 问题陈述

PyQuest 的教学正文（题面、对话、解析）用霞鹜文楷，代码块用 JetBrains Mono，logo、地名和胜利大标题用 ZCOOL KuaiLe。三套字体都通过第三方 CDN 的样式表引入，写在页面头部：

- **大陆网络环境**：fonts.googleapis.com 常被阻断或极慢。头部的外链样式表会阻塞渲染，连接挂起时浏览器可能要等到超时才开始画页面（需在大陆网络实测白屏时长）。学生打开游戏看到的是长时间白屏，或者回退成系统字体、排版错乱。
- **课堂与离线场景**：机房内网、断网演示、本地 `npm run preview` 离线运行时，字体全部加载失败。
- **画布文字**：野外和巢穴里的飘字（如「+1 碎片」）由 Phaser 画在画布上，用的是 ZCOOL KuaiLe。画布文字在创建那一刻用已经加载好的字体栅格化，字体晚到不会重绘。只要字体比第一次飘字晚到，那串字就永久是回退字体。
- **测试**：E2E runner 为了不被外网拖住，把所有外链请求直接回空 200。所以测试环境里字体从来没真正加载过，我们对「字体是否正确生效」没有任何验证。
- **维护者**：外链版本号写死在页面头部，升级和审计都要手改，也没人知道这些字体的许可证是否允许随包分发。

## 解决方案

把三套字体随项目一起构建和发布：

- 页面不再访问任何第三方域名；生产构建产物里自带带 hash 的字体文件，部署到任何静态托管（包括内网）都能完整显示。
- 中文字体保持按 unicode-range 切片、按需下载，首屏只下载实际用到的字形所在的切片，不一次性拉下几十 MB。
- 字体到达前先用相近的系统字体显示（不白屏），到达后平滑替换（font-display: swap）。
- 画布飘字在显示字体就绪后才开始使用；超过等待上限就用回退字体继续，不卡住游戏。
- CI 断言「页面零外链请求」和「字体体积在预算内」，以后有人再引入外链会被直接拦下。

4. 作为学生，我想要「+1 碎片」等飘字始终是游戏风格的快乐体，以便画面风格统一。

6. 作为网速很慢的学生，我想要字体没到之前先看到系统字体的文字，以便能先开始读题。

## 实现决策

- **字体来源改为 npm 依赖**，由 Vite 解析并输出带 hash 的字体文件：
  - 霞鹜文楷：沿用当前页面已在用的 `lxgw-wenkai-webfont`（同一版本 1.7.0），它本身就是按 unicode-range 切片的 webfont 分发包，只是从 jsdelivr 外链改为本地依赖。
  - ZCOOL KuaiLe、JetBrains Mono：使用 Fontsource 分发包（`@fontsource/zcool-kuaile`、`@fontsource/jetbrains-mono`，均标注 OFL-1.1）。JetBrains Mono 只引入实际用到的 400 与 700 两个字重，ZCOOL KuaiLe 只引入 400。
  - 字体族名保持不变（"LXGW WenKai"、"ZCOOL KuaiLe"、"JetBrains Mono"），页面里所有 font-family 声明和 `--font-kai` 回退链一律不动。这样纯属引入方式替换，视觉零变化。
- **引入位置**：在游戏入口模块里 import 三套字体的样式表，由 Vite 打进构建产物；同时删除页面头部的 Google Fonts / jsdelivr 外链和对应的 preconnect。
- **font-display**：全部为 swap（Fontsource 和文楷分发包默认就是 swap，需核实）。回退链保持现状：楷体类回退到 Kaiti SC / STKaiti / KaiTi，等宽回退到 Consolas。
- **画布文字等待显示字体**：启动场景在开放标题按钮前，先请求加载 ZCOOL KuaiLe（以及文楷常规体）的首屏切片，等待上限 3 秒（数值待实测调整），超时就继续。之后创建的画布文字直接使用已就绪的字体。这个等待和资源预加载并行，不额外串行拉长启动时间。
- **许可证登记**：README「许可证」一节新增「字体」条目，列出三套字体的许可证（OFL-1.1；文楷分发包的 npm 包装许可证标为 MIT，字体本体为 OFL，需在落地时核实原文）。
- **零外链断言**：E2E runner 现在会拦截所有非本地请求并回空 200。改为照常拦截，同时把请求 URL 记录下来，在「浏览器无报错」断言旁边新增「页面零外链请求」断言。另加一个构建产物检查：dist 的页面与样式中不得出现第三方域名的 URL。
- **体积预算**：以「进入标题画面」和「打开第一道题」两个时间点为准，统计字体字节数（未压缩传输量）作为基线写进预算，CI 超出预算即失败。预算数值由测量工单产出，不预设。

## 测试决策

- 好测试只看外部行为：页面发出了哪些请求、字体族是否在页面里生效、构建产物里有没有字体文件，不检查 CSS 的写法。
- **E2E（首选接缝）**：在声明式 runner 的公共收尾断言里加「页面零外链请求」，11 章脚本自动全部获得这条断言，无需逐章修改。字体生效用浏览器的字体就绪 API 检查三套字体族都已加载，放在第一章 E2E 的标题画面步骤里。
- **构建产物检查**：作为 npm test 之后、build 之后的一步（与 CI 的 build 步骤相邻），扫描 dist 中的 html/css，断言无第三方 URL、字体文件存在。
- **先例**：runner 里已有的「浏览器无报错」收尾断言，和外链拦截路由，都是现成的挂载点。

## 待决策

1. **是否做自定义字形子集化**（只打包游戏文本里出现过的字形）：推荐先不做。先用分发包自带的 unicode-range 切片，跑测量工单看首屏体积；只有体积超出可接受范围时，才用研究工单评估子集化。子集化要在每次改题面后重新生成，维护成本高，还可能漏掉未来新题里的生僻字。
2. **画布字体等待上限**：推荐 3 秒。太短在慢网下飘字会回退，太长会拖慢首次进入。落地时用节流网络实测再定。
3. **ZCOOL KuaiLe 是否保留**：它只用于 logo、地名、大标题和飘字，字形用量很少。推荐保留，但若测量显示它的切片占首屏体积大头，可以考虑把 logo 换成 SVG 文字轮廓。这属于视觉改动，需要另行确认。

## 不做的事

- 不更换任何字体，也不调整字号、行高等排版。
- 不引入 Service Worker 或离线缓存策略（离线可用指「构建产物自带字体」，不是 PWA）。
- 不处理 Tiny Swords 素材的分发问题（见公开部署相关 effort）。
- 不改世界地图 SVG 里的系统字体栈。

## 备注

- 现状核实：页面头部第 8、9 行是 Google Fonts，第 12-14 行是 jsdelivr 的文楷；全仓库没有任何 document.fonts / FontFace 调用，画布飘字直接写死 "ZCOOL KuaiLe" 字体族。
- E2E runner 中的外链拦截注释写明了动机：「弱网/离线时这些请求会长期 pending，卡住截图与 networkidle」。这正说明外链在真实用户那边同样会出问题。
- 公开部署 effort 依赖本 effort：不先本地化字体，部署给大陆学生的版本仍会白屏。
