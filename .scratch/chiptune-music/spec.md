# 程序化 chiptune 背景音乐与音频设置

Status: needs-triage
Priority: P3
Source: 接手评估新增——游戏目前只有程序化音效（核实：音效模块用 WebAudio 振荡器/噪声现场合成 8-bit 音效，
零音频素材），没有任何背景音乐；野外、巢穴、BOSS 战、答题、胜利封印页在听觉上完全一样安静，氛围全靠画面。
Depends on: accessibility（设置面板里的音量与静音项、减少动态/听觉偏好）、achievements-codex（无直接依赖，仅共享「答题时不打扰」原则）

## 问题陈述

- 玩家进入「深空晕环」和「诺瓦村庄」时听到的是同样的寂静，章节主题的差异只靠画面，沉浸感弱。
- BOSS 战没有任何听觉上的紧张感，胜利封印页没有「仪式感」的乐句。
- 静音只有按 M 一个开关（核实：只在章节场景里监听 M 键，静音状态只存在内存里，刷新页面就恢复有声；标题画面无法静音），
  也没有音量调节；在图书馆、课堂上玩的学生需要「默认安静、可调」的音频控制。
- 音效目前直接接到音频输出（核实：每个音效的增益节点直接连到 AudioContext 输出，没有总线），无法分别调节音乐与音效，也无法统一淡入淡出。
- 切到后台标签页时也没有暂停音频的逻辑（核实：只有存档模块在切后台时写档）。
- 使用外部音频素材会引入许可证与体积问题——项目已经因为 Tiny Swords 的许可证吃过苦头。

## 解决方案

延续音效模块「零素材、现场合成」的思路，做一个轻量的程序化音乐系统：

- **音频总线**：主音量 → 音乐总线 + 音效总线，所有声音都经过总线；静音作用在主总线上。
- **小型序列器**：用 WebAudio 时钟做「提前调度」（看前 100ms 安排音符），方波旋律 + 三角波低音 + 噪声鼓三个声部，循环播放短乐段。
- **主题**：每章一个野外主题与一个巢穴变奏；BOSS 战一段紧张循环；胜利封印页一段短乐句；标题画面一段主旋律。为了控制创作量，章节主题由「动机 + 调式 + 速度 + 配器」参数化生成，而不是逐章手写整曲。
- **答题时压低**：答题面板打开时音乐平滑降到约 30% 音量（或切到同调的安静垫音），关闭后恢复；答对/答错音效不受影响。
- **音频设置**：音乐音量、音效音量、静音，持久化保存；M 键与界面按钮都能静音，标题画面也能用。
- **生命周期**：遵守浏览器自动播放策略（首次用户交互后才启动音频）；切后台暂停、回来恢复；没有 WebAudio 的环境静默降级。

## 用户故事

1. 作为玩家，我想要每一章的野外有自己的背景音乐，以便进入新章节时有「来到新地方」的感觉。
2. 作为玩家，我想要巢穴的音乐比野外更低沉紧张，以便感受到 BOSS 就在前方。
3. 作为玩家，我想要 BOSS 战开始时音乐切到战斗循环，以便战斗更有张力。
4. 作为玩家，我想要击败 BOSS 后胜利封印页响起一段短乐句，以便通关有仪式感。
5. 作为学生，我想要答题面板打开时音乐自动压低，以便专心读题和代码。
6. 作为学生，我想要答题时的对错音效依然清晰，以便第一时间知道结果。
7. 作为在图书馆/课堂上玩的学生，我想要能把音乐关掉但保留音效（或反过来），以便按场合调整。
8. 作为玩家，我想要静音设置在刷新页面后仍然生效，以便不用每次进来都按 M。
9. 作为玩家，我想要在标题画面就能静音，以便打开游戏的第一秒就不会突然出声。
10. 作为玩家，我想要分别调节音乐和音效的音量，以便找到舒服的平衡。
11. 作为玩家，我想要切到别的标签页时音乐暂停、回来时继续，以便不在后台打扰我。
12. 作为玩家，我想要场景切换（进巢穴、走传送门、读档）时音乐平滑衔接而不是突然中断或叠成两首，以便听感自然。
13. 作为对声音敏感的玩家，我想要音乐默认音量偏低，并能在设置面板里一键关闭，以便不被吓到。
14. 作为使用读屏软件的玩家，我想要音乐在读屏播报时不会盖过语音（默认低音量 + 可关闭），以便正常使用读屏。
15. 作为低性能设备上的玩家，我想要音乐调度不造成掉帧，以便游戏流畅。
16. 作为浏览器不支持 WebAudio 的玩家，我想要游戏照常运行只是没有声音，以便不因音频报错而无法游玩。
17. 作为玩家，我想要第二部（统计圣所、灵思之塔、毕业试炼）的音乐在风格上与第一部有所区别，以便感受到「第二部的大陆」。
18. 作为玩家，我想要世界地图/冒险手册打开时音乐继续但略微压低，以便浏览时不突兀。
19. 作为玩家，我想要死亡重生时有一个短促的下行乐句并重新开始本章音乐，以便节奏有起伏。
20. 作为维护者，我想要音乐数据是紧凑的纯数据（动机、调式、速度、配器），以便新增章节时只填几个参数。
21. 作为维护者，我想要不引入任何音频文件，以便没有许可证与体积负担。
22. 作为维护者，我想要测试接缝能读到音频状态（当前曲目、是否压低、静音、音量、AudioContext 状态），以便 E2E 能断言切歌与压低，而不需要真的「听」。
23. 作为维护者，我想要序列器的调度逻辑可以用假时钟做单元测试，以便确认不漏拍、不重复调度。

## 实现决策

**音频总线（prefactor）**
- 音频模块持有一个共享 AudioContext 与三级增益：主总线 → {音乐总线, 音效总线}。现有音效的振荡器/噪声节点改为接到音效总线；音乐接到音乐总线。
- 静音 = 主总线增益平滑降到 0（不再是「音效函数直接 return」），这样音乐与音效同时生效；静音状态与两个音量持久化。
- 持久化位置：优先使用 accessibility 规划的「设置」存储（独立于主线存档、清档不丢）；若它尚未落地，本 effort 先用一个独立的设置键，形状与之对齐（待决策 2）。
- AudioContext 仍然在首次用户交互后才创建/恢复（标题画面按钮点击即满足浏览器自动播放策略）。

**序列器**
- 「提前调度」模型：一个低频定时器（约 25ms）检查接下来约 100ms 内该响的音符，用 AudioContext 时间精确安排；不在每帧里做音频工作，不依赖 Phaser 的帧循环。
- 声部：旋律（方波，可选占空比）、低音（三角波）、打击（噪声 + 包络）。乐段以「步」为单位（16 分音符），每个声部是一串紧凑的音符记号。
- 曲目切换：旧曲目在小节边界淡出、新曲目淡入（约 0.5–1 秒），避免叠两首。

**主题数据（参数化）**
- 每个主题 = `{ motif, mode, tempo, instrumentation, variation }`：
  - motif：4–8 个音的动机；mode：大调 / 小调 / 多利亚 / 五声等；tempo：BPM；
  - 野外 = 动机按调式展开成 8 小节循环；巢穴 = 同动机降调 + 低音加重 + 速度略慢；BOSS = 共用一段战斗循环，按章移调。
- 章节注册表增加一个可选的音乐参数字段（缺省时按章号生成一个确定性的默认主题），第一部与第二部各用一组配器风格。
- 胜利乐句、死亡下行乐句、标题主旋律为固定短乐段。

**场景挂接**
- 野外场景进入 → 本章野外主题；巢穴场景进入 → 本章巢穴主题；BOSS 被激活（破盾或进入战斗范围，以现有 BOSS 状态为准，需核实最合适的触发点）→ BOSS 循环；BOSS 被击败 → 胜利乐句（与封印页同步）。
- 答题面板、对话框、世界地图打开时音乐压低（答题 30%、地图 60%，可调）；关闭后恢复。
- 页面切后台 → 暂停 AudioContext；回到前台 → 恢复。

**测试接缝**
- 只读查询新增音频状态：`{ track, ducked, muted, musicVolume, sfxVolume, contextState }`，纯 JSON。

## 测试决策

- **E2E**：在章节 runner 增加可选断言（或独立套件）：进入第一章野外后音频状态的曲目为第一章野外主题 → 打开符文答题面板时 ducked 为真 → 关闭后为假 → 进入巢穴后曲目切换为巢穴主题；按 M 后 muted 为真，刷新页面后仍为真。E2E 只读状态，不录音。Playwright 的无头 Chromium 中 AudioContext 可创建（需核实；若被策略挂起，以「状态字段」断言为准，不断言真实发声）。
- **单元测试层（依赖 core-unit-tests）**：序列器调度器用假时钟驱动——给定 BPM 与乐段，N 秒内调度的音符数与时间点正确、不重复、切歌时不叠加。
- **smoke**：每章都能生成合法主题参数（音高在可听范围、速度在合理区间、乐段长度一致）。
- **人工验收**：样板主题需要真人试听（音乐好不好听没有自动化测试），由 grilling 工单确认风格。
- 先例：smoke 现有的「贴图行宽一致」类纯数据校验；E2E runner 的状态快照断言方式。

## 待决策

1. **曲风方向**：推荐第一部「明亮的 8-bit 冒险风」（大调/多利亚、方波主旋律），第二部「更安静的合成器氛围」（小调/五声、三角波主旋律、速度更慢）。→ 工单 03 试听后定。
2. **设置的存储位置**：推荐与 accessibility 共用同一个设置存储（独立于主线存档与元进度）；本 effort 先落地时用同名键与同样形状，避免日后迁移。
3. **默认音量**：推荐音乐默认 40%、音效默认 80%；首次进入不弹设置框。
4. **答题时压低 vs 切换安静垫音**：推荐压低（实现简单、衔接自然），垫音作为后续可选。

## 不做的事

- 不引入任何音频文件（mp3/ogg/wav）或外部音乐库。
- 不做逐章手写整首乐曲（用参数化主题控制创作量）。
- 不做动态配乐（随战斗强度实时变化）、不做音乐播放器/曲目选择界面。
- 不改现有音效的音色设计（只改接线到音效总线）。

## 备注

- 现有音效函数在静音时直接跳过合成，改为总线静音后，静音期间仍会创建少量节点；需要确认开销可忽略，或在主总线为 0 时继续短路合成以省资源。
- 序列器的定时器在后台标签页会被浏览器节流，这正好与「切后台暂停」的策略一致。
- 程序化音乐也可以成为 world-secrets 的彩蛋载体（例如在某处演奏隐藏旋律），留作后续联动。
