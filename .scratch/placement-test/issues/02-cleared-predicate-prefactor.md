# 02: 「已放行」单一判定 prefactor（无摸底时行为零变化）

Status: ready-for-agent
Type: task
Blocked by: None (can start immediately)

## 要做什么

在做任何摸底界面之前，先把「章节已放行 = 已通关 或 已放行」收拢成一个判定，并让所有跨章解锁的消费方使用它：

- 章节进度新增可选布尔字段 `placed`（缺省 false）；存档读写带上它，旧存档缺字段时视为 false，不改存档版本号与 KEY
  （若 learning-records 的 v3 已落地，则放进 v3 schema）。
- 核心模块新增跨章判定 `cleared(id)`；以下改为调用它：世界地图章节解锁、「前往下一章」门 / 传送门的解锁条件
  （解析器新增派生 flag `cleared`，地图构建器改用它）、「继续冒险」落点（状态模块）与标题按钮章节号（存档模块的只读探测）。
- HUD「全部通关」、胜利统计「章节进度」保持只认 done。
- 章内阶段推断不变。
- 测试接缝新增语义动作 `placeChapters([ids])`（测试专用）与只读查询 `placement()`。

## 验收标准

- [ ] 现有 11 章 E2E 不改任何断言原样通过（没有任何章节被放行时行为完全一致）
- [ ] 新增 E2E：用 `placeChapters([1, 2])` 后刷新读档 → 标题显示「继续冒险 · 第 3 章」、落点第三章野外、第二章前方门已开、
  世界地图第三章可传送、第一二章 done 仍为 false
- [ ] 一致性校验（smoke，或单元测试层若已落地）：给定若干进度夹具，世界地图解锁、门解锁、继续落点三者结论一致
- [ ] 旧格式存档（无 placed 字段）读档后行为不变（E2E 预置旧存档验证）
- [ ] GLOSSARY 新增「已放行（placed）」词条，并在「章内阶段」补充说明
- [ ] `npm run check` 全绿
