# 摸底测试与跳章：学过 Python 的学生直接从合适的章节开始

Status: needs-triage
Priority: P2
Source: 接手评估新增 · 借鉴教学研究（见 .scratch/INSPIRATION.md）——Duolingo 入门摸底定位；课程混合水平班级的现实
Depends on: 无硬依赖（协同：learning-records 记录摸底作答、learning-report 展示摸底结果、mistake-review 的「练习模式」答题面板）

## 问题陈述

- P4A 课程的学生水平差异很大：天文专业研究生里有人本科就写过几年 Python，也有人第一次接触编程。
  现在所有人都必须从第一章「变量」开始，一路答完 W1-W3 的基础题才能到第四章天文包。
  对有基础的学生，这是 30-60 分钟的重复劳动，很可能在第一章就失去兴趣。
- 助教常被问「我会 Python，能不能直接跳到天文部分？」——游戏里唯一的跳章手段是测试接缝的 `gotoChapter`，
  它会把前几章直接**标记为通关**，这对学生是错误的语义（没学过却显示通关），学习报告也会失真。
- Duolingo 等产品的做法：入门时一个约 5 分钟的摸底测试，把学习者放到合适的位置，同时保留回头学的入口。

## 解决方案

1. 标题画面在「开始冒险」旁增加「我学过 Python（摸底测试）」入口（仅新游戏时可用，或在设置里随时重测）。
2. 摸底测试从 W1-W3 **已有题池**抽题，按章逐级推进：每章约 4 题（覆盖该章野外 / 巢穴 / BOSS 档）。
   某章通过（例如 4 题答对 3 题且 BOSS 档那题答对）就进入下一章的题；某章没通过就停止。
   全程最多 12 题、约 5 分钟。摸底期间不扣心、不发碎片。
3. 结果页：「你已掌握第一章、第二章，建议从第三章开始」——学生可以接受建议，也可以坚持从第一章开始。
4. 接受建议后，已掌握的章节标记为**已放行**（不是「已通关」）：
   - 通往下一章的传送门打开、世界地图可传送、「继续冒险」落点正确；
   - 世界地图上这些章节显示「已摸底」标记（区别于金色的已通关）；
   - 这些章节仍然可以回去完整游玩，打败 BOSS 后才变成「已通关」；
   - 胜利统计的「章节进度」只计真正通关的章节。
5. 摸底结果写入作答记录，老师的学习报告里能看到谁跳过了哪些章、摸底答对率。

## 用户故事

1. 作为有 Python 基础的学生，我想先做一个几分钟的摸底，以便跳过我已经会的基础章节。
2. 作为学生，我想摸底题和游戏里的题风格一致，以便摸底结果真实反映我在游戏里的水平。
3. 作为学生，我想摸底时答错不扣心、不影响存档，以便放心作答。
4. 作为学生，我想看到摸底进度（第几题 / 共几题、正在测第几章），以便知道还要多久。
5. 作为学生，我想某章没通过时摸底就停止，以便不在明显不会的内容上浪费时间、也不被打击。
6. 作为学生，我想结果页清楚地告诉我每章是否掌握、建议从哪章开始，以便做决定。
7. 作为学生，我想可以拒绝建议、仍从第一章开始，以便按自己的节奏学。
8. 作为跳章的学生，我想直接落在建议章节的野外，并且传送门、世界地图都按我已放行的章节正确解锁，以便不卡关。
9. 作为跳章的学生，我想世界地图上被放行的章节有「已摸底」标记，以便知道哪些是跳过的。
10. 作为跳章的学生，我想随时回到被放行的章节完整游玩，以便查漏补缺。
11. 作为回到被放行章节的学生，我想石碑 / 长老的台词承认我是「摸底通过后回来的」，以便故事连贯。
12. 作为学生，我想被放行的章节在我真正打败 BOSS 后变成「已通关」，以便努力被记录。
13. 作为学生，我想胜利画面的章节进度只算我真正通关的章节，以便统计诚实。
14. 作为摸底没通过任何章的学生，我想得到鼓励的结果页并从第一章开始，以便不觉得自己「考砸了」。
15. 作为学生，我想标题画面的「继续冒险 · 第 N 章」按已放行章节算出正确的 N，以便读档后落在正确位置。
16. 作为教师，我想在学习报告里看到每个学生的摸底结果（放行了哪些章、摸底答对率），以便了解班级起点。
17. 作为教师，我想摸底只放行 W1-W3（Python 基础），天文与数值部分必须正常游玩，以便课程核心内容不被跳过。
18. 作为教师，我想摸底题全部来自已审核的现有题池，以便不引入未经审核的新内容（ADR-0001）。
19. 作为助教，我想能在设置里让学生重测，以便学生在课外补习后重新定位。
20. 作为维护者，我想「已放行」的判断集中在一个地方，以便传送门、世界地图、继续冒险落点、HUD 的规则不各自为政。
21. 作为维护者，我想没有做摸底的玩家体验完全不变，以便新功能零回归风险。
22. 作为维护者，我想摸底不复用测试接缝的 gotoChapter（它会把章节标记为通关），以便语义清楚。
23. 作为 E2E 维护者，我想有一条完整的摸底 E2E（答题 → 放行 → 落点 → 传送门 / 世界地图 → 回头游玩被放行章节），以便防回归。

## 实现决策

- **新状态「已放行（placed）」**：章节进度新增布尔字段 `placed`（存档新增可选字段，缺省 false；
  若 learning-records 的 v3 schema 已落地则放进 v3，否则作为 v2 的向后兼容新增字段，不改版本号）。
- **单一判定：「章节已放行」= done || placed**。在核心模块提供一个跨章判定（例如 `cleared(id)`），
  以下消费方全部改为调用它（prefactor，02 号工单）：
  - 世界地图的章节解锁（现为「前一章阶段 == 已通关」）；
  - 传送门 / 前方门的解锁条件（现为 `requires: { ch, flag: 'done' }`，解析器只读 `progress[ch][flag]`）——
    推荐在解析器里新增一个派生 flag `cleared`，地图构建器的「前往下一章」门改用它；
  - 「继续冒险」落点（furthestChapter）与标题按钮文案（saveChapter，只读存档不应用到状态）；
  - HUD「全部通关」判断**不**改（只认真正通关）。
- **章内阶段不变**：phaseOf 只读本章进度（GLOSSARY 约定），被放行但未游玩的章节仍是「新来」阶段——
  这正确：回去玩时从头开始。世界地图节点状态在「新来 + 已放行」时显示「已摸底」标记（区别于 done 的金色）。
- **台词**：章节 npcLines 允许新增可选词条 `placed`（被放行且本章阶段为「新来」时优先使用），
  缺省回退到 `new`；W1-W3 的 `placed` 台词是界面文案（非题面），草稿由 01 号 grilling 确认。
- **摸底流程**：在标题画面上以覆盖层运行（不进入任何章节场景）；答题复用答题面板的「练习模式」
  （不扣心、不发奖励、不改符文槽状态；与 mistake-review 02 号的复习模式 prefactor 共用——谁先落地谁做）。
  抽题：W1-W3 每章从野外 / 巢穴 / BOSS 三档池各取题，共约 4 题；摸底用过的题**不**写入「已答题」集合
  （玩家回去游玩时题池完整），但写入作答记录（来源标记为 placement）。
- **通过规则**（推荐，待 01 号 grilling）：每章 4 题答对 ≥ 3 且该章 BOSS 档题答对 → 该章通过；
  从第一章开始，某章未通过即停止；只放行连续通过的前缀章节；最多放行到第三章（第四章起不可跳）。
- **重测**：设置里提供「重新摸底」；重测结果只会**增加**放行章节，不会撤销已放行或已通关（避免学生误操作丢进度）。
- **与测试接缝 gotoChapter 的区别**：gotoChapter 继续是测试专用的「标记通关」动作；摸底走自己的「放行」路径。
  接缝新增语义动作 `placeChapters([ids])`（测试专用）与只读查询 `placement()`，用于 E2E 构造与断言。
- **术语**：GLOSSARY 新增「摸底测试」「已放行（placed）」，并在「章内阶段」词条补一句：放行是跨章状态，不改变章内阶段。

## 测试决策

- 好测试只看玩家可见结果：结果页内容、落点、传送门是否开、世界地图标记、回头游玩、统计口径。
- **E2E（首选）**：新增独立脚本 `e2e-placement`：
  1. 标题画面点「我学过 Python」→ 用接缝读答案、真实点击答完前两章的题、故意答错第三章 BOSS 档题 → 结果页显示「建议从第三章开始」→ 接受；
  2. 断言落在第三章野外、第一二章 `placed` 为 true 且 `done` 为 false、第二章「前往下一章」门已开；
  3. Tab 世界地图：第一二章显示「已摸底」、第三章可进入、第四章锁定；
  4. 刷新 → 标题按钮显示「继续冒险 · 第 3 章」→ 读档落点正确；
  5. 传送回第一章：长老说 `placed` 台词；胜利统计口径在通关第一章后只计真正通关的章节。
  另加一条「不做摸底」的回归：现有 11 章 E2E 原样通过。
- **smoke / 单元测试**：「已放行」判定与各消费方的一致性（给定一组进度夹具，世界地图解锁、门解锁、继续落点三者结论一致）；
  若 core-unit-tests 已落地则作为单元测试。
- **存档兼容**：旧存档（无 placed 字段）读档后行为不变——用 E2E 预置一份旧格式存档验证。

## 待决策

1. **通过规则与题量**：推荐每章 4 题、≥3 对且 BOSS 档必对；备选：真正的自适应阶梯（答对升档、答错降档），更省题但更难向学生解释。
2. **可放行范围**：推荐只到第三章（Python 基础）；W4 起是课程核心，不允许跳。
3. **入口时机**：推荐新游戏时在标题画面提供，并在设置里提供「重新摸底」；备选：只在第一次开始时提供一次。
4. **放行章节的奖励**：推荐不发碎片、不算通关；被放行章节真正打通后正常计入。
5. **结果是否可拒绝**：推荐可拒绝（尊重学生选择），拒绝后结果仍写入作答记录供老师参考。

## 不做的事

- 不做第四章及以后的摸底；不做「测完直接通关」。
- 不做基于大模型或复杂心理测量（IRT）的自适应。
- 不新增题目：摸底只用 W1-W3 现有题池。
- 不改现有章节的进度结构与通关语义（done 的含义保持不变）。

## 备注

- 依据：Duolingo 入门摸底定位（约 5 分钟测试放到合适位置，技能按顺序解锁）——参考 Duolingo 官方博客
  https://blog.duolingo.com/duolingo-101-how-to-learn-a-language-on-duolingo ；本设计不依赖其具体算法。
- 课堂现实：混合水平班级中让有基础的学生跳过已掌握内容，可减少重复劳动、把时间留给课程核心（W4 起的天文与数值方法）。
- 现状核实：世界地图解锁只看前一章阶段是否「已通关」；前方门 / 传送门用 `requires: { ch, flag: 'done' }`；
  「继续冒险」落点与标题按钮文案分别在状态模块与存档模块各算一遍（两处都要改为「已放行」口径）；
  测试接缝 gotoChapter 会把前序章节标记为完整通关并破解全部符文槽，不适合给学生用。
