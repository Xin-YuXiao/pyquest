# 观测站小游戏：把天文实操变成可以动手玩的小实验

Status: needs-triage
Priority: P2
Source: 接手评估新增。现在所有学习都发生在四选一答题里；而课程的灵魂是「动手」——拉伸 FITS 图像、并行分配任务、找光变周期、拟合 NFW 轮廓。题库里已经有这些操作的知识点（w3 蒙特卡洛估 π、w5boss `range(rank, nruns, size)` 任务摊派、w7lair FFT 频率轴、w8lair log-log 拟合、w9 χ²/dof），但没有让学生亲手调参数、看结果实时变化的载体。
Depends on: learning-records（完成记录按存档 v3 扩展约定持久化）；quiz-expansion-w4-w8 的课程素材工单（需要真实数据或讲义口径的小游戏）；与 accessibility（键盘操作、读屏）、mobile-touch-controls（滑块触控）、achievements-codex（观测徽记展示）协调

## 问题陈述

- **学生**：我知道 χ²/dof ≈ 1 表示拟合合理，但从没亲手拖动参数看 χ² 怎么变；我会背「FFT 峰值对应周期」，却没见过一条真实的光变曲线怎么折叠。
- **教师**：四选一题能检验「知道」，检验不了「会用」；Pyodide 沙盒（另一个 effort）能考写代码，但对很多学生门槛太高。中间缺一层「调参数、看现象」的可视化练习。
- **玩家**：章节之间只有赶路和答题，节奏单一；通关后没有轻松一点、又和本章相关的可选内容。
- **维护者**：没有承载交互式小实验的界面框架，每做一个都得从零写弹层、暂停、存档。

## 解决方案

- 在章节野外放置一座**观测站**（可交互道具），本章通关后开放（不打扰主线）；按 E 打开全屏的观测面板，场景暂停，可随时退出。
- 观测面板是一个**小游戏宿主**：统一的标题、说明、操作区、结果区、退出按钮、完成判定与星级评定；每个小游戏只实现自己的「数据生成 + 交互 + 判定」。
- **数据优先程序生成**（按固定 seed 生成带噪声的模拟数据），不依赖外部文件、不涉及数据再分发许可；需要真实数据的小游戏（FITS 图像）等素材工单完成后再做。
- **奖励只是锦上添花**：首次完成回满爱心，按完成质量评 1-3 星，星级记入存档并可在 achievements-codex 的图鉴中展示；不发碎片、不影响通关。

## 用户故事

1. 作为学生，我想要亲手拖动 NFW 参数看曲线贴合与 χ² 实时变化，以便真正理解「拟合」在做什么。
2. 作为学生，我想要 χ²/dof 的数值随我的操作实时更新并用颜色标出 <1、≈1、≫1 三个区间，以便把题目里背过的判据和画面对应起来。
3. 作为学生，我想要在光变小游戏里同时看到功率谱和折叠曲线，以便理解「频率峰」和「周期」是同一件事的两面。
4. 作为学生，我想要在并行搬砖里比较连续分块和轮转摊派两种策略，以便明白为什么讲义用 `range(rank, nruns, size)` 分配任务。
5. 作为学生，我想要看到蒙特卡洛估计误差随样本数按 1/√N 缩小，以便记住「要精度翻倍，样本要翻四倍」。
6. 作为学生，我想要后验曲线在每次掷硬币后更新，以便直观感受先验被数据逐步淹没。
7. 作为玩家，我想要观测站只在本章通关后开放，以便它是奖励性的可选内容，不打断主线。
8. 作为玩家，我想要随时可以退出小游戏且不受任何惩罚，以便它是轻松的放松环节。
9. 作为玩家，我想要首次完成时回满爱心并获得星级评价，以便有动力去玩。
10. 作为追求完美的玩家，我想要可以反复挑战刷更高星级，并保留最好成绩，以便有重玩价值。
11. 作为玩家，我想要每个小游戏开头有一段不超过三句的说明和一个「提示」按钮，以便不看攻略也能上手。
12. 作为玩家，我想要完成后看到「真值」与我的结果对比（例如真实 ρ₀、Rₛ），以便知道自己离答案多近。
13. 作为玩家，我想要每次打开同一个小游戏时数据相同（固定种子），并有「换一组数据」按钮，以便既能复盘也能挑战新数据。
14. 作为键盘玩家，我想要用方向键微调滑块、Tab 切换控件、Esc 退出，以便不依赖鼠标。
15. 作为触控玩家，我想要滑块足够大、可以直接拖动，以便在手机上也能玩。
16. 作为读屏用户，我想要滑块有标签和当前值、完成判定以文字播报，以便不依赖图形。
17. 作为偏好减少动态效果的玩家，我想要撒点动画等效果可以关闭，以便不引起不适。
18. 作为教师，我想要每个小游戏的讲解文字与讲义口径一致，并能追溯到对应题目或讲义章节，以便它不会教出与课堂不同的说法。
19. 作为教师，我想要学生的小游戏完成情况和星级能出现在学习报告里，以便了解学生的动手练习情况。
20. 作为读档续玩的玩家，我想要已完成的小游戏和最佳星级保留，以便收集进度不丢。
21. 作为维护者，我想要新增一个小游戏只需实现「生成数据、渲染交互、判定结果」三个接口并在注册表登记，以便扩展成本低。
22. 作为维护者，我想要小游戏的数值核心（χ² 计算、折叠、甘特图总耗时、π 估计、Beta 后验）是纯函数，以便用 smoke 或单元测试直接验证。
23. 作为维护者，我想要能用 Python 对照校验这些纯函数的数值（与 verify-quiz 同一思路），以便确认前端算出的 χ² 与 numpy 一致。
24. 作为 E2E 作者，我想要一个只读接缝返回当前小游戏的真值参数，以便测试能把滑块设到正确位置并断言完成。
25. 作为 E2E 作者，我想要小游戏宿主用真实 DOM 控件（range input、button），以便 Playwright 能直接操作。

## 实现决策

- **观测站道具**：新道具类型 `observatory`（程序化像素望远镜贴图，或复用塔楼贴图加色调，需与美术风格核对），由章节主题字段 `observatory: '<gameId>'` 声明；通用生成器在石碑附近、避让区之外放置；手工地图章节（第一、二章）本期不放。
- **开放条件**：章内阶段为「已通关」时可交互；未通关时按 E 提示「观测站要等本章封印解除后才开放」。
- **小游戏宿主**（DOM 覆盖层，与答题面板同级）：负责打开/关闭、暂停与恢复场景、说明与提示、结果展示、星级评定、写入完成记录、Esc 退出、焦点管理（与 accessibility 协调）。宿主不认识任何具体小游戏。
- **小游戏接口**（极简形状）：

  ```
  { id, chapter, title, intro: string[],
    generate(seed) → data,              // 纯函数：同 seed 同数据
    mount(container, data, report) → unmount,   // 渲染交互；用户操作时调用 report(result)
    judge(data, result) → { done: boolean, stars: 0..3, feedback: string } }  // 纯函数
  ```
- **渲染**：用内联 SVG 或 Canvas 2D 自绘图表（散点 + 误差棒 + 曲线、功率谱、甘特图、直方图），不引入图表库，控制体积。
- **数值核心为纯函数**：NFW 密度 ρ(r) = ρ₀ / [(r/Rₛ)(1 + r/Rₛ)²]（与 w8 题目同式）、χ² 与 χ²/dof、相位折叠、离散傅里叶功率谱（数据量小，直接算即可）、任务调度总耗时、蒙特卡洛 π、Beta 后验密度；随机数用带 seed 的伪随机生成器（与地图生成器同类）。
- **完成记录**：新增存档字段 `observatory: { [gameId]: { bestStars, completedAt } }`，按存档 v3 扩展约定加入（依赖 learning-records 的 v3 schema 工单）；首次完成回满爱心。
- **测试接缝**：新增只读 `observatoryInfo()`：当前打开的小游戏 id、seed、真值参数、当前判定结果。
- **数据来源**：程序生成的小游戏不需要外部数据；FITS 拉伸需要真实图像——依赖课程素材工单确认可用数据及其再分发许可（例如讲义使用的 HorseHead.fits 的许可需核实），不满足则改用程序生成的「模拟星云」图像。

## 测试决策

- **好测试的标准**：断言玩家可观察结果——完成判定、星级、爱心回满、记录持久化；不断言渲染细节。
- **E2E（首选）**：新增声明式步骤 `observatory`：在本章通关后走到观测站 → 按 E 打开 → 通过 `observatoryInfo()` 取真值 → 用 DOM 操作把滑块设到真值附近 → 断言「完成」与星级 → 退出 → 断言场景恢复、记录写入 `state()` 快照。另一条：本章未通关时按 E 不打开面板。先例：答题面板的 DOM 点击流程与 runner 的 quizClick 护栏。
- **smoke**：每个小游戏的纯函数用固定 seed 断言——同 seed 同数据；真值参数下 judge 判定完成且三星；明显错误参数下判定未完成；χ² 对已知小数据的手算值相符。
- **数值对照（可选）**：仿照 verify-quiz，用本机 python 对 χ²、Beta 后验、功率谱峰位做一次对照，确认与 numpy/scipy 结果一致（误差容限内）。
- **回归**：`npm run check` 全绿；观测站不影响任何章节的现有 E2E（通关前不可交互，不改变进度）。

## 待决策

1. **样板选哪个？** 推荐 **NFW 拟合滑块（第八章）**：完全程序生成、同时覆盖 W8 与 W9 两章知识点、交互最简单（两个滑块）；备选蒙特卡洛估 π（更简单，但教学增量较小）。
2. **开放时机**：推荐「本章通关后」；备选「封印门打开后」（会和 BOSS 战抢注意力，不推荐）。
3. **奖励**：推荐「首次完成回满爱心 + 星级记录」，不发碎片；金币类奖励等 difficulty-economy 定稿。
4. **讲解文字的口径**：每个小游戏的说明与反馈文字是否需要逐条对照讲义？推荐是——与出题同一流程（提纲 → grilling），程序生成的数据不受此限。
5. **第一、二章要不要观测站？** 推荐不要（课程前两周是纯 Python 基础，没有合适的天文实操）。
6. **FITS 拉伸用真实数据还是模拟图像？** 推荐先查讲义所用数据的许可：可再分发就用真实数据（更有说服力），否则用程序生成的模拟星云。
