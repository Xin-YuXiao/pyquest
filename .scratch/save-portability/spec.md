# 存档导出 / 导入

Status: needs-triage
Priority: P2
Source: 接手评估新增——存档只存在单个浏览器的 localStorage 里；学生在机房电脑和自己笔记本之间切换、
换浏览器、清理缓存时，进度与学习记录全部丢失
Depends on: learning-records（导出导入的是 v3 存档；复用其校验纯函数）

## 问题陈述

- 课程学生常在机房电脑、自己的笔记本、宿舍台式机之间切换，而进度锁死在某一台机器的某一个浏览器里。
- 机房电脑经常还原系统或清理浏览器数据，一次清理就让学生从第一章重来。
- 浏览器隐私模式、换浏览器、重装系统都会丢档，游戏里没有任何备份手段。
- 学习记录（错题、报告数据）上线后，丢档的代价更大：丢掉的不只是进度，还有一学期的学习过程。

## 解决方案

- **导出存档文件**：在标题画面和世界地图里点「导出存档」，下载一个存档文件（JSON），
  文件名带日期，内含完整进度、学习记录与导出时间。
- **导入存档文件**：在标题画面点「导入存档」选择文件，游戏先校验，再显示预览
  （来自哪天、进行到第几章、各章进度、作答记录条数），确认后才覆盖当前存档；
  覆盖前自动备份当前存档，可以「撤销上次导入」。
- **存档码**：不方便传文件时（比如只能用聊天软件），可以「复制存档码」得到一段文本，
  在另一台机器「粘贴存档码」导入。为控制长度，存档码只含进度与每题汇总，不含原始作答日志（会明确提示）。
- 所有错误输入（不是存档、文件损坏、来自更新版本的游戏、被改坏）都给出清楚的提示，
  并且绝不部分写入、绝不破坏当前存档。

## 用户故事

1. 作为学生，我想要把存档导出成文件，以便在另一台电脑上继续玩。
2. 作为学生，我想要导出的文件名带日期，以便区分多个备份。
3. 作为学生，我想要在标题画面就能导入存档，以便一开机就接着上次的进度。
4. 作为学生，我想要导入前看到存档的预览（日期、章节进度、作答条数），以便确认是我要的那份。
5. 作为学生，我想要导入会覆盖当前存档时被明确询问，以便不会误覆盖。
6. 作为学生，我想要导入前当前存档被自动备份，以便导错了可以撤销。
7. 作为学生，我想要「撤销上次导入」恢复到导入前的状态，以便纠正失误。
8. 作为学生，我想要导入老版本（v1/v2）导出的存档也能用，以便早期的备份不作废。
9. 作为学生，我想要导入来自更新版本游戏的存档时被告知「请更新游戏」，而不是读坏，以便知道原因。
10. 作为学生，我想要选错文件（比如一张图片）时得到清楚的提示，以便重新选择。
11. 作为学生，我想要损坏或被改坏的存档被拒绝且当前存档不受影响，以便不会两头都丢。
12. 作为学生，我想要被手动修改过的存档在导入时得到「可能被修改」的警告并需要再次确认，以便自己决定是否继续。
13. 作为学生，我想要复制一段存档码，在只能发文字的场合也能迁移进度，以便不依赖文件传输。
14. 作为学生，我想要知道存档码不含完整作答日志，以便需要完整数据时选择导出文件。
15. 作为学生，我想要导入后直接落在存档进度对应的章节，以便无缝继续。
16. 作为学生，我想要在游戏进行中（世界地图里）也能随时导出备份，以便机房下课前快速保存。
17. 作为在机房上课的学生，我想要导出不需要任何账号或网络，以便断网也能用。
18. 作为老师，我想要能导入某位学生的存档查看其进度，以便现场答疑。
19. 作为维护者，我想要导入走与读档完全相同的迁移与校验函数，以便只有一套存档逻辑。
20. 作为维护者，我想要导出文件带格式标识与版本，以便将来格式升级时能识别。
21. 作为维护者，我想要超大文件（> 5 MB）被直接拒绝，以便恶意或错误文件不会卡死页面。
22. 作为维护者，我想要存档中引用了已不存在的章节/题目/槽位时被清理并给出警告，而不是拒绝整份存档，以便题库演进后旧备份仍可用。
23. 作为维护者，我想要导入后的状态与导出前逐字段一致（往返测试），以便确信没有字段丢失。

## 实现决策

- **校验/迁移复用**：导入使用 learning-records 拆出的「迁移」「校验」纯函数，返回
  `{ ok, save, warnings[], errors[] }`：errors 非空则拒绝；warnings（如引用了不存在的题目/槽位/章节、
  integrity 不匹配）展示给用户确认。导入成功的存档先完整水合到内存、再一次性写入存储，失败不留半成品。
- **导出文件信封**：

  ```
  format: 'pyquest-save', formatVersion: 1, gameVersion, exportedAt,
  integrity: '<save 的摘要>',
  save: { …v3 存档对象… }
  ```
  也接受「裸存档对象」（没有信封，直接是 v1/v2/v3 存档 JSON），便于从开发者工具里手抄出来的存档也能导入。
- **版本规则**：v1/v2/v3 接受并迁移；`v` 大于当前支持版本 → 拒绝并提示更新游戏；缺 `v` 或类型不对 → 拒绝。
- **范围清理**：未知章节 id 的进度丢弃；碎片数截断到 [0, 本章所需]；当前章节截断到有效范围；
  已破解槽位/已答对题目里不存在于当前地图/题库的 id 丢弃；以上各产生一条 warning。
- **大小上限**：文件 > 5 MB 直接拒绝（不读入）；存档码 > 1 MB 拒绝。
- **integrity**：浏览器内置摘要算法对 save 内容求摘要；不匹配只警告（需二次确认）不拒绝——
  这不是安全机制，只用于提醒「文件被改过或传输损坏」。
- **备份与撤销**：导入覆盖前把当前存档原样写入一个独立的备份键（只保留最近一次）；
  标题画面在备份存在时显示「撤销上次导入」，执行后恢复并删除备份。
- **存档码**：存档去掉原始作答日志（保留每题汇总与复习状态）→ JSON → 浏览器内置压缩流（deflate）→ base64url，
  加一个可读前缀（如 `PQ1:`）便于识别。浏览器不支持压缩流时退化为不压缩的 base64url（**需核实**目标浏览器支持情况，
  课程机房浏览器版本未知）。粘贴导入走与文件相同的校验流程。
- **入口**：标题画面新增「导入存档」（无存档时也显示）与「撤销上次导入」（仅备份存在时）；
  标题画面（有存档时）与世界地图头部新增「导出存档」「复制存档码」。导入只在标题画面提供，
  避免游戏场景运行中替换全局状态。

## 测试决策

- 好测试：往返一致——导出、清空、导入后，`__PYQUEST__.state()` 与导出前完全一致、继续冒险落点正确；
  坏输入被拒且原存档不变。
- **单元测试**（主力）：信封/裸存档识别、版本规则、范围清理与 warnings、integrity 匹配/不匹配、
  大小上限、存档码编码/解码往返（含不支持压缩流的退化路径）。
- **E2E**（声明式 runner + `__PYQUEST__`）：
  - 玩到第一章碎片 2/3 → 导出（Playwright 下载事件拿到文件）→ 清空存储刷新 → 标题画面导入该文件 →
    预览显示第一章 → 确认 → 进度为 2/3；
  - 已有第二章存档时导入第一章存档 → 确认覆盖 → 「撤销上次导入」→ 回到第二章存档；
  - 导入一个非 JSON 文件与一个 `v: 99` 的文件 → 均显示对应错误，原存档不变；
  - 复制存档码 → 清空 → 粘贴导入 → 进度一致。
- 先例：E2E runner 的 `saveCheck` 与 `resume` 步骤（存档写入与刷新续玩）。

## 待决策

1. **是否做存档码**——推荐做：机房场景下传文件往往比发一段文字麻烦；代价是需要压缩流支持与长度控制。
2. **导入是否只在标题画面提供**——推荐只在标题画面：避免游戏场景运行中整体替换状态带来的场景一致性问题；
   世界地图只提供导出。

## 不做的事

- 不做云存档、账号、自动同步。
- 不做多存档槽位（仍是单存档 + 一个导入前备份）。
- 不做存档加密或防作弊签名。
- 不做跨游戏版本的「降级导出」（新版本存档不保证能被旧版本读取）。

## 备注

- 依赖 `../learning-records/issues/01`（v3 结构与校验纯函数）。
- 学习报告（learning-report）的 JSON 与存档文件是两种格式：报告给老师看、不可导回游戏；存档文件可导回。
  两者的 format 标识不同，导入存档时若误选了报告 JSON，应提示「这是学习报告，不是存档」。
