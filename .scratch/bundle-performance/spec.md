# 加载性能：拆包、素材瘦身与首屏加载进度

Status: needs-triage
Priority: P3
Source: 接手评估新增。生产构建只有一个约 1.5 MB 的 JS 文件，构建配置把 chunk 体积警告阈值调到 1500 KB 掩盖了警告；构建产物还会整包复制从未被加载的 cc0 素材；素材加载期间没有进度提示
Depends on: 无（与 `self-hosted-fonts` 的字体体积预算互补；公开部署的素材许可问题见公开部署相关 effort）

## 问题陈述

在校园网或手机热点上第一次打开 PyQuest 的学生，会遇到这些情况（数据为 2026-10-25 本地构建实测）：

- **一个大文件**：生产构建只产出一个 JS 文件，约 1.5 MB（gzip 后约 434 KB）。其中 Phaser 引擎约 1.2 MB（gzip 约 317 KB），题库约 185 KB（gzip 约 67 KB）。每次更新哪怕只改了一道题，学生都要重新下载包括 Phaser 在内的整个文件，浏览器缓存完全没起作用。
- **警告被掩盖**：构建配置把 chunk 体积警告阈值调到 1500 KB，Vite 原本会给出的「chunk 过大」提示被关掉了，体积再涨也没人知道。
- **白搬的素材**：构建把整个素材目录当作公共目录原样复制进产物，其中 cc0 素材（约 970 KB）在源码里没有任何引用（README 也说明它「当前版本未加载，留作第二部备用」），却随每次部署一起发布。
- **加载期间无反馈**：启动场景预加载 Tiny Swords 素材时没有任何进度提示。标题画面是页面里的静态 HTML，从一开始就显示「开始冒险」按钮，但按钮的点击处理要等素材全部加载完、启动场景进入 create 阶段才绑定。网速慢时学生点了按钮没有任何反应（根据代码推断，需在节流网络下实测确认），容易以为游戏坏了。

## 解决方案

- **拆包**：把 Phaser 拆成独立的 vendor chunk。日常更新只改业务 chunk，Phaser 的缓存长期有效。
- **体积预算**：去掉对警告的掩盖，改为一份明确的体积预算（各 chunk 与构建产物总量），CI 自动检查并输出体积报告，超出预算即失败。
- **素材瘦身**：构建产物只发布运行时真正加载的静态素材，cc0 备用素材不再进入产物（仍保留在仓库中）。
- **加载进度**：标题画面在素材加载期间显示进度（百分比或进度条），「开始冒险」按钮在加载完成前处于明确的「加载中」禁用状态，加载完才可点击；加载失败时给出可理解的提示和重试入口。
- **题库按需加载**：先评估、再决定。题库 gzip 后约 67 KB，收益可能不足以抵消复杂度。

## 用户故事

1. 作为第一次打开游戏的学生，我想要看到加载进度，以便知道游戏正在加载而不是卡死了。
2. 作为网速慢的学生，我想要「开始冒险」在加载完成前明确显示为不可用，以便不会白点几次。
3. 作为网速慢的学生，我想要加载一完成按钮就自动变为可用，以便不用刷新页面。
4. 作为遇到素材加载失败的学生，我想要看到「加载失败，点此重试」，以便不用自己猜怎么办。
5. 作为回访的学生，我想要游戏小更新后不必重新下载整个引擎，以便打开更快、更省流量。
6. 作为用手机热点上课的学生，我想要首次加载的总下载量尽量小，以便不浪费流量。
7. 作为维护者，我想要每次构建都看到各 chunk 和总产物的体积，以便心里有数。
8. 作为维护者，我想要体积超出预算时 CI 失败并指出是哪个 chunk 超了，以便在合并前发现体积回退。
9. 作为维护者，我想要预算数值写在一个配置里并注明依据，以便调整预算时有据可查、在评审中可见。
10. 作为维护者，我想要构建不再掩盖 Vite 的体积警告，以便工具链自己的提示也能发挥作用。
11. 作为部署游戏的维护者，我想要构建产物里只有运行时用得到的文件，以便部署包干净、上传更快。
12. 作为维护者，我想要 cc0 备用素材仍保留在仓库中，以便第二部以后需要时还能用。
13. 作为维护者，我想要 Phaser 升级时 vendor chunk 的 hash 才变，以便缓存命中率可预期。
14. 作为维护者，我想要加载进度的显示不依赖额外的网络请求，以便慢网下它是最先显示出来的东西。
15. 作为使用「减少动态效果」系统设置的学生，我想要进度条不使用夸张动画，以便符合我的偏好。
16. 作为维护者，我想要加载进度的行为有 E2E 断言，以便以后改动标题画面时不会把它弄坏。
17. 作为维护者，我想要知道题库按需加载能省多少、要付出什么代价，以便有据地决定做不做。
18. 作为维护者，我想要 E2E 仍能在 Tiny Swords 占位图上跑通，以便素材瘦身不破坏 CI。

## 实现决策

- **vendor 拆分**：在构建配置中，把来自 Phaser 依赖的模块单独打成一个 chunk（命名带 vendor 语义）。业务代码作为另一个 chunk。两者都带内容 hash。
- **体积预算与报告**：新增一个构建后检查步骤，读取 dist 中各文件的原始大小和 gzip 大小，按「Phaser chunk、业务 chunk、样式与页面、静态素材总量、产物总量」分组，与预算配置比较。预算初始值为实测基线加 10% 余量，配置中注明测量日期。CI 在构建步骤之后执行；超出预算时退出码非零，并打印超出的组和数值。体积报告也在本地 `npm run build` 之后打印。
- **去掉警告掩盖**：Phaser 拆出去以后，业务 chunk 不会再超过 Vite 默认的 500 KB 警告阈值（需在拆分后实测核实），删除被调大的阈值配置，恢复默认。
- **静态素材瘦身**：公共目录只包含运行时由启动场景加载的素材。cc0 备用素材移出公共目录，在仓库里换一个不会被构建复制的位置保存，同步更新 README「许可证」一节的路径描述。Tiny Swords 素材的运行时 URL 保持不变，占位图生成器写入的位置随之调整，保证 CI 照常运行。Tiny Swords 是否能随构建产物公开发布属于许可问题，由公开部署相关 effort 决定，本 effort 不改变它是否进入产物。
- **加载进度**：标题画面中新增加载状态区域。启动场景的预加载阶段向它报告进度，可以通过页面自定义事件，与 HUD 刷新事件同一模式。加载期间「开始冒险」「新的冒险」按钮禁用，文案为「加载中 N%」；加载完成后恢复正常文案与可点击状态，再由标题模块绑定点击处理。任一素材加载失败时显示失败提示和「重试」按钮，重试即重新加载页面。进度条在减少动态效果偏好下不使用过渡动画。
- **测试接缝**：在既有只读查询中增加「启动是否就绪」，供 E2E 等待使用，取代固定的 networkidle 或硬等待。

## 测试决策

- 好测试只看外部行为：产物里有哪些文件、各自多大；标题按钮在加载前后的可用状态；进度事件是否从 0 增长到 100。
- **E2E**：第一章脚本新增断言：首屏加载期间「开始冒险」不可点击、进度显示存在，加载完成后可点击。利用 Playwright 的请求拦截延迟素材响应，制造可观察的加载窗口；再拦截一个素材请求使其失败，断言失败提示与重试按钮出现。
- **构建产物检查**：体积预算脚本本身就是测试，验证方式是临时把预算调低，确认 CI 失败。
- **先例**：HUD 刷新、碎片入袋都用页面自定义事件跨模块通信；runner 已有对外链请求的路由拦截，可以照此拦截素材请求。

## 待决策

1. **cc0 备用素材放哪**：推荐移到仓库内一个明确标注为「未发布备用素材」的目录。备选是直接删除（README 说留作第二部备用，而第二部已经用通用生成器落地、没用到它们），删除需要维护者确认。
2. **体积预算余量**：推荐 10%。太大失去意义，太小每次加功能都要改预算。
3. **题库按需加载**：推荐先做评估工单（本 effort 06），不预设结论。

## 不做的事

- 不更换 Phaser，也不做 Phaser 的自定义精简构建（tree-shaking Phaser 需要大量配置，收益不确定，另议）。
- 不做 Service Worker / 离线缓存。
- 不处理字体体积（见 `self-hosted-fonts`）。
- 不决定 Tiny Swords 能否公开发布。

## 备注

- 实测（2026-10-25，chore/quality-baseline 构建）：dist 主 JS 1,487 KB，gzip 434 KB；Phaser 压缩版约 1,196 KB，gzip 约 317 KB；题库源文件约 185 KB，gzip 约 67 KB；页面 HTML（含内联样式）约 45 KB；cc0 约 970 KB，源码与页面中没有任何引用。
- 构建配置把公共目录设为整个素材目录，注释写着「TinySwordsFreePack 在 .gitignore 单独排除」。但 .gitignore 只影响 git，不影响 Vite 复制：本地有 Tiny Swords 时，它会完整出现在 dist 里。这一点对公开部署的许可判断很重要，已在本 effort 记录，供公开部署 effort 参考。
