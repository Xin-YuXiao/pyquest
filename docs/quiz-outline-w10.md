## 第十章 · 灵思之塔（幻言魔像）· w10shard(29) / w10lair(30) / w10boss(31)

| 池 | 题目知识点分配 |
| --- | --- |
| shard ×10 | vibe coding 四步流程定位（需求→分解→迭代→验证，非「一句话生成整个程序」）· prompt 具体性原则（须含输入/输出/库/边界，对比「帮我拟合数据」）· LLM 能力边界：统计生成、不保证正确、「看起来对」≠「对」· 幻觉识别：编造不存在的 API/参数名 · 为什么验证必须（科研代码错误可进论文，无人替你负责）· 小步迭代 vs 一次性大段生成（错误定位成本）· 测试用例先行概念（先写期望输入/输出，再让 AI 实现）· 上下文管理：给 AI 数据形状/单位/包版本 · 何时不信 AI：关键数值计算（归一化常数/单位换算）vs 样板代码（绘图模板）· 人机分工：AI 生成候选，人负责判断与验证 |
| lair ×7 | **高斯归一化漏因子**（挑错+算正确值：`np.exp(-(x-mu)**2/(2*sigma**2))` 漏 `1/(σ√(2π))`，x=μ=0,σ=2 时正确值 1/(2√(2π))≈0.1995；可执行）· **角度当弧度**（AI 写 `np.sin(30)` 想要 sin 30°，正确 `np.sin(np.radians(30))`=0.5；可执行）· **直方图 bin 边界 off-by-one**（`np.linspace(0,10,11)` 得 10 bins，AI 写 10 个边界只得 9；问 bins 数；可执行）· **测试用例设计**（`mag2flux(m)=10**(-0.4*(m-25))`，哪个测试最能暴露零点错误 → m=25 应给 flux=1 的锚点用例）· **边缘情况：除零污染**（`np.mean(flux/err)` 遇 err=0 得 inf，识别含 0 误差的输入会污染结果；可执行）· **math vs numpy 标量/数组混淆**（`math.sin(np.array([...]))` 抛 TypeError，应改用 np.sin；可执行）· **回归检查语义**（AI 改函数后重跑旧测试的目的 = 确认旧行为未被破坏） |
| boss ×3 | **完整流程排序**（打乱五步：描述需求→分解 prompt→先写测试用例→逐段生成并跑测试→整体回归，选正确顺序）· **prompt 改写对比**（给模糊版 vs 具体版两个 prompt 求同一任务，选更可能产出正确代码者并指出关键改进点 = 指定输入形状/输出契约/边界行为）· **回归破坏处置场景**（v1 通过测试 → 让 AI 加功能得 v2 → v2 使旧测试变红；正确处置 = 先修回归或回退，而非删旧测试/继续堆功能） |

## 正确性验证 workflow 的覆盖方式（成体系考点对照）

| 计划钦定考点 | 落点 |
| --- | --- |
| 小步迭代 | shard：小步迭代 vs 一次性生成的错误定位成本题；boss-1 排序题中「逐段生成并跑测试」步骤 |
| 测试用例先行 | shard：测试先行概念题；lair-4：锚点测试用例设计（m=25→flux=1）；boss-1：排序中测试先于实现 |
| 边缘情况 | lair-3（bin 边界 off-by-one）、lair-5（除零 inf）、lair-6（标量/数组类型边界）；shard：prompt 须含边界条件 |
| 回归检查 | lair-7：回归检查语义；boss-3：回归破坏处置策略 |

四考点在三个池均有落点、且 lair/boss 提供可执行/有确定答案的载体，满足「成体系」要求。
